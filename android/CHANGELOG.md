# Changelog

Aiden On The Go for Android. Earlier Android changes are recorded in the pull requests and plans under `docs/plans/`.

## Unreleased

- **2026-11-13 — Simpler Bots and approvals on revision 61 Macs (provisional Remote revision 61).** The app asks a revision 61 Mac for `approval:cards`, `approvals:settings`, `bot:settings-changes`, `bot:suggestions` and `bot:templates` one at a time, and each screen changes only when its capability is held. Approval cards follow the Mac's typed card: Deny first, the arguments and body, and only the buttons the Mac offers; a card the phone can't fully show says to allow it on the Mac. A tap shows its answered line at once and puts the card back if the Mac refuses. Bot chats show held settings changes (Apply / Dismiss, with the change), receipts with Undo, skill, lesson and tidy-up suggestions; a skill too long to review here says to add it on the Mac. Templates show their version and **Open** for a template that already made a Bot, and say so when a template changed. New bot is one name field. **Settings → Approvals** shows the Mac's mode (Ask, Auto, Never ask; Auto is disabled until a model is connected) and its rules, with Allow / Ask / Block, Remove and **Add rule** from the Mac's list. On these Macs, hand-off cards take two steps (**Take control**, then **I’m done**), Bot messaging is one **Can message other Bots** switch, Full access offers **Disable a tool**, and **Settings → Appearance → Chat → Show tool activity** replaces the per-Bot Chat activity page on this phone. Older Macs keep today's screens.

- **2026-11-06 — "By voice" label (Remote revision 60).** A chat message Aiden Live sent on the Mac shows a small "By voice" label with a microphone under it. The host marks it with `inputSource: "voice"` on user messages only; the app ignores any other value or a marker on a reply. Older hosts send no marker, so nothing changes there.

- **2026-11-05 — Combined Remote revision 58.** Connector watches, Open work, routine model management and approved Bot peers first enter the shared release at revision 58. - **Bot peers** (Remote revision57, `bot:peers`) adds full Profile pair management: owner routing descriptions, explicit named bidirectional approval and revocation, read-only catalog access, exchange detail/source/result text and protected same-request Stop checks. Peer transcript and Open-work links open the scoped exchange. Exact encrypted journals retain drafts and unknown operations across restart and permission loss; accepted Bot deletion purges only that Bot’s records and fences late replies. Peer completion uses the existing notification feed with stable deduplication and late access checks. See [Bot peers](PEERS.md).

- **Routine models** on Bot profiles lists every host-owned scheduled, event and connector watch routine on revision-56 hosts offering `bot:routine-models`. Choose Inherit Bot model, an exact primary model and host-supported thinking level, and an optional explicit fallback. Saving authorizes only those routine choices; the Bot default and unrelated grants stay unchanged. Recent runs show chosen and actual provider/model/thinking, fallback cause, admission/start times and scheduled occurrence/timezone with actual start delay. Model changes use encrypted, backup-excluded exact-request journals and retain drafts through conflicts and unknown outcomes. Interrupted-work Resume checks unknown-cost status only after the person chooses Resume and asks for explicit acknowledgement tied to the exact interrupted submission and opaque cost receipt. Stale consent cannot approve a newer cost for the same input; malformed or older acknowledged journals without a receipt fail closed. Typed uncertain outcomes, including a first 409 after admission, retain the original request. Lost Resume replies retain the same UUID and acknowledgement across restart. Successful retries read the current session without treating a cached running receipt as current state or waking the message outbox; Profile Resume still only lifts a pause. Confirmed deletion from Profile, the Bots list or chat removes that Bot’s local model and Resume records and fences held replies, while failed deletion keeps the requests.

- **Open work** on Bot profiles keeps accepted tasks, waiting reasons, completion and linked execution status together on hosts offering `bot:open-work`. Add/edit, mark done, reopen, dismiss and undo the latest per-item change for up to 24 hours. Owned source/result sheets show actual retained text. Linked Stop and Stop and dismiss wait for host acknowledgement, with a same-identity Check Stop for uncertainty; mixed-input work explains why it cannot be stopped. Exact requests and drafts survive restart in encrypted, backup-excluded storage and are purged with the pairing. Task changes require Bot-edit permission; all text requires both Bot and chat visibility.

- Bot profiles gain **Watches** on hosts offering `bot:watches`. Create or edit a connected-mail watch using safe account/mailbox labels, sender/subject/unread filters and 15/30/60-minute intervals; pause/resume, preview with **Test check**, explicitly **Run now**, or delete it. Source discovery happens only when you choose **Find connected sources**. Calendar availability and repair guidance come from the host; unsupported connectors do not fall back to scripts. The owning host checks sources while Aiden is running and awake, including after the phone disconnects. Writes require Bot-edit permission. Drafts and exact original mutation identities are durably kept in encrypted, backup-excluded storage across reconnect, navigation and process restart; uncertain outcomes offer an explicit same-request retry, and conflicting edits require review of the current host revision.

- Remote revision 57 (`bot:allowed`): capable hosts offer Always allow for a Bot after repeated approvals, plus an Allowed without asking profile list. The list includes every rule and folder across pages. Remove waits for the host and keeps the row on failure. Unknown-outcome retries keep the exact decision/scope body and key; Always acknowledges “Always allow requested.” The host remains the authority for saved access. Eligible folder cards also show the host’s approval count. Older hosts keep their existing cards.
- **Recording player cleanup (2026-11-02).** Leaving or replacing a recording card now releases its downloaded video even before the player's first frame. A late download for a removed card is discarded, and closing then leaving releases the file once.

- **Browser recordings (2026-11-02).** Each Play keeps its own temporary file, including overlapping downloads of the same recording. Starting or cancelling another download no longer deletes an active download or player. Cleanup handles cancelled delivery and leaving the chat; startup reclaims files abandoned by a previous process.

- **Inbox (Beta).** The sidebar's organization menu gains **Inbox (Beta)** beside Workspaces and Recents, remembered on this phone. Chats are grouped into **Needs you** (an approval, a question, or a failed run you haven't seen), **Pinned**, **Updates** (unread replies), **Earlier** (the last seven days, the newest 20 with the rest behind **Show more**) and a **Working** shelf, in compact rows that show the workspace, the status and how long it has waited. The Mac or `aiden serve` host sorts each chat; this phone keeps the chat it has open out of Updates, wakes a snooze on its own clock and ages out old chats, and sorts the chats of an older host itself with the desktop's rules. Swipe right to **Mark read** (when the host shares read state) and left for **Done** or **Snooze** (1 hour, this evening, tomorrow, next week) when the host offers triage to phones. Done and Snooze are never offered on a chat that waits on you or is running, and on a failed run you haven't seen only when the host can also mark it read; they appear as soon as the host's features arrive, even after the list. Each change shows at once with Undo in a snackbar (which stays until dismissed with TalkBack on, including when TalkBack is turned on while it shows), Undo puts back what the chat held before, and a refused change puts back only what it changed. Undo goes away 5 seconds after the change, as on the Mac, even if it was waiting behind another message, and a change that had to be resent because the chat changed elsewhere first lands quietly, with no confirmation or Undo. An Undo is never resent: if the chat changed on another device since, Undo leaves it as it is and says so. A snooze confirmation says "tomorrow" for tomorrow. A chat you open while its change is still on its way stays read even if the host refuses, Mark read no longer hides a pin made on the Mac meanwhile, a list refresh never undoes a swipe, and a change sent just before you switch hosts settles on the host it went to. Opening a chat ends its Done only for a reply the host counts, not a blank or cancelled one. Opening one row's swipe actions closes any other. TalkBack offers the same actions on each row. Times follow the phone's locale. Workspaces and Recents now list chats by recency, as on the Mac, instead of putting chats that need you first.
- The Working indicator on chat rows is now the desktop's open ring turning once every 1.5 seconds, instead of a breathing dot, and it holds still when Reduce Motion is on.
