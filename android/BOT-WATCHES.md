# Bot watches on Android

On a paired host offering the negotiated `bot:watches` capability, open **Bot profile → Watches**. A phone with Bot-read permission can inspect existing watches. Creating, editing, discovering sources, testing, pausing/resuming, deleting and running a watch also require Bot-edit permission. Older hosts hide the profile entry; a restored Watches destination explains that the host needs an update.

When the host offers Composio in **Bot profile → Advanced → Access**, Composio has one connection allowance. Enabled apps and tools are managed in Composio, rather than granting each internal meta-tool on the phone. A previously partial Custom grant is retained as an unavailable selected connection; it is never rebound to the broader service by an unrelated model or settings edit. Remove that unavailable choice and explicitly select the new Composio service to grant it. This service allowance does not prove a watch adapter or make an unsupported Calendar source available.

Choose **New watch → Find connected sources** to ask the host for its supported connected accounts and resources. The phone receives opaque option IDs and safe provider/account/resource labels. It never receives raw MCP arguments, credentials or binding fingerprints. Connection setup and repair stay on the owning computer. Calendar controls use the host's availability descriptor; Calendar remains unavailable while exact account, recurrence and cancellation identity cannot be guaranteed. There is no script fallback.

For Mail, choose sender/subject filters, unread-only if needed, a 15/30/60-minute interval and the Bot's instructions. **Approve watch** authorizes those bounded reads under the Bot's current grants. The first successful check establishes a baseline. The host alone checks sources while Aiden is running and the computer is awake; navigating away or disconnecting the phone does not stop it. Pausing, quitting or sleeping the host stops checks.

While the Watches screen is resumed, it refreshes the host's saved status about every 15 seconds. This is a cache-only GET: it does not discover sources, test a connector, run a watch or poll source contents. Refresh stops when the screen pauses or closes, and keeps drafts and unconfirmed mutations intact.

**Test check** previews a bounded result without advancing the baseline or starting the Bot. In an existing draft without a newly selected source, **Test saved watch** explicitly tests the saved configuration. **Run now** separately requests execution and reports whether the host admitted or suppressed/combined the run under its policies. Delete stops future checks without undoing admitted work. A failed watch links to the Bot's chat and issues.

Drafts and exact in-flight mutation identities are stored in the existing encrypted, backup-excluded preference store under the current pairing identity. A synchronous durable commit finishes before any mutation is transmitted, and restored requests never retry automatically after process death. Secure-storage failure refuses transmission while keeping the draft visible. Forgetting or revoking the pairing purges its records and fences late writes. Uncertain responses keep the original request body, expected revision and UUID; no new identity or automatic write retry is created. Refresh can reconcile a create by its exact host ID or a deletion by absence. Other uncertain outcomes offer **Retry same request**. A later retry error, including a missing route/resource or revision refusal, does not settle the original unknown operation or allow a fresh write identity. Watch text limits match the host's UTF-16 units; editor truncation preserves surrogate pairs. Concurrent edits preserve the draft and current host configuration; **Use latest revision** explicitly accepts saving against the newer revision. State from a different or replaced pairing cannot issue requests or publish a late response.

Verification uses Gradle's discovered JVM tests: `AidenBotWatchContractTest`, `AidenBotWatchClientTest`, `features.bots.AidenBotWatchControllerTest`, `AidenBotWatchJournalStoreTest`, and watch navigation cases in `navigation.AidenNavigationStackTest`. The shared DTO fixture is `protocol/aiden-remote/v1/fixtures/bot-watches.json`. Compilation and JVM tests do not substitute for paired physical-device, TalkBack, or visual acceptance.

This covers native request construction and state; it does not establish authenticated Calendar support or physical-device acceptance.
