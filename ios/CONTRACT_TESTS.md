# Aiden Remote contract tests

The normative API is [`../protocol/aiden-remote/v1/openapi.json`](../protocol/aiden-remote/v1/openapi.json). Cross-platform fixtures live under `../protocol/aiden-remote/v1/fixtures/`.

Desktop and Swift tests must agree on protocol versioning, pairing, error envelopes, bounds, opaque handles, revision/idempotency preconditions, SSE sequence and terminal behavior, and forbidden private fields. A passing decoder test is not permission to add an undocumented endpoint or payload.

Connector-watch coverage lives in `AidenBotWatchTests` and the focused watch methods in `AidenRemoteClientTests`. The Xcode test target copies the shared `bot-watches.json` fixture. Cases cover safe Codable projections, required identity/revision and bounds, private-field rejection, explicit source discovery, typed saved/draft testing, current grant and pairing fences, stale edits, removal, unknown outcomes with frozen mutation identities retained across denied retries and write-grant changes, authoritative settlement racing a denied retry, pause/resume/delete, Run now admission, and older-host capability fallback, protected restart retention and pairing purge, expired replay refusal, and corrupt local attempt fail-closed behavior. Simulator results are regression evidence; they do not substitute for physical pairing, sleep/reconnect or provider/account acceptance.

Composio service compatibility uses the existing Bot catalog, selection and Advanced-save behavior in `AidenBotContractTests`: one current Composio allow choice alongside ordinary connection choices; retained unavailable or unknown old partial IDs; an unrelated edit and catalog rebase that cannot grant the new service; and an explicit replacement selection that uses only the new host-issued ID. No additional Remote DTO, capability or protocol revision is involved.

Open work revision 55 adds `AidenBotOpenWorkTests` and focused methods in `AidenRemoteClientTests`; the Xcode target copies the shared `bot-open-work.json` fixture. Behavioral coverage includes strict identities and partial payload refusal, decimal IDs above JavaScript’s safe-integer range, scalar and UTF-8 text bounds, waiting-state validation, current and old-host grants, same-revision execution refresh, stale drafts, actual retained evidence and privacy, metadata-only mutation bodies, the complete add/edit/Waiting/Done/Reopen/Dismiss/Undo journey, Undo fenced by another client’s pending Stop, frozen unknown writes including parsed `unavailable`, restart and cross-window retention, pairing purge and late callbacks, denied retry fencing, protected Stop checks beyond 24 hours, and terminal acknowledgement before Stop and dismiss completes. Simulator execution is regression evidence and does not prove physical pairing, VoiceOver operation or provider/host lifecycle acceptance.
