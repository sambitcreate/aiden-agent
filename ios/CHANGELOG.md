# Changelog

## Unreleased

- **2026-11-11 — Stopped calls read as stopped (Remote revision 61).** A tool call the person ended with Stop on the Mac reads "<Step> stopped" with a neutral mark and is not counted as an issue. The host marks exactly those calls with `stoppedByUser: true`; a call cancelled for any other reason, even earlier in a run the person later stopped, keeps the cancelled issue treatment. Older hosts send no mark, so their cancelled calls stay issues.

- The app is now one tab shell: **Inbox**, **Workspaces**, **Bots** and **Search**, each with its own stack, and a sidebar at regular width. Inbox lists every paired machine's chats together. The Aiden-logo menu, its first-run tip and the per-machine sidebar views are gone, along with the build setting that chose between the two shells. Scheduled tasks, Usage, Machines and Settings open as pages in a tab. An open chat stays on its own machine when the default machine changes. A notification for a machine you've removed now does nothing instead of showing an error.

- Behind the scenes, `AidenChatFeature.swift` and `AidenWorkspaceShellView.swift` are now split into focused files under `Features/Chat/` and `Features/Workspace/`. No change to behavior or appearance.

- Aiden On The Go now needs iOS 26 or later (it was iOS 18). iPhones that cannot run iOS 26 stay on the last build they have. The app uses the system Liquid Glass and Image Playground APIs directly, without the older material fallbacks. Reduce Transparency still shows solid surfaces.

- Debug builds can launch the real shell against fake machines: `-AidenDemoScenario <one|four|empty|busy|offline-mix|old-host>` serves every request from an in-process responder on `*.demo.invalid`, without touching your Keychain, pairings or caches. A new `AidenOnTheGoUITests` target uses it. CI runs one smoke test that opens the shell against every scenario; the screenshot matrix and accessibility audit stay a local tool. Release builds contain none of it. CI also gains a non-blocking Xcode 27 build and test check; releases stay on Xcode 26.6.

- **2026-11-06 — "By voice" label (Remote revision 60).** A chat message Aiden Live sent on the Mac shows a small "By voice" label with a microphone under it. The host marks it with `inputSource: "voice"` on user messages only; the app ignores any other value or a marker on a reply. Older hosts send no marker, so nothing changes there.

- **2026-11-05 — Remote revision 59 reconciliation.** Main now uses revision 58 for connected-chat live-history checkpoints. Continuity watches, Open work, routine models and approved Bot peers therefore enter the combined release at revision 59. Earlier dated revision assignments remain historical; messaging/access/plans/allowed thresholds remain 54–57.

- **2026-11-05 — Notification visibility during delivery.** Bot notification polls recheck their original messaging, issue, access-request, peer and read grants before posting and saving progress, including after system permission/post callbacks. Lost access keeps the original cursor and delivered IDs. Routine notifications retain older-host baseline behavior; no Remote wire or revision change.

- **2026-11-05 — Combined Remote revision 58.** Connector watches, Open work, routine model management and approved Bot peers first enter the shared release at revision 58. Earlier revision numbers below describe branch implementation checkpoints; shipped messaging, access requests, plans and allowed-list capabilities retain revisions 54–57. Both `message` and `peer` notifications remain supported.

- **2026-11-04 — Verified Calendar watch support.** Supporting Mac and Linux Electron hosts now offer Composio Calendar sources after authenticated exact-account/list/events/GET acceptance. Existing Watches controls can discover, preview and manage those sources; no new native contract revision is needed. iMCP Mail remains Mac-only. Watch diagnostics report only their own inspection/check outcome and do not authorize a source or change its availability.


- Remote revision 56: full per-routine model, thinking and explicit fallback management for existing scheduled, event and connected-app watch routines; host-projected choices and recent chosen/actual model and timing facts. Protected drafts and frozen CAS requests survive disconnect/restart, and stale choices require review. Interrupted-work Resume checks unconfirmed provider cost and requires explicit acknowledgement when needed; unknown requests keep their exact interrupted-submission and cost-receipt preconditions, consent body and UUID. A stale confirmation cannot authorize a newer unconfirmed cost on the same interrupted submission. Resume preflight and consent are scoped to one active, visible chat visit while background hand-off updates continue. First typed unknown/in-flight outcomes retain the exact pending Resume even on HTTP 409. Pending Resume blocks capability-loss fallback, and replayed historical receipts reconcile current session state passively. Profile unpause and older-host wire behavior remain unchanged.

- Contract revision 55 (`bot:open-work`): a supporting paired host adds **Open work** to Bot profiles. Add and edit responsibilities, record Waiting reasons, mark Done, Reopen, Dismiss and Undo a recent metadata change. View owned source/result transcript excerpts and host-derived execution. Stop targets only safely linked work, and Stop and dismiss waits for acknowledgement. Protected local drafts and frozen requests survive disconnect and restart; Add never starts or schedules a run.

- Contract revision 54 (`bot:watches`): a supporting paired host adds **Watches** to Bot profiles. Discover safe account/resource choices, create and edit typed watches, pause or resume, preview a test check, delete, or explicitly Run now. Polling and execution stay on the host. Calendar remains unavailable until exact-account and occurrence guarantees are available. Protected device-only drafts and frozen unresolved requests survive disconnect and restart, with stale-revision review and the original mutation identity retained for an explicit retry.

- Remote revision 57 (`bot:allowed`): capable hosts offer Always allow for a Bot after repeated approvals, plus an Allowed without asking profile list. The list includes every rule and folder across pages. Remove waits for the host and keeps the row on failure. Unknown-outcome retries keep the exact decision/scope body and key; Always acknowledges “Always allow requested.” The host remains the authority for saved access. Eligible folder cards also show the host’s approval count. Older hosts keep their existing cards.

- Stream recovery keeps a host-requested retry delay across a temporary network loss, counting time asleep toward the wait.
- **Recording player cleanup (2026-11-02).** Leaving or replacing a browser-recording card removes its downloaded video even if the player has not appeared. A load that finishes after navigation cannot reopen the player, and repeated Plays of the same recording keep separate files so closing one preserves the other.

- Leaving a Bot chat while a send is being cancelled keeps the message available to retry with its original key, even if the connection returns a receipt during cancellation.

- **Inbox (Beta).** The sidebar's view menu gains **Inbox** beside Workspaces and Recents, remembered for each Mac. Chats are grouped into **Needs you** (an approval, a question, or a failed run you haven't seen), **Pinned**, **Updates** (unread replies), **Earlier** (the last seven days, the newest 20 with the rest behind **Show more**) and a **Working** shelf, in compact rows that show the workspace, the status and how long it has waited. The Mac or `aiden serve` host sorts each chat; this iPhone keeps the chat it has open out of Updates, wakes a snooze on its own clock and ages out old chats, and sorts the chats of an older host itself with the desktop's rules. Swipe right to **Mark read** (when the Mac shares read state) and left for **Done** or **Snooze** (1 hour, this evening, tomorrow, next week) when the host offers triage to phones. Done and Snooze are never offered on a chat that waits on you or is running, and on a failed run you haven't seen only when the host can also mark it read. Each change shows at once with Undo, which puts back what the chat held before, and a refused change puts back only what it changed. A change that had to be resent because the chat changed elsewhere first lands quietly, with no confirmation or Undo, and an Undo is never resent: if the chat changed on another device since, Undo leaves it as it is and says so. A snooze confirmation says "tomorrow" for tomorrow. VoiceOver reads each confirmation aloud and the banner stays until you dismiss it; without VoiceOver an Undo banner goes after 5 seconds, as on the Mac, and other messages after 10. A banner shown again after you come back to the list keeps only what was left of that time and isn't read aloud twice, and turning VoiceOver on or off while it shows takes effect at once. A chat you open while its change is still on its way stays read even if the Mac refuses the change, and a change sent just before you switch Macs settles on the Mac it went to. Opening a chat ends its Done only for a reply the Mac counts, not a blank or cancelled one. VoiceOver offers the same actions on each row, and reads the Working ring as "Working". Workspaces and Recents now list chats by recency, as on the Mac, instead of putting chats that need you first.
- The Working indicator on chat rows is now the desktop's open ring turning once every 1.5 seconds, instead of a spinner, and it holds still under Reduce Motion.
- Contract revision 51: chats without a workspace match the Mac. The sidebar shows them in one **Chats** group instead of a "No workspace" section per chat, and **New Chat** offers **No Workspace** first ("Use your global settings. Aiden keeps a private folder for this chat."), which starts a chat that runs on the Mac with its global settings in a private folder of its own. The private folders no longer appear in the workspace list, the Existing Workspace picker or Scheduled Tasks, and a "No workspace" section archived on an older build comes back under Chats. Touch and hold a chat under Chats to delete it. Older Macs, and the CLI, offer nothing new.
- Contract revision 50 (`attachments:raw`): sending photos shows a bar over the composer, in workspace and Bot chats, with "Sending 2 of 3" and how far it has got, and a **Stop** button. When the paired Mac offers it, the iPhone asks for it in a call of its own and then sends PNG and JPEG photos as their own bytes instead of base64 text, about a quarter less data. Older Macs get the same bar and the upload they always took.
- Contract revision 49 (`chat:jobs`): when the paired Mac offers it, the iPhone asks for it in a call of its own, and a workspace chat shows "2 in background" beside the composer while the agent has something running for it on the Mac (a dev server, a watcher, a long test run, or a server a command left running). The list says how long each has run or how it ended, the addresses a server listens on ("localhost:5173 on your Mac"), and offers **Stop**, which ends the job and everything it started. The list refreshes after each reply and every few seconds while something runs. Older Macs show nothing new.
- Contract revision 53 (`chat:new-worktree`): when the paired Mac offers it, the iPhone asks for it in a call of its own. A new Workspace chat in a Git repository then shows a **New worktree** chip beside the composer. Turned on, your first message shows at once with a **Setting up worktree…** row and **Cancel** while the Mac makes a worktree from the repository's default branch (or the branch it's on, without a remote), names its branch from the message (`aiden/new-chat` for a message of attachments only), and moves the chat into it; then the message sends there. Cancel puts the message back in the composer; if the Mac finishes the worktree anyway, sending again uses it. If the Mac can't make the worktree, it says why in plain words and the message comes back unsent, and sending again tries afresh. If New worktree stops being available while the chip is on, the chip turns off and the message stays unsent. The chip is hidden for a folder that isn't a repository or has no commits yet (when the phone may read Git), for a workspace that is already a worktree, and on older Macs.
- The disconnected recovery panel now offers **Switch connection**, so an unavailable computer no longer leaves you with only Retry. Open the saved-computer list or pair another Aiden Agent directly, including when a secure-identity failure prevents retrying.

- The Thinking row in a chat no longer opens for a second and folds shut, which made the transcript jump when a fast model thought in many short bursts. It now stays one row tall: while the model thinks, the row shows its latest finished sentence or line next to "Thinking", fading in as each one finishes (no movement under Reduce Motion) and fading out when thinking ends. Tap the row to read the full reasoning, as before.
- Contract revision 47 (`spending-limits-v1`): when the paired Mac has spending limits on, a workspace chat or Bot chat shows a quiet line once it has used 80% of its limit ("This chat has used $4.10 of its $5.00 limit."), and a card with **Allow $X more** once it reaches it. Allowing more from two devices at once adds the amount once. The limits themselves are set on the Mac. Older Macs show nothing new; a send over the limit is refused with the Mac's message either way.
- Contract revision 46 (`chat-browser-recordings-v1`): when the agent on the Mac records a browser tab, the chat shows a **Browser recording** card under the "Stopped browser recording" line with the video's length and size ("0:12 · 1.0 MB"). When the paired Mac announces it, **Play** reads the MP4 from the Mac only then, keeps it in a temporary file while it plays full screen with the system controls, and removes it when the player closes. A recording the Mac no longer has says "This recording is no longer on the Mac." A WebM recording, or a Mac that doesn't serve recordings, shows "Watch this recording on your Mac." instead of Play. A recap the phone can't verify is dropped and the step stays an ordinary activity line. Older Macs send no card.
- Contract revision 44: a picture the agent shows, shares or generates now sits right under the step that made it, in the order the reply happened, instead of piling up after the whole reply. Older replies get the same order when the Mac can tell which step showed which picture. Older Macs keep the pictures at the end.
- Bot inbox search works with spaces, accents and symbols. The iPhone now sends a space as `+`, which every Mac reads, instead of `%20`, which the Mac refused, so a search such as "plan week" worked nowhere before. A search with an accent, `&`, `#` or `+` needs a Mac on contract revision 41; an older one still refuses it.
- Contract revision 42 (`bot:issues`): when the paired Mac offers it, the iPhone asks for it in a call of its own, and a Bot's **Needs you** cards appear in its chat: what happened in plain words (a routine paused after repeated failures, a sign-in that lapsed, a run that stopped making progress) with up to two actions (**Resume routine**, **Stop**, **Keep waiting**, **Open chat**). A card whose only action opens the Mac's own settings reads "Open on your Mac". The Bots list shows how many open cards a Bot has, and an issue that arrived while the app was in the background posts one notification that opens the chat. Older Macs send no cards.
- A message sent in a Bot chat now looks sent the moment you press Send, instead of faded until the Mac accepts it. "Sending…" shows under it only when it has waited more than 2 seconds (offline, or a slow Mac); Queued and "Couldn’t send · Try again" are unchanged.
- Contract revision 39 (`schedule:cards`): when the paired Mac offers it, the iPhone asks for it in a call of its own after its other opt-ins, and a scheduled-task approval becomes a full review card instead of a one-line summary. The card asks what approving would do ("Save this scheduled task?", "Pause this scheduled task?", "Run this scheduled task now?"), leads with the task's name, cadence and next run (read in the phone's own time zone and clock), then lists where it runs (the project, its connectors, "Anywhere on your computer" for Full access, or "No project"), its access as a soft Read-only or warning-tinted Full access chip, the model or "Script", notifications and time zone. The instructions or script follow in a block that folds to six lines behind **Show all**, with a note when the Mac shortened them, and a note says when scheduling is off or the task stays paused. A card that fails the phone's checks is dropped and never changes what the approval allows; older Macs, and the Assistant's automation edits, keep the summary card.
- The approval card matches the desktop redesign: an accent icon tile, the action as a plain question ("Run this command?", "Edit forecast.ts?"), the exact command or path in a code block without the "Run command:" prefix (long requests fold to six lines behind **Show all** and scroll in a bounded box once expanded, with a **Scroll for more** cue while the end is out of view), a centered "Aiden is paused until you choose." note, and two full-width buttons. **Allow once** carries a chevron menu for **Allow for this chat** and **Always allow** when the Mac offers them, each saying what it covers: the exact command, or any later edit to that file. An action that only the Mac may allow now says "Allow this on your Mac. You can deny it here." A scheduled task asks "Save this scheduled task?" (or "Change this automation?"), as on the Mac, and the card's shadow no longer blurs its text in light mode. A chat's activity summary now says "Skipped 1 command" for a denied call instead of "Ran 1 command", and "Waiting for approval" while a call waits, matching the Mac.
- Contract revision 38: when the agent on the Mac reads a web page in extract mode, the chat shows the values it read in a card under the "Fetched web page" line, each with the page line it came from. Values the agent isn't sure of carry a **Guess** label, and values the page doesn't have read "Not on the page". The Explored summary also counts the web pages read. Older Macs send no card.
- Contract revision 37 (`bot:handoffs`): when the paired Mac offers it, the iPhone asks for it in a call of its own. A Bot's chat then shows the step the Bot hands back ("Your turn: …") next to the question and approval cards. **Done**, **Skip** and **Open** answer it, and a note typed in the composer is sent as Done. A sign-in offers **Finish on your Mac** and **Skip**. The Bot profile's More menu offers **Pause Bot** and **Resume Bot**, and a paused Bot's chat shows a Resume card and holds the composer. Bots list rows now read "Interrupted — tap to resume" for an interrupted Bot and "Paused" for one you paused. A hand-off that arrives while the app is in the background posts one notification that opens the chat. Older Macs keep the "needs you on your Mac" message.
- Smoother chat streaming. A finished reply no longer flashes twice or jumps as it settles: the live reply is replaced by the saved one in the same frame, a reply that only ran tools stays on screen until the saved transcript arrives, and "Working for" now sits in the footer row that "Worked for" takes over. Text that arrives in bursts is paced out word by word over about a quarter second instead of landing in lumps (never more than ~600 characters behind, and the end of a reply drains in instead of dumping; off under Reduce Motion), in workspace and Bot chats. Half-received Markdown no longer flashes as raw syntax: an open `**bold`, `` `code`` or link on the line being written draws finished, and a lone list or heading marker waits for its text. A sent message keeps its row when the Mac confirms it, so its attachment thumbnails no longer reload.
- Contract revision 36: a chat whose unseen output is a failed turn now says **Failed** (a soft red pill, VoiceOver "Failed") in place of the unread dot, so a run that failed in the background no longer looks like a fresh reply. Opening the chat clears it with the dot. Older Macs omit the hint and keep the dot.

A first read with nothing saved shows shaped skeleton rows, empty states appear only after the Mac answers, and an unreachable Mac with nothing saved says so.
