# Protected task-quality host adapter v2

H2b extends the frozen six cases without editing `task-quality-fixtures/pilot-manifest.json`, its controls, or historical results. `npm run test:task-quality` executes the new production-harness adapter and protected verifier. This is offline falsification, with no inference, billed usage, quality-improvement or rollout claim.

Each run creates a fresh workspace and a separate private host directory. Agent tools are Aiden's production pinned workspace file tools, the real scoped `read_tool_output` reader when relevant, and the durable Todo extension. There is no shell, connector or network tool in this evaluation surface. Oracles, controls, manifest, sessions and receipts stay outside the workspace. Historical observations are legal assistant-tool-call/tool-result pairs. Output recovery stores actual bytes in ToolOutputStore and presents an actual handle and bounded preview; acceptance requires the corresponding real authorized read to return the decisive rows. A correct guessed answer alone fails that predicate.

For resumed plans the host executes the actual Todo list operation to seed JSONL history, writes a real compaction checkpoint containing the short resume summary, rebuilds Todo through durable replay, and starts the model with that compacted context. Every committed intermediate snapshot is recorded privately. Forbidden mutation attempts also invalidate acceptance, even if the final file and plan look correct. Final state is reopened from the JSONL repository; matching final state cannot erase intermediate evidence.

Production PiAgentRuntimeHarness executes the controls. The host records an artifact-bound task-predicate receipt using PiVerificationStore, and inspects its freshness and evidence availability before accepting it. The same host receipt and snapshot are captured in a private WorkflowEvidenceStore bundle; candidate prose cannot supply that evidence. Provider prose and lifecycle completion never constitute task acceptance. Failed assertions are failed checks; isolation/setup/protocol errors are inconclusive. Agent attempts to escape the workspace fail acceptance even when production tools deny the access and the final solution is correct.

The original Python oracles import candidates directly, which would expose grading material in the same process. The new trusted verifier retains every frozen assertion and replaces only its three reviewed importlib bootstrap statements with an RPC proxy. Candidate code executes in one persistent OS-isolated worker for the entire oracle, preserving module state across calls. A separate, deliberately constrained Python admission policy protects observation fidelity: bounded syntax, csv/io imports, allowlisted builtins and attributes, no reflection/frame access, and a namespace separate from the worker protocol. All frozen controls fit this subset. Arbitrary Python, dynamic imports and introspection are unsupported and produce an inconclusive result, never a pass. OS isolation alone does not make a Python process tamperproof against its own candidate code. RPC uses a bounded object graph with stable identities for lists, dictionaries and tuples. It preserves shared references across calls and synchronizes all retained objects, including earlier arguments mutated during a later call and mutations before exceptions. Only exact supported value types cross the protocol; dynamic type construction is unsupported. Identity comparisons are admitted only against None/bool singletons because primitive interning across separate interpreters cannot be faithfully inferred. This keeps the frozen input-preservation assertions meaningful. Candidate stdout is discarded or bounded; CPU, file descriptors, child process admission, Linux address space and wall time are bounded. The verifier never executes model code in its trusted process.

On macOS, `sandbox-exec` denies writes and network by default and denies reads from user home trees, temporary state, external volumes and network mounts. Only the disposable candidate directory and generic RPC worker are read exceptions; ordinary system runtime reads allow Python startup. A trusted probe inside the same isolated worker executes actual attempts to read an existing oracle, write protected state and connect to an actually listening host-local TCP port. It passes only when reads/writes are denied or hidden and the host listener is unreachable. Linux hidden mounts produce FileNotFoundError; a separate network namespace may refuse the host port instead of macOS's PermissionError. macOS 26 CI already runs the registered core lane. On Linux the implementation requires `bwrap` (bubblewrap), Python 3, working unprivileged user namespaces, and the existing file-mutator build prerequisite. It uses a fresh PID, mount, IPC, user and network namespace with read-only Python/system mounts, the candidate and generic worker only. Linux execution has not been exercised on this macOS host. Missing or disabled OS isolation fails closed; there is no unsandboxed fallback. Install bubblewrap in a Linux evaluation runner before invoking this suite.

A version 2 experiment identity records harness commit and dirty diff digest; source/fixture/lock hashes; model/provider/API/effort/options; full admitted prompt and tool-schema template hashes (including Todo), no-skills hash, policy revision and fresh-cache preparation. Existing directories and manifest files are not reused. Explicit identity comparison rejects incompatible resume. Each task permits at most 16 provider requests, 64 tool calls and a 45-second harness deadline, followed by a separately bounded verifier. The executable offline adapter admits only its faux-control provider/API configuration; H2c needs a separately frozen provider, request/output, endpoint, wall-time and cumulative-spend manifest before any real inference.

Acceptance checks include all 7 positive and 22 negative frozen controls; correct final output with no retained-output read; correct final output after attempted checkpoint replacement; production tool read/write attempts against grading paths; actual OS isolation denial; persistent correct-once/then-raise and request-introspection mutation-forgery and cross-call alias attacks; identity incompatibility; and unchanged/harmful paired controls retaining the baseline. The seven existing lifecycle replays remain separate. No Remote/transcript contract or native-client behavior is added.
