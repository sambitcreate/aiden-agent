# Helpers (native subagents)

A foreground chat can delegate up to four fresh `scout`, `planner`, `reviewer`, or `implementer` tasks per call, and up to eight per reply. Children inherit the approved workspace and model, stop with the parent, and appear as one collapsible card in the transcript (one line per child, the shared role named once in its header) plus a **Subagents** list in Environment. Only one indicator shows at a time: while the card is on screen nothing else does, and once it scrolls out of view a pill above the composer takes over (`⌘⇧S` opens its tray of runs, with Stop, Show in chat and a button that opens the helper chat, worded for the helper's state: Open helper chat while it runs, Review when it waits on you, View result once it ends; the tray opens even while the pill is hidden). Every helper shows the same status word everywhere: Queued, Running, Waiting on you, Done, Failed or Stopped. A helper that waits on one of your approvals reads Waiting on you in the card, the pill, the tray and the Subagents list, even while its own record still says it is running. The implementer can edit files and run commands within the parent permission ceiling.

## What each role may do

| Role defaults when capabilities are omitted | Full workspace access                                          | Ask workspace access                                                               | None                    |
| ------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------- |
| Scout, planner, reviewer: read/search       | Read/search                                                    | Read/search                                                                        | No workspace tools      |
| Implementer: read/search, write/edit, shell | Writes and shell run under this child run without another card | One write grant and one separate shell grant per child run, requested on first use | No write or shell tools |

## Time limits and partial work

Chat helpers have no short clock: a 24-hour safety net counts from the first launch, and helpers waiting for a slot lose no time. A Bot's helpers share 60 minutes per reply from the first launch; after that, further helper calls in the reply start nothing. A reply is one message to the Bot and the answer it produces, so a new message starts a new reply with a fresh 60 minutes. An interrupted Bot task that a person resumes also counts as a new reply; the desktop's own quiet retries keep the reply's clock. Near its turn or tool limit, or a Bot's time limit, a child reserves one text-only reporting turn. A helper that is stopped, fails or runs out of time hands the parent its last messages and the files it changed, marked incomplete and unverified. Cancellation still stops it. Web and MCP calls keep their existing per-call approval behavior. Implementer cannot delegate to another subagent. Rollout flags and the parent capability ceiling can narrow every row.

## Saved conversations

Each helper's conversation (its task, messages and tool steps) is saved with the chat, with API keys, tokens, private keys and secret-named values such as passwords and one-time codes hidden by the same credential filter a stopped helper's partial work uses, and file paths kept, up to 2 MB per helper (older steps are dropped first). It is removed when the chat is deleted. Bot helpers save it the same way, on the desktop and under `aiden serve`; Bot helpers' conversations are not shown, and phones do not receive them.

## The helper chat

Clicking a helper (a row in the chat card, the tray's helper chat button, or the Subagents list) opens its **helper chat** in the side panel: the task, then its messages and steps drawn like the main chat (runs of tool steps grouped). Only the window running the chat updates it live as the helper works; another open window re-reads the saved copy whenever the helper's status or saved revision changes, including when it ends. A helper waiting on an approval reads Waiting on you, as does the main chat's working line, in the window running the chat. A helper's approval is answered in one place, the card in the main chat: while the helper chat sits in the side panel it shows a short row, Needs your approval in the main chat, with **Go to approval**, which scrolls to the main chat's approval card, puts focus on it and briefly tints it (with Reduce Motion the tint holds still instead of fading); when the main card shows other requests first, the row says how many and the button reads **Go to main chat**; and the full approval card appears inside the helper chat only while it is expanded. A bar at the bottom shows the model with Stop while it runs (Stop all when it has started helpers of its own that are still active), Expand and Close; Expand shows the helper chat in place of the main chat, and the side panel says the helper is open in the main chat, until **Back to main chat** or Esc (its tooltip names the key). While the expanded helper chat covers the conversation, the conversation's link previews and tooltips stay closed (a menu or dialog opened from it still shows its own); when the side panel floats over the conversation in a narrow window, any open link preview or tooltip closes once and the visible strip shows them again on the next hover. If the main chat needs you for something else while a helper chat is expanded, a bar says the main chat needs your approval or has a question for you, and its **Go to approval** or **Answer question** button returns to the main chat and puts focus on what waits. A helper that stopped or failed shows one plain box saying what happened in plain words (for example that it ran out of turns or allowed steps) and what it changed, with **Ask the main chat to retry**, which puts a ready-made request in the message box without sending it. If its conversation cannot be loaded, the helper chat says so with **Try again**. Helpers saved before conversations were recorded show a short summary instead: what it was asked, what it did, and its result. The helper chat is read-only.
