# Skill discovery

Desktop Aiden reads `SKILL.md` instructions from global and workspace `.agents`, `.claude/skills`, and `.aiden/{skill,skills}` folders. Workspace skills override global skills with the same name. Within each source, `.aiden` takes precedence over `.claude`, then `.agents`. Configured skills and immutable built-ins keep their existing precedence. Turn discovery and invocation off in Settings → Skills.

Aiden also reads enabled installed Claude Code plugins from `~/.claude/plugins/installed_plugins.json`. It merges boolean `enabledPlugins` values from `~/.claude/settings.json`, then the active workspace's `.claude/settings.json` and `.claude/settings.local.json`. Missing, disabled, malformed, and nonboolean entries are ignored. Aiden reads local files only. Discovery never installs, launches, or fetches a plugin and does not load plugin hooks, commands, MCP servers, or executable code.

A plugin's manifest name, or its installation key before `@` when no name is supplied, prefixes each authored skill name as `plugin:name`. Namespaces accept letters, digits, underscores, and hyphens, with a maximum of 40 characters. Ordinary authored skills can override the same namespaced skill. The standard `skills/` collection, bounded relative `skills` paths in `.claude-plugin/plugin.json`, and a root `SKILL.md` are supported. Absolute paths, parent escapes, and symlinked skill paths are rejected. Aiden reads the skill's frontmatter name and invocation policies directly, rather than dispatching a native plugin command.

The first applicable installed record in inventory order supplies each plugin. User and managed records are global unless workspace settings enable them, in which case they require workspace access. Project and local records require a `projectPath` matching the active workspace directory after resolving path aliases and always require workspace access. Aiden does not inherit a different checkout's installation or a parent project's settings into a nested workspace. Alternate Claude config/cache environment paths and plugin development sources are not imported.

Plugin metadata files are limited to 1 MiB each, with at most 128 plugin inventory entries and 16 custom paths per plugin. On desktop, plugin instructions share the existing source budgets with ordinary skills: 1,000 candidates, 4,000 traversed entries and 16 MiB per workspace/global source. Individual instruction and relative-depth limits still apply. The catalog refreshes at its existing request boundary and short cache interval.

The standalone CLI supports enabled installed plugins through the same bounded scanner, after its own project trust decision. It keeps native and explicit skill paths ahead of automatic sources. Because its current command runtime cannot enforce a separate user-invocation policy, it omits plugin skills marked `user-invocable: false`. Desktop honors model and user invocation policies independently.

The CLI also accepts repeated `--add-dir <directory>` options, including the equals form. Each folder contributes `.aiden/skills`, `.claude/skills`, and `.agents/skills` after the active project's normal sources. Relative paths resolve against the launch directory, including when resuming a session elsewhere. At most 32 folders are accepted. The active project's trust decision and `--no-skills` gate these automatic roots. This option imports skills only; it does not expand file-tool or shell permissions. See the [CLI guide](../packages/cli/README.md).

Paired phones and desktop hosts consume their existing workspace skill catalog. Skill paths and instruction bodies stay on the serving host; the wire contract is unchanged.
