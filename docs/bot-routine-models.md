# Models for Bot routines

Choose **Model** beside a scheduled routine, event routine or connected-app watch on the desktop. On iPhone and Android, open the Bot’s **Profile → Routine models** to choose from all its routines. The owning desktop supplies the models and supported thinking levels. Opening this chooser does not refresh a provider catalog, connect an app or sign in.

**Bot default** uses the Bot’s model and thinking level when a fire is accepted. **Choose a model** saves an exact model and thinking level for this routine. Saving grants that routine permission to use its chosen model; it does not change the Bot’s default or another routine. In Custom access, this is a separate routine-specific grant. Choose an optional fallback explicitly if you want one. Unsupported thinking levels cannot be saved.

An unavailable chosen model or credential stops the work with **Needs you**. An explicitly configured fallback can be selected only before provider or tool effects, for an eligible unavailable-model or credential failure. A request already prepared or sent keeps its actual model. Provider errors, spending limits and partial work never trigger an automatic switch. Images must fit the selected model or the Bot’s explicitly configured image-understanding companion.

Each accepted fire keeps its model, thinking, allowed fallback, source restrictions and budget scope across queued turns, tools, summaries and restart recovery. Changing a setting affects future fires. A different routine or a person’s message in the same conversation keeps its own choice. Current access and credential revocation still apply; a saved choice cannot restore revoked access. A recovered connector watch cannot create a missing connection.

The chooser shows recent accepted runs with both the chosen and actual model, thinking level and any fallback reason. Scheduled runs retain their original due time and timezone alongside actual start time, so a delayed run can explain when it was meant to run. A recurring catch-up uses the latest relevant missed occurrence; resuming or editing does not rewrite an already claimed occurrence.

A save uses the displayed revision and an identity retained on that device before transmission. A conflict keeps your draft for review. A lost response or unavailable storage outcome keeps the exact request for an explicit retry; an authoritative matching host receipt can settle it. Clients stop ordinary retries after twenty-three hours rather than inventing a replacement identity. Deleting a Bot clears its local pending watch, Open work, routine-model and Resume requests after the owning host confirms deletion; ordinary missing rows or a failed read do not prove deletion.

If Aiden cannot confirm the cost of an earlier provider request, the Bot remains interrupted. **Resume** explains that another request may incur another charge and requires your confirmation for that exact interrupted input and unconfirmed provider request. If another device already resolved it and a later request has an unknown cost on the same input, the earlier dialog cannot approve the later one. This acknowledgement retains the unknown receipt and permits a new attempt; it does not record a zero cost or raise known spending limits. Unpausing a Bot in Profile does not acknowledge a cost or resume its interrupted turn. See [spending and recovery](usage-limits-and-spending.md#unconfirmed-bot-request-costs).

Every client retains a Resume request’s exact UUID and body before sending it, including an ordinary request without cost acknowledgement. Leaving a page or restarting the app does not replace that request or add consent to it. **Retry saved Resume** on desktop confirms the original request first. A new foreground visit requires fresh preflight and confirmation for a new request; work the host already accepted continues under its existing rules. The host records consumed Resume identities in the conversation before effects and retains them for twenty-four hours. Replaying one reads current state without resuming or acknowledging again. A crash before its effects can leave work interrupted: settle the saved request, then make a fresh explicit Resume action. Full or unreadable control storage refuses another operation.

This management surface is available on macOS and Linux desktops with Bots, and on paired iOS and Android clients when the host negotiates `bot:routine-models` with Bot and chat read access. Saving, catalog access and Resume preflight also require Bot write access. An older or unsupported host leaves the surface unavailable. The standalone `aiden serve` host does not advertise these optional management routes.

Routine choices and execution claims are kept in the existing authenticated, rollback-protected Bot capability state; provider keys are never included in those claims or sent to phones. This private state is forward-only: after this release writes routine-model state, an older Aiden build may refuse that Bot’s authority. Use the matching build with that profile rather than alternating old and new releases.

For contributors, `npm run test:subagents` builds the VCC worker and native test prerequisites before exercising child runtimes. The routine-model suites also exercise real durable sessions and restart boundaries; model selection is bound at each task’s preparation rather than by changing a conversation-wide default.
