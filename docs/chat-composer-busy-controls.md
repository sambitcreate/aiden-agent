# Chat composer busy controls audit

Reference: [Hermex Bot Mode contract](https://github.com/uzairansaruzi/hermex/blob/master/docs/agents/bots.md), reviewed on September 23, 2026. Aiden remains on its own Mac execution runtime and Remote API v1.

| Hermex rule or mode | Aiden desktop after this change | Aiden On The Go |
| --- | --- | --- |
| Idle Send, with a busy race that cannot silently interrupt | Ordinary Send uses Aiden's append and turn admission gate. A raced busy append is rejected; the draft is restored for a deliberate choice. | Atomic turn start; a busy admission fails. |
| Steer adds guidance without interrupting | The composer's Steer mode and each text-only queued row's Steer action use the shared `chat:admitRunInput` admission (the same main-owned boundary as Remote `chat-run-input-v1` and Telegram `/steer`). Main checks the exact stream and renderer document owner, saves the guidance to the transcript, then admits it to Pi's steer queue. The open chat shows the committed message as soon as the receipt arrives. When Pi reads it, the saved message is reused, so it appears once. An admitted receipt says guidance was sent, not read; a committed-but-not-admitted receipt says it was saved as history. Only an uncommitted rejection or an unknown outcome keeps the draft or queued row. | Steer through `POST /streams/{id}/inputs` when the server advertises `chat-run-input-v1`. |
| Queue runs after the current response | Explicit Queue mode uses the existing Mac window's bounded, editable follow-up queue. Its receipt says only that a follow-up was queued. | Queue through `POST /streams/{id}/inputs` (`mode: queue`) when the server advertises `chat-run-input-v1`. |
| Redirect interrupts and changes direction | Removed on October 5, 2026. Stop, then send, does the same thing without a third mode. | Removed from iOS and Android at the same time, so all clients offer only Steer and Queue. |
| Separate Stop clears work and queued prompts, retaining unrelated composer text | Stop cancels the exact current stream and clears local queued follow-ups. The independent composer draft remains. Accepted Steer guidance is already in the transcript, so after Stop it stays there as history; it is not returned to the draft or resent. No Queue or Steer is admitted until Stop settles. Pending tool approvals are cancelled by the Mac's existing stream cancellation path. | Stream cancel only. |
| Drafts and unknown acknowledgments never auto-retry | Desktop text drafts are device-local across navigation and relaunch. A submission stores an unresolved marker before dispatch; a rejected or uncertain result restores the text. The queue's uncertain append path removes its claimed item and pauses, so it cannot replay automatically. Attachment bytes remain in the live picker and do not survive relaunch. | iOS has a device-local draft store; Android keeps the draft in its view model. Both reconcile turn state rather than resending after connection loss. |
| Receipts describe admission, not model consumption | Queue shows admission copy. The queue editor remains a Mac-local draft manager; it does not claim to edit the Pi runtime's queue. | No busy admission receipts. |

## Send control (desktop, iOS, Android)

All three clients show the same control while a response runs: one accent pill with the current mode's name and a chevron, next to a separate Stop button. Clicking or tapping the name sends in that mode (Enter does the same on desktop). The chevron opens the Steer / Queue menu, and so does holding the name; on desktop you can keep holding, drag onto a mode, and release to send in it. Each menu row shows the mode's name, a one-line description, and a check on the current mode. Picking a mode with a draft sends the draft in that mode; with nothing to send it only switches, and the pill stays visible (dimmed) with an empty draft. The mode resets to Queue when the response ends. Desktop disables Steer while the draft has attachments or a selected skill. Phones show the pill only when the paired Mac advertises `chat-run-input-v1`.

## Shared admission

Desktop Steer, Telegram `/steer`, and the Remote inputs route all enter Pi through `llmClient.admitChatRunInput`. The guidance is durable in the transcript before Pi accepts it, so a Mac restart cannot lose an accepted receipt; the run itself ends with the app, and a later delivery attempt is rejected as `run_not_active`. Desktop and Telegram do not keep a request-ID ledger: neither surface auto-retries, and Telegram does not resend edited `/steer` commands. This work is tracked by [Hermes-inspired Bot run control](plans/hermes-bot-run-control-plan.md).
