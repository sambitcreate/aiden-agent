## Existing mitigations and stale-plan corrections

The July `docs/plans/performance-stability-efficiency-plan.md` is historical evidence, not an accurate assertion of every current bug.

- **Perpetual streaming RAF is no longer present:** `streaming-markdown-reveal.tsx:84` returns when caught up; `:96` reschedules only while work remains; `:99` cancels cleanup. Do not implement that historical fix again. Reduced motion still performs bounded scheduling, not perpetual scheduling.
- MarkdownContent, MarkdownInline and CodeBlock use memoization (`markdown.tsx:108`, `:136`; `code-block.tsx:17`). Stable string content avoids repeated parser/highlighter work, although wrapper reconciliation and growing current content remain targets.
- Terminal `requestRender` coalesces to one pending RAF (`surface.ts:1730`); cursor blinking is conditional on focus, terminal flags and reduced motion (`:1814`). Drawer unmounts after exit (`terminal-drawer.tsx:538`) and viewport teardown disposes the surface (`:325`). Hidden-terminal continuous rendering is not established here.
- Device WebGL selects `powerPreference: "low-power"`, disables mipmaps and caps DPR (`phone-viewer.ts:54`, `:66`, `:202`); demand rendering only continues while motion needs frames (`:126`). Disposal releases GPU resources and context (`:229`). DevicesPanel observes document visibility (`devices-panel.tsx:419`), while device stream creation is gated by active (`device-viewer.tsx:149`). Verify packaged minimize/occlusion separately rather than assuming an offscreen stream leak.
- Subagent elapsed-time timer is already restricted to active panel with active runs/handoff (`subagents-panel.tsx:256`). The live orb animates opacity during duplex with reduced-motion support (`styles.css:2468`), not a demonstrated always-on canvas loop.
- Dictation stop releases RAF, tracks and AudioContext (`pill-app.tsx:105`, `:119`).

Collect Chrome performance traces (scripting/style/layout/paint/compositing), React profiler for attribution, process-separated renderer/GPU/main CPU and memory, and OS energy/wakeup counters. GPU process CPU is not equivalent to GPU busy time. Report median and p95 over repeated equal-length runs; compare wall-clock energy under equivalent work. Screen recording and DevTools can perturb baselines, so collect instrumented attribution runs separately from clean energy runs.
