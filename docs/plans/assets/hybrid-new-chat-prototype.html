Hybrid new chat: interaction spec

⌘N still opens a draft instantly in the last workspace. The composer's top bar then shows only what applies to that folder: git controls appear only for git repos, and pull requests only once a branch has commits on a GitHub repo. After the first send it shrinks to the branch and PR, and for a plain folder it disappears.

1Instant by default

⌘N never asks. It opens a draft with the composer focused, in the workspace you're looking at.

2Each chip shows only when it applies

No branch chip for plain folders, no machine chip without paired Macs, and no PR chip until there's something to open as a PR.

3Nothing on disk until you send

Switching workspace or choosing a new worktree only edits the draft. Only Open folder, Clone and a Local branch checkout write to disk straight away, and each is a deliberate action.

4Summary, not gone

After the first send the bar shrinks to the branch and any PR. The workspace is already in the window header. Today the whole bar disappears, PR chip included.

Try it

Pick a workspace from the chip or the headline (try Notes, a plain folder), switch to a new worktree from the branch chip, type a message and press ↵. Then use Agent commits to see the PR chip appear. Each action is listed on the right with what it changed.

Inside the menus

Workspace menu

  • Opens with the search field focused. Lists up to 5 recent workspaces, ordered by latest chat activity, with relative times.
  • All workspaces (n) appears only when there are more than 5. When you type, the menu shows matches from all workspaces in one list.
  • Worktree workspaces are left out of this list. They appear in the branch menu under their repo, so the list stays short.
  • If what you type starts with /, ~ or ., a path row appears: Open ~/x if the folder exists, Create folder and open if only its parent exists, otherwise an inline error.
  • The actions are always at the bottom: Open folder… ⌘⇧O and Clone repository…, which turns the menu into a URL field with an editable destination. Clone runs only when you press Clone, shows progress in the menu, and selects the result.
  • Scratch chat is the last row (today's ~/aiden behaviour, renamed).
  • Choosing a workspace keeps your typed text, attachments and model, and puts focus back in the composer. The branch chip resets to that workspace's remembered mode.

Branch menu (git repos only)

  • The Work in group comes first, as radio rows: This checkout (current branch + changes), New worktree, and one row per existing worktree (shown only if there are any).
  • This checkout lists branches. Picking one checks it out now, as today. With uncommitted changes, other branches are disabled, with a note and a Use a new worktree instead button.
  • New worktree replaces the list with Start from (base branch radio). It adds Start from origin only if the repo has a remote, and shows Branch name: Auto, which you can edit. Nothing is created until you send.
  • The auto name is aiden/<slug of the first message>, with a number added if the name is taken. You no longer have to type a branch name before starting.
  • An existing worktree moves the draft to that worktree's workspace.
  • The mode is remembered per workspace and defaults to This checkout.

Flows

Quick start (most chats)

  1. ⌘N opens a draft in the workspace you're viewing. The composer is focused.
  2. The headline reads "What should we build in aiden-agent?", so you can see where the chat will run.
  3. Type and press ↵. The bar shrinks to a summary.
Extra clicks compared with today: 0

Wrong workspace

  1. Click the workspace name in the headline or the chip. The search field is focused.
  2. Type "lum" and press ↵.
  3. The draft moves to the new workspace and keeps your text. The draft row moves in the sidebar too.
Nothing is written to disk. Esc closes the menu and returns to the composer.

Start in a new worktree

  1. Open the branch chip and choose New worktree. The chip turns blue and reads "New worktree · from main".
  2. Optionally choose another base branch or edit the name.
  3. Send. Your message appears straight away, with a progress row (Fetching origin → Creating aiden/fix-login → Ready), then the agent starts.
  4. If it fails, the progress row offers Retry and Run in this checkout instead. Until it succeeds the chat stays a draft.
Replaces today's flow, which creates the worktree immediately and needs a typed branch name.

Use a folder that isn't a workspace yet

  1. Workspace menu → Open folder… ⌘⇧O, or paste ~/projects/website into search.
  2. The folder is added as a workspace and the draft moves to it.
  3. The branch chip appears only if the folder is a git repo.
Or Clone repository…: paste the URL, check the destination, press Clone, and it's selected when done.

Choose first

  1. ⌘⇧N, or the chevron beside New Agent in the sidebar, opens the New chat in… palette.
  2. Recent workspaces are listed first. Typing a path works as in the menu.
  3. ↵ starts a draft there. ⌥↵ starts a draft there with New worktree already selected.
Also: the hover + on any sidebar workspace row starts a draft there.

After the chat starts

  1. The bar shrinks to the branch (aiden/fix-login). The workspace is fixed and shown in the window header. For a plain folder the bar disappears.
  2. Once the agent commits on a GitHub repo, a purple Create PR chip appears in the summary.
  3. After the PR exists the chip reads #482 · Open, then Merged.
The setting that hides the bar today (autoHideComposerContext) would choose between the summary and fully hidden.

Edge cases, keyboard, accessibility

Edge cases

  • Folder missing: the workspace chip shows a warning badge. Sending is blocked, with "Locate…" or "Remove".
  • Repo with no commits: the branch chip reads "No commits yet" and New worktree is disabled.
  • Detached HEAD: the branch chip shows the short SHA. New worktree still works from any base.
  • The folder becomes a repo while the draft is open (for example, the agent runs git init in another chat): the branch chip appears on the next focus or refresh.
  • Paired Mac goes offline mid-draft: the machine chip shows Offline and sending is blocked. Switching to This Mac keeps the text.
  • @-mentions of files that don't exist in the new workspace get a soft warning chip after a switch.

Keyboard and accessibility

  • ⌘N new draft · ⌘⇧N New chat in… · ⌘⇧O open folder (⌘O is already Open in editor).
  • In menus: ↑↓ to move, ↵ to choose, Esc to close and go back to the composer. Focus is never lost.
  • Chips are buttons with aria-haspopup and labels like "Workspace: aiden-agent". Work in uses role=radiogroup.
  • New chips are announced politely ("Pull request available"), with no moving focus.
  • Neutral focus-visible rings on chips. The search field gets no accent ring, per the text-input rule.
