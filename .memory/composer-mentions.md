# Composer `@` mentions (UI SDK lessons, Unit 12)

2026-11-19. Plan: `docs/plans/ui-sdk-lessons-plan.md` row 12. Guide: `docs/design-guide.md` → Mentions.

- No `@` feature existed before. The file source is the Files panel's bounded index, `workspacesApi.files` (`workspaces:files`, 4,000 entries, depth 20, skips node_modules etc.; it needs folder access). `useWorkspaceFileIndex(workspaceId, enabled)` in `renderer/lib/queries.ts` reads it only while a mention is open (staleTime 30 s). No new IPC.
- Offered only when `surfaces.localContext`, the workspace has a folder, is not No workspace, and `permission !== "none"`. Remote chats get nothing. Chips reset when that workspace id changes.
- Pure rules in `renderer/lib/composer-mentions.ts`: `findMentionTrigger` (`@`/`＠` at start, after whitespace or `( [ { " '`; query is `[\p{L}\p{N}\p{M}_\-./~+]` up to 120; the token runs past a mid-word caret), `removeMentionTrigger` (also drops one doubled space), `rankMentionCandidates` (name = title + marks, path = keyword, symlinks that are not files skipped, 50 max), `formatMention` / `messageWithMentions` (`@path`, `@dir/`, `@"path with space"`, chips first then text).
- Why chips above the textarea, not inline tokens: the composer is a plain `Textarea` with dictation, restore-unsent, slash and edit-last logic all keyed on its string. Inline atomic tokens need a contenteditable editor (the reference `opp/ui` TokenInput uses U+FFFC offsets and a range rule) — a rewrite. A chip row like attachments is truly atomic for free: the caret never enters it, X or Backspace at offset 0 removes it whole. Trade-off: the mention loses its position in the sentence (it is sent first).
- Composer wiring (`composer.tsx`): `mentions` state next to attachments; `mentionTrigger` memo (null while slash, composing, dictation preview, a locked box, a range selection, or `mentionDismissedAt` matches); Escape via `useLayer(open, "popover", { onEscape })`; blur also dismisses, focus clears the dismissal, and deleting the `@` clears it. Keys: ↑/↓ wrap, plain Enter/Tab pick (`isComposingKey` skips). Send: `submit` builds `trimmed = messageWithMentions(mentions, text.trim())`; `draftText` stays the plain text. `sendComposerPayload({ mentions })` writes `@path` only into `markComposerSubmission` (reload recovery is text-only), clears the chips after the claim and, on failure, restores them as chips ahead of any new ones. Review fix: restoring them as `@path` text reopened the picker and the next Enter swapped the mention for the top match. No picker while `parseSubmittedSlashCommand(text)` matches (/btw, /visualize lose chips otherwise, and leave them for the next message); Enter is swallowed while the index `isLoading`; folders get a `path/` keyword. The legacy source-grep in `composer.test.tsx` for `markComposerSubmission(...)` was updated in place (not grown) and backed by a behavioral localStorage check in the mounted test. Mentions count as draft content (`canSend`, `data-message-draft`, ↑-to-fork, Esc-stops-reply).
- Not persisted: `saveComposerDraftText` stores text only, so chips are lost on a chat switch or reload. Copying the textarea never includes chips.
- Also fixed axe `label-content-name-mismatch` on `.composer-workspace-trigger`: names are now "<shown name>. Choose a workspace." / "<name>. Workspace unavailable: …" / "<name>. Open folder in file manager."; the exclusion is gone and the a11y ARIA snapshot uses a regex. Playwright `name:` matching is substring, so existing "Choose a workspace" locators still work; the Testing Library one in `composer-context-bar.test.tsx` became a regex.
- Tests: `renderer/lib/composer-mentions.test.ts` (pure), `renderer/components/composer-mentions.test.tsx` (mounted Composer, fake `workspaces:files`), one e2e in `tests/e2e/chat-shell-interactions.spec.ts`. `composer-attachments-mounted.test.tsx` stubs `../lib/queries`, so it gained a `useWorkspaceFileIndex` stub; any new queries hook the composer imports needs the same.
