## D4 (completion wakes, `chat` notice, Stop cascade)
- `AGENT_NOTICE_SOURCES` gains `"chat"` (card: MessagesSquare, "Started chat"). Phones see notices as one text line, no revision.
- `ChildChats` takes `onRunEnded`; `startTurn` follows each lead-started run via `streams.watch` until a terminal stream state (`childRunEnd`: done→done, cancelled→stopped, error→failed, interrupted). Approval/question waits are not terminal. `stop` marks the run told first. `ChatLinkRunEnd` gained "stopped".
- `completion-delivery.ts` `ChildChatCompletions`: `runEnded` (ignores a run that isn't `link.runId`, or already in `delivered`) sets `owed`, groups per lead for 10 s (`CHILD_COMPLETION_GROUP_MS`), `flush` re-checks `delivered` (wait dedupe), posts one `chat` notice (reply fenced, 4,000 chars) through `noticeDelivery`, wake unless the lead is quiet; marks delivered and clears owed unless dropped. `quietLead`/`resumeLead`.
- Wiring `child-chats-main.ts`: `childChatCompletions`, `leadChatStopped(chatId)` (quiet + `stopAll`, only if it has children), `leadChatResumed`. llm-client `cancel(..., "user_stop")` calls `leadChatStopped` (desktop and phone Stop); a person turn (not Aiden-started) in a chat with no `startedBy` calls `leadChatResumed`.
- Tests: `completion-delivery.test.ts` (real NoticeDelivery: queued, woke, budget → recorded, grouping, wait dedupe, quiet), child-chats tests for run-end reporting and stop-as-told, notice card/parse tests.

## Phase 5 review fixes (D4–D7)
- Start keys hash lead + tool-call id (`agent-chat:<sha256 32 hex>:<index>`), so Responses-API ids (`call|item`) and long ids fit the link KEY and Remote's 128-char idempotency format. `ChildChats.create` removes the chat (and `discardWorktree` the worktree) when a step after create fails. The worktree branch is seeded from the title (Remote caps that text at 4,000).
- `compileResultSchema` (and `isStorableResultSchema`) deep-scan every object node, data keywords (`enum`/`const`/`default`/`examples`) and map names included, and refuse any key `pattern`/`patternProperties` (a `propertyNames` pattern is caught inside it; a property literally named "pattern" is refused too); depth >64 fails closed. `$ref`/`$dynamicRef`/`$recursiveRef` only `#`, `#/$defs/<name>`, `#/definitions/<name>` (name `[A-Za-z0-9_.-]`), so no pointer can make ajv compile data as schema (Phase 5 loop-closing review: ReDoS via `#/default` etc.).
- `ChildChatCompletions.recoverOwed()` runs at startup (main/index.ts, after follow-through; `.catch` logs): owed endings post one record-only notice per lead, re-reading each link just before its lead's post (a resumed lead's `wait` may have told it); a lead with a group already gathering gets them added to it. `settle` clears `owed` only when delivered or dropped with `gone: true` (NoticeDelivery sets it only for `append` → `gone`); busy/error drops stay owed for the next start. Submitted results in notices cut at 4,000 chars.
- `stop()` marks told only after the cancel succeeded. Status lists skip reading replies. `follow` pushes `onChanged` on moves to/from needs-you; the renderer polls every 15 s only while a chat is `running`.
- Link store coalesces queued saves; only the newest 64 links keep `resultSchema`/`result`.

## Final integrated review fixes (schema cost, notice taint)
- result-schema.ts: ajv runs without `allErrors` (first error only). Before compiling (and in `isStorableResultSchema`) `schemaCost` sums every applied subschema with refs resolved and memoized: a ref cycle (including a root `$ref: "#"` and `$defs` that refer back) is refused ("refs must not loop"), as are >256 refs (`RESULT_SCHEMA_MAX_REFS`), cost >10,000 (`RESULT_SCHEMA_MAX_COST`; the `$defs` chain of `anyOf: [10 × $ref next]` blew ajv up exponentially even without allErrors), resource keys (`$id`, `$anchor`…) below the root, and `uniqueItems` unless `items.type` is scalar (non-scalar uniqueItems is quadratic: 2.8 s on 21k arrays).
- Notice taint (approval-gate/run-taint.ts): `messageBringsOutsideContent` = user message whose notice source is `chat` or `pull_request`, or whose content holds the `TRIGGER_EVENT_LABEL` ("What happened", renderer/shared/agent-notices.ts) data fence (a schedule notice with event text, or the task's own-chat prompt). Job/check/script output doesn't count. llm-client adds `runTaintHistoryOfMessages(generationChat.messages)` to the RunTaint history (whole chat, so later runs stay tainted; `leadRunTaint` follows). A notice admitted mid-run calls `generation.outsideInput()` (chat-run-input-admission.ts) → `runTaint.markOutside()`. `runTaintPersonText` strips data fences (`withoutDataFences`), so event-text sites aren't "named".
- Auto judge request: `ownerRequestText(messages, currentUser)` — on a notice-woken turn the last user message with no notice and not `fromLeadChat`, else ""; data fences stripped.
- Value-size bound (loop-closing review C): `checkResult` first walks the value iteratively (`resultSize`: values incl. object keys + chars/64; refuses >`RESULT_MAX_VALUES` 10,000 or depth >`RESULT_MAX_DEPTH` 64, before JSON.stringify), then 64 KB, then refuses when `compiled.cost × size > RESULT_CHECK_MAX_WORK` (1,000,000). `compileResultSchema` now returns `cost`. Reviewer shapes (items through a 16-way 3-level tree × 9k numbers; per-branch minLength × 64 KB string) are refused in ms.
