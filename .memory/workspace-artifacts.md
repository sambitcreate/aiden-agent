# Workspace artifacts (2026-10-19)

Built in PR #554 on `claude/project-thread-7xf9t3`. The user guide is `docs/workspace-artifacts.md`, and the decisions are in `docs/plans/workspace-artifacts-plan.md` ("As built").

Owner decisions:
- The launcher offers the Artifacts tab once the list loads, even before the first page (owner confirmed 2026-11-05; replaces the 2026-10-19 rule that it shows only once the workspace has a page).
- The workspace owns its pages, and the person deletes them from the tab or by asking Aiden.
- Access follows chat behavior.
- Desktop only (macOS and Linux) for v1: no CLI, Bots, Telegram, phones or Remote protocol change.

Invariants to keep:
- Main runs only commands saved with the artifact. The renderer sends an id, an action name, values and the page digest; main refuses a digest that changed.
- Under Ask, shell commands run only when `approvedDigest === workspaceArtifactDigest(sources, actions)`. File sources run under Ask without approval. None runs nothing.
- The tool's approval card records the digest per stream, and the tool consumes it.
- Action placeholders are standalone unquoted arguments, never the command itself, after a runner (eval/sudo/env/xargs, `RUNS_ARGUMENT`) or in an interpreter's code position (`CODE_ARGUMENTS`: `sh -c`, `python -c`, awk/sed program); text params never where bash reads names or arithmetic (`[[ ]]`, `(( ))`, let/read/declare/printf -v). The scan builds real shell words per top-level command (drops redirections, skips assignments and keywords), so the command name can't hide. A real-shell oracle test runs every accepted candidate with code-running values; extend it with each new bypass. The parser skips comments, tracks `$'…'`, refuses unbalanced quotes and any placeholder it didn't check. Values are bound to read-only `AIDEN_ARG_N` variables (not `set --`, which a template could reset), so the confirmed value is the one that runs. No leading `-`, no negative numbers, and no control or invisible characters.
- A shared refresh is keyed by digest, approval, permission and the resolved folder. A caller cancelling leaves the run going; the run aborts when the last caller leaves. Only the newest live run for a page saves, and results are never saved when the digest changed mid-run.
- The folder is re-verified with realpath before anything runs.
- The `aiden-artifacts` skill is a builtin in `main/services/workspace-artifacts/skill.ts`, not in `resources/aiden-help`, because the CLI copies that folder.
- Removing a workspace, including through the worktree path, removes its artifact files.

Tests: `npm run test:workspace-artifacts`. Each of the five build phases had an Opus medium review, and the blocking findings were fixed with behavioral tests.

## Build-and-check loop (2026-11-02)

Adopted from a review of DeepSeek Creator Mode's plugin skill (Notion: "DeepSeek Creator Mode → Aiden"). The skill teaches list, save a small working page, read the save result, fix, stop. It says not to make mock previews and not to test a button that changes something.

- Each create/update result now ends with a page check (`main/services/workspace-artifacts/check.ts`). It draws the page with the first refresh's data, mirroring `renderNode` in `aiden-ui-block.tsx` (If, Each, node budgets), and reports field reads that miss on every row, member reads on a list (including `.length`), `<Each>` over an object, unknown `$name`s, `run()` calls naming no action or passing the wrong number of values, and sources the page never reads. Reads rooted in a source that did not load, and rows of an empty list, are reported as not checked rather than passing.
- The evaluator gained an optional `scope.onRead` hook, set only by the check. If `renderNode` changes how it walks the tree, update the check's walker too.
- Check limits (after review): it is bounded (250 ms deadline, 10 findings, 3,000 chars) because it runs inside every save. Page-chosen names are JSON-quoted and only shown when they match `[\w$-]{1,40}`, so source data or markup can't inject text into the tool result. Guard reads (If/ternary tests, `!`, left of `&&`/`||`, `== null`) are collected statically and not flagged. Hidden If branches, render-budget cutoffs and time-outs are reported as not checked. Shared helpers moved to `renderer/shared/aiden-ui/props.ts` and the render budget to `AIDEN_UI_RENDER_BUDGET` so the renderer and the check can't drift.

## Agent run (2026-11-02)

- `workspace_artifact` gained `operation: "run"` (`id`, `action`, `args`). It calls the same `runner.runAction` the tab's buttons use, then refreshes and returns the refresh summary.
- Under Ask the card shows `preview: {kind: "command"}` with the resolved command; its digest is `runApprovalDigest(pageDigest, command)`, so an allowed card covers that exact command on that exact page. A save card's digest can't authorize a run. No card when there's no folder, permission is none, or the page's commands were never allowed (the call then refuses). Under Full it runs with no card; "only when asked" is skill guidance only.
- A failed command throws, so the chat shows the call as failed. The card label is "Artifact" and the timeline says "Run artifact action".
- `llm-client.ts` carries the card's preview through `artifactApprovalPreview` next to `artifactApprovalDigest`.
- Planned next: revision history with Restore (built 2026-11-03, below), a New page entry point (built 2026-11-03, below), then export/import (an imported page arrives with its approval cleared; built 2026-11-03, below).

## Revision history (2026-11-03)

- `store.replace` (through private `replaceWith`) keeps the version it replaced in `<workspaceId>.history.json`: its own `DataStore` (0600, compact, `preserveCorruptFile: false`, 24 MiB cap, injectable as `historyMaxBytes`). Entries are `WorkspaceArtifactRevisionV1` (`revision, savedAt, description?, visual, sources, actions, refresh`) and never carry `approvedDigest`. The normalizer validates each entry by rebuilding a full artifact and running `parseWorkspaceArtifactV1`, and drops bad entries and non-id keys.
- At most `WORKSPACE_ARTIFACT_LIMITS.history` (5) per page, sorted by revision. Before each write, `trimHistoryToFit` drops the oldest entries across pages (by `savedAt`) until the JSON fits, so history never fails for size. It measures the JSON once and subtracts each removed entry's bytes.
- History is written after the page write succeeds, except for `restore`, which writes the current version first and refuses the restore if that fails (a person restoring relies on undoing it; `replaceWith` still records afterwards, idempotent per revision, to catch an update landing in between). A failed history write goes to `onHistoryError` (main.ts logs it with `logger.error("workspace", …)`; store.ts can't import `platform.js` because tests load it without Electron) and never fails a plain replace. `create`, `rename`, `approve` and `saveState` record nothing. `delete` always drops the page's history inside `history.update` (a failure there goes to `onHistoryError` and the delete still returns `removed`); `removeWorkspace` removes the file.
- Races (2026-11-03 review): `recordRevision` runs inside the serialized history update, re-reads the live page ids, prunes entries for ids no longer live and skips a page that was deleted meanwhile. It throws a private `HistoryDetachedError` (writes nothing) when the workspace's page or history `DataStore` is no longer the current one. `removeWorkspace` detaches both stores, then awaits a barrier update on the old history store before removing the files, so an in-flight replace can't re-create `<ws>.history.json`. (An in-flight replace can still re-create `<ws>.json` itself: pre-existing, not addressed.)
- `restore(ws, id, revision, options)` replaces the page with the entry through `replaceWith`, keeping the current title (read inside the artifacts transaction), so the revision increments, the replaced version goes into history (restore is undoable) and approval follows replace's rule: inside the locked write, approved when `options.approvedDigest` equals the saved commands' digest, else kept when the previous `approvedDigest` equals it, else cleared. `WorkspaceArtifactWriteOptions.approvedDigest` (create, replace, restore) replaced the old `approved` boolean; the tool passes the shown card's digest straight through and the store compares it. A dropped revision throws "Revision N of this artifact is no longer kept."
- `history()` returns `WorkspaceArtifactRevisionSummary` newest first; `needsApproval` is `workspaceArtifactCommandsNeedApproval(entry.sources, entry.actions, digest(entry), current.approvedDigest)` (shared helper, the same predicate as the tool card), so it is true even while the current page itself waits. The panel shows it only under Ask with a folder, via `workspaceArtifactRevisionWaitsForApproval` in `renderer/lib/workspace-artifacts-view.ts`. `earlierRevisions(ws)` is the bulk read `list` uses. Revision numbers are checked by the shared `isWorkspaceArtifactRevision`.
- IPC `workspaces:artifacts:history` and `workspaces:artifacts:restore`; restore validates with `isWorkspaceArtifactRevision` and passes no write options, so the renderer can never approve through it.
- Tool `operation: "restore"` (`id`, `revision`). Under Ask a card like update's ("Restore revision N of the artifact …") appears when the restored commands exist and differ from `approvedDigest`; its digest is the restored commands' digest. `assertSourcesRunnable` applies. Create, update and restore share the `afterSave` tail (first refresh + page check). Timeline label "Restore artifact".
- Panel: **Earlier versions…** (lucide `History`) opens a dialog keyed by artifact id like rename/delete. After a restore it calls `refreshAtRevision(n)`; `useArtifactRefresh` re-reads once the view reaches revision n, if the page may run. The row buttons use `aria-disabled` rather than `disabled` while a restore runs. The dialog is keyed by artifact id (a restore running for another page shows nothing), forgets its list on close, and after a restore the header closes it only if it is still open on the restored page; `refreshAtRevision(artifactId, n)` names the restored page. Restore buttons look disabled through `aria-disabled:` classes locally: the shared `Button` was not taught `aria-disabled` styling because device-viewer and Model Pad rely on aria-disabled buttons staying hoverable for their reasons, and busy-send-button already dims its wrapper. In jsdom, a `waitFor` on any Radix dialog closing asynchronously spun forever; the tests settle with `act` + a short timeout instead.

## New page entry (2026-11-03)

- **New page…** is the empty state's accent button and, once there are pages, a `+` icon button (`aria-label="New page…"`) beside the title or switcher. It is not in the per-page Actions menu. `ArtifactsPanel` owns one `creating` state and one `NewArtifactPageDialog` (title "New page"), and remembers which opener was used for `returnFocus`.
- The dialog has a plain `Label` + `Input` ("What should it show?"), suggestion chips (shared `Button variant="muted" size="small"`, no borders, `aria-label="Use: <label>"`) and **Draft in chat**. The field is cleared on close. When drafting is unavailable the reason replaces the description and the confirm button gets `aria-describedby` to it (new `confirmDescribedBy` prop on the shared `Dialog`).
- Chips are `WORKSPACE_ARTIFACT_PAGE_IDEAS` (`{label, subject}`) in `renderer/lib/workspace-artifacts-view.ts`; a chip puts its subject (for example "this repository's open pull requests") in the field. `workspaceArtifactNewPageRequest` keeps the person's words verbatim apart from trimming, and adds "." only when the text doesn't already end in `.`, `?` or `!`. Unit tests: `renderer/lib/workspace-artifacts-view.test.ts`.
- `environment-panel.tsx` stages it with `stageComposerText(chatId, text, { notice: null })` into the active chat only when that chat belongs to the active workspace, and never calls `sendPromptToChat`. With no such chat it passes `newPageUnavailable`, and the confirm is disabled. "Ask Aiden to change this" also passes `notice: null`. `stageComposerText`'s optional `notice`: left out, a mounted composer says "A visual added a follow-up to your draft."; `null` says nothing.
- Focus: after a draft, `returnFocus` targets `focusRegionEntry("composer")` (`renderer/lib/focus-regions.ts`; `focusRegion` reuses it), falling back to the opener. Composers carry no chat id, so it can't be scoped to the target chat; it is the composer on screen.
- Reachability (owner confirmed 2026-11-05): the context exposes `artifactsOffered` (`loaded && workspaceId === activeId`), used by the launcher and the ⌘K "Open Artifacts" command (`chat-top-bar.tsx`); it was `views.length > 0`. The close-on-empty effect now records the workspace on a failed read too (keeping the previous count for the same workspace), so a tab opened on a failed read survives a Try again that finds no pages. It still closes on the last delete and on a switch to a workspace without pages.
- Without a folder or with access None, `assertSourcesRunnable` refuses sources and actions, so such pages can only carry `<Data>`; the user guide says so.
- The onboarding gallery tile ("Ask for a page you'll come back to…") was left as is; it doesn't contradict the flow.

## Export/import (2026-11-03)

- `main/services/workspace-artifacts/transfer.ts`: `workspaceArtifactPageFile` (export shape), `parseWorkspaceArtifactPageFile[Text]` (strict reader), `workspaceArtifactPageFileName`, `WorkspaceArtifactImports` (tokens). IPC `workspaces:artifacts:export`, `importPreview`, `importConfirm`, `importDiscard`. The handler takes injected `files` (save/open dialogs, `writeFile`, capped `readFile`) and `owner(event)`; production wiring is `workspaceArtifactFiles` in `main.ts` (`writeFileAtomic` 0600, `readRegularFile` after `realpath`) and `rendererDocumentOwner` → `${id}:${documentId}` in `handlers/index.ts`.
- Invariants:
  - The file never carries `approvedDigest`, ids, `workspaceId`, `createdByChatId`, revision, timestamps, snapshots or history. Unknown keys in an imported file (a smuggled `approvedDigest`, `id`) are ignored, never kept.
  - State: `WorkspaceArtifactV1.initialState` (and history entries) hold the state the markup declared, separate from `visual.state`. The tool sets it from `compiled.state` on create/update with markup and keeps the previous one when markup is omitted; `replace`/`restore` carry it; `saveState` never touches it and takes the revision the person was looking at; state from any other revision is dropped silently, in the store and in the renderer's `rememberState`. The panel keys `AidenUiBlock` by id and revision, so each revision starts from its own state. Export writes `visual.state = initialState` (never the saved state); import sets both `visual.state` and `initialState` from the file. No migration: a page saved before `initialState` existed exports no state.
  - Import reads with the strict shared parsers (`parseWorkspaceArtifactSources/Actions/Refresh/Description`, so placeholder rules apply), then `validateCompiledAum` (`renderer/shared/aiden-ui/validate.ts`, artifact actions on): it shares the compiler's tables (catalog kinds/required/children, `INLINE_ELEMENTS`, `AIDEN_UI_FUNCTIONS`/`AIDEN_UI_BINARY_OPERATORS`/`AIDEN_UI_NAME`, `RUN_ACTION_NAME`, `MAX_RUN_ARGUMENTS`, `RESERVED_DATA_NAMES`), refuses https-less literal `openUrl`, undeclared `setState`/bind keys, non-JSON `dataJson`, and rebuilds the tree with known keys only and fresh path keys. Then `parseChatUiVisualV1` and finally `parseWorkspaceArtifactV1` on a full candidate. Wrong format, a newer or odd version, non-JSON and files over `WORKSPACE_ARTIFACT_FILE_MAX_BYTES` (2 MiB) are refused with a message.
  - Invisible characters: `hasControlCharacter` refuses C0/C1, U+2028/2029 and `\p{Cf}`/`\p{Default_Ignorable_Code_Point}`/`\p{Bidi_Control}`, except the variation selector after an emoji/keycap base and ZWJ between emoji (`EMOJI_PARTS`), so "❤️" titles still save. Commands also refuse `\r` and 3+ consecutive newlines. `isWorkspaceArtifactTitle` applies it (one line), so stored titles with hidden characters are now unreadable (set aside) — pre-1.0, no migration.
  - File names: `workspaceArtifactPageFileName` = `safeExportFileName(title, { fallback: "Aiden page", extension: ".aiden-page.json" })` from `chat-export.ts`, base capped at 150 UTF-8 bytes. `durable-fs` `stagedPathFor` keeps at most 100 bytes of the target name, so a ~255-byte target still stages.
  - `WorkspaceArtifactFiles` and `readWorkspaceArtifactPageFile` (realpath + `readRegularFile`, so FIFOs fail with EFTYPE without blocking) live in `transfer.ts`.
  - Nothing is stored before `importConfirm`. The token is 24 random bytes (base64url), single use, bound to workspace + owner document, 5-minute TTL, at most 8 waiting (oldest evicted). A wrong workspace or window gets "no longer available" without consuming it. `importDiscard` is called on Cancel, on workspace switch and on unmount; expiry covers a missed discard.
  - `importConfirm` calls `store.create(ws, content, { uniqueTitle: true })` with no `approvedDigest`, so under Ask commands wait for Review/Allow; it notifies `created` (no `chatId`), and the renderer selects the returned id. `freeWorkspaceArtifactTitle` picks "Title (n)" within 80 chars inside the locked write.
  - Preview checks the per-workspace limit before opening the file dialog.
- Panel: Actions menu gains **Export page…** (`Download`) and **Import page…** (`Upload`) between Earlier versions and Delete; the empty state shows **Import page…** as a secondary button (also when New page is unavailable). No header button. The preview dialog is "Import “Title”?", reuses `ArtifactCommandList` (extracted from `ArtifactAccessNotice`'s Review list), lists file sources, and picks its lines with `workspaceArtifactImportAccess` (`renderer/lib/workspace-artifacts-view.ts`: `needs-approval | run | off | no-folder`). The dialog description is always Aiden's "Adds this page to {workspace}."; the file's description shows in the body as "The file describes it as: …". The preview carries `refresh` (when there are sources) and `shellSources`; under Full with shell sources refreshing on open the copy is "These run as soon as you import it[, then every N minutes]." and the confirm button is **Import and run**. File sources get their own access line (read as soon as the page opens under Ask/Full). Full access gets the warning fill. Import into a folderless workspace is allowed on purpose; nothing runs.
- No tool operation: export/import are person-only; the skill says so.
- Tests: `renderer/shared/aiden-ui/validate.test.ts` (every fixture passes unchanged; each refused case), `transfer.test.ts` (parse rules, titles, file name incl. 80 CJK chars, round trips via the tool for a stateful page and a wide page with `<Data>`, host read of symlink/FIFO/oversized, token cap), `store.test.ts` (`initialState` vs `saveState`, free title), `durable-fs.test.ts` (240-byte target), `main/handlers/workspace-artifacts.test.ts` (export content, round trip, tokens, smuggled approval, cancel/oversized/foreign files), `artifacts-panel.test.tsx` (preview per access level, confirm selects, cancel discards, export IPC).
