# Mobile link consent and draft privacy hardening (2026-10-27)

## W4

Public iOS/Android URL parsing never grants recording authority. `new-chat-voice` remains a navigation alias; new-chat ingress freezes installation, pairing creation identity, workspace and display names before a native confirmation. Approval is in memory, expires after 60 seconds and is consumed before asynchronous creation. Cancellation/revocation/changed identity and late responses cannot replay or publish a new action. No automatic mutation retry was added.

iOS App Intents are main-app-only and now foreground the app and hand one action to `AidenForegroundIntentRouter`, without URL flags, shared bearer tokens, network or Keychain access. The router retains a cold pending action until the view consumes it once. Android has no shipped internal voice producer; immutable notification PendingIntents and iOS widget/notification links continue to navigate to existing chats/Bots.

Current per-chat/new-chat model preference ownership from `.memory/mobile-model-preference-remediation.md` is preserved. No Remote wire revision changed.

Logs are `/tmp/aiden-security-mobile-{ios-build,ios-tests,android,ios-policy}.log`; final W4 result bundle is `/tmp/aiden-security-mobile-w4-commit-tests.xcresult`. Physical-device microphone indicators, permission combinations and OS cold App Intent launch acceptance remain unperformed.

## D3

Decision: editable drafts and unresolved-send records stay only on their original device and are excluded from backup. This is privacy hardening, not proof of historical upload or a policy violation. iOS `AidenChatDraftStore` marks an existing root during initialization, even without a subsequent write; every text, pending-send and partial-consumption rewrite prepares the excluded root before writing. Exclusion errors prevent new writes and retain readable existing content. Recreating storage reapplies the attribute. Complete-until-first-user-authentication protection is preserved. Android manifest/cloud/device-transfer exclusions are unchanged.

New filesystem tests cover existing-store migration without byte changes, pending-send-only storage, deletion/recreation and exclusion failure for every rewrite path. The dedicated protection test writes an independent system-protected control; this iOS simulator omits its Data Protection attribute, so only that protection test is explicitly skipped. Backup/resource tests are unconditional. Final simulator run: 58 passed, 0 failed, 1 hardware-property skip out of 59 on the same iPhone 18 Pro / iOS 27 destination, result `/tmp/aiden-security-mobile-d3-commit-tests.xcresult`. Generic iOS hardware build-for-testing and iOS release policy pass. Signed physical Data Protection verification and actual backup/restore acceptance remain unperformed. Two earlier new protection-oracle failures are retained in the failed result bundles and explained in `.papercuts/security-mobile-consent.md`; no production protection was removed or weakened.
