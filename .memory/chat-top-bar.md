# Compact chat top bar — 2026-10-08

Claude-desktop-style top bar (owner request). Keeps Aiden's radii (16px squircle `--radius-button`) and the 52px header height (traffic lights stay centred at `trafficLightPosition` y 20).

## Shape
- `Button variant="bar"` (ui.tsx): transparent at rest, `list-hover` on hover, `list-selection` while `aria-pressed`/`aria-expanded`. Used at `size="small"` (28px) for every window-header action: chat, Remote chat, Bot chat header, Environment/Quick View toggles, Open-in-editor picker. `variant="toolbar"` (glass) remains only for floating actions (bot message actions).
- Leading cluster: `SplitView.SidebarToggle` now portals the toggle plus its `children` into the leading anchor (90px on macOS, 12px elsewhere since 2026-11-01; see `.memory/linux-window-controls.md`); chat and Settings sidebars pass `<HistoryNavButtons/>` (Go back / Go forward over the router's memory history; availability from `location.state.__TSR_index` vs `history.length`; `aria-disabled` so focus survives reaching the end). TanStack history skips `useBlocker` guards on BACK/FORWARD, so `renderer/lib/guarded-history.ts` wraps the router's memory history (router.tsx): it records entry locations and runs blockers before traversing (protects the Images `LeaveGuard`, and Settings' "Back to app"). The Files editor and Git operations are guarded by action checks, not registered blockers, so `HistoryNavButtons` also refuses traversal (toast, same wording as the sidebar) while `editorState.dirty`/`saving` or `gitOperationBusy` — Pullfrog P1 on #425: Forward into Settings unmounted the Files editor and dropped unsaved text. The toggle keeps `aria-pressed` but suppresses the pressed fill. Collapsed headers pad by `useSplitViewCollapsedHeaderInset()` (190 on macOS, 142 with Aiden's Linux title bar, 112 with the system one; was the `SPLIT_VIEW_COLLAPSED_HEADER_INSET` constant), shared by `ScrollArea` and `StudioSurface`. No keyboard shortcuts for back/forward yet (Cmd+[ conflicts with editor outdent; would need registry commands).
- `ScrollArea` gained `titleAccessory` (rendered after the `h1`, outside it).
- `renderer/components/chat-top-bar.tsx`: `ChatTitleMenu` (Rename…, Duplicate chat → `copyChat()`, Copy title; drafts show plain text), `WorkspaceChip` (name + menu: path, branch or "Not a Git repository"/"No folder", Show in Finder, Open in terminal, Open on GitHub, copy path/branch), `WorkspaceToolButtons` (Quick View first | Terminal, Changes, Browser, Device, Files | Open in editor, ⋯ with Context/Subagents | Environment toggle last; Quick View and Environment ride the `leading` and `end` slots so they stay visible when the tools fold into ⋯ — see `.memory/quick-view-cards.md`).
- Non-Git safety: Changes hidden unless `git.isRepo` and access is not `none` (a cached repo read must not outlive access being turned off); Files hidden without a folder and disabled when permission is `none`; branch/GitHub items only for readable repos. With access off the chip says "Workspace access is off" (Git reads report not-a-repo without access) and drops Finder/terminal/GitHub. A folder-less workspace gets a static chip, not an empty menu. A chat with no workspace gets no tool buttons and no ⋯ menu.
- Title menu trigger is the shared `Button variant="bar"`; its accessible name is the visible title (an `aria-label` would rename the `h1`), and it uses an inset focus ring (`--keyboard-focus-offset: -2px`) because the `h1` clips overflow for the ellipsis. Rename goes through the pane's `renameChat` (chat control); Duplicate is disabled with `forkDisabledReason`.
- Tool pressed state uses context `toolsPresented` (tools open and not hidden behind a stacked Quick View; the workbench reports `stacked` through `reportSurfaceLayout`). GitHub link only for `github.com/owner/name` canonical keys (`renderer/lib/workspace-chip.ts`); repository identity is read lazily when the chip menu opens. Opening the chip menu invalidates `queryKeys.git(id)` so a fresh `git init`/branch switch shows without the 60s poll.
- Tool buttons fold into ⋯ when the header's content box (after the collapsed inset) is < 680px; the chip hides at ≤560px via the `chat-toolbar` container query (also content-box); the `h1` keeps `min-w-24` when an accessory is present.
- Back into an empty draft whose view closed (Settings, another page, another chat) reopens it blank at the same id: `chat-draft.ts` remembers the last 32 such drafts and the `/chat/$chatId` route's `beforeLoad` calls `reopenClosedChatDraft`. Drafts that were sending, sent, or discarded on purpose are not remembered. Back into a deleted chat still shows the "This chat is no longer available" pane (no auto-redirect, to avoid racing draft promotion).
- Floating Environment panel now always starts at `top-14` (was `top-3` when there was room) so it never covers the top bar, matching Quick View.

# Composer context bar chips — 2026-10-15 (hybrid new-chat plan, Phase 1)
- `renderer/lib/composer-context-chips.ts` (`composerContextChips`) decides the composer strip: drafts get the full bar (workspace, machine picker only when a paired Mac is offered — the static "Local" label is gone, branch for readable repos with a warning-fill change count). After the first user message with `autoHideComposerContext` on (default) the bar is a shorter `summary` (branch + PR chip) for git repos and `hidden` otherwise; with it off the full bar stays. `ComposerContextBar` takes `mode` and `data-mode`; `data-collapsed` still means hidden.
- PR chip only on started chats in a readable repo with a remote whose host is not a known non-GitHub forge (`remoteCanHostPullRequests`: github.com, *.ghe.com and unknown/self-hosted hosts qualify; gitlab.com, bitbucket.org, codeberg.org, Azure DevOps, sr.ht etc. do not), AND linked/pending/current PR or `branchCanOpenPullRequest` (a named non-default branch, pushed or not — no cheap ahead-of-base count; without origin/HEAD, main/master count as default). It is the only place to link an existing PR, so it must stay reachable. The PR reads (`useComposerContextChips`) are skipped otherwise, so drafts and plain folders read no PR state. "<label> available" is announced only on a false→true transition after the chat's PR reads had settled.
- No Appearance control exists for `autoHideComposerContext` (only settings:set); the plan's Summary/Hidden choice is not built.
- Focus returns to the composer input only if it was inside the strip just before the update (`StripFocusKeeper.getSnapshotBeforeUpdate`) and that chip left or the strip hid; focus dropped on <body> by clicking transcript text is left alone. The closed branch trigger uses the live Git status count (the menu's branches query is not refreshed while closed).
- Tests: `renderer/lib/composer-context-chips.test.ts` (truth table), `renderer/components/composer-context-bar.test.tsx` (real Composer, happy-dom), `tests/e2e/chat-top-bar.spec.ts` plain-folder and Git cases.
