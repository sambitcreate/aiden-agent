# Bot browser and credential boundary — 2026-10-21

Plan: `docs/plans/bot-handoffs-rules-computers-plan.md` §5.1 (package P6). Branch `wp/p6-browser`, on top of P1 (hand-offs), P3 (rules) and P4. User doc: `docs/environment-browser.md` "A Bot's own browser".

## Profile and workspace
- `main/services/browser/bot-profile.ts`: profile id `bot:<botId>` (a real id gives `bot:bot:<uuid>`), partition `persist:aiden-bot-<botDirectoryName>`. `botDirectoryName` validates the id.
- `bot-workspaces.ts`: main-only registry from a Bot's managed workspace to its Bot. Registered by `bot-browser-tools.ts` `candidates()` and by `botBrowserWorkspace()` (the panel's `bots:browser:workspace`). Renderer input never registers one.
- `service.ts`:
  - `create` forces the Bot profile for a Bot workspace; any other workspace asking for a `bot:` profile is refused. `close()` never resolves `this.profile()` for Bot ids.
  - `runCommand` admits registered Bot workspaces. An agent command on a Bot workspace must carry `credentialBoundary`, and a boundary command must be an agent command on a Bot workspace.
  - Boundary refusals: `evaluate`, `record_*`, `open_file`, annotation actions, `screenshot`, `devtools`; any `selector`/`locator` probing `value` (`assertBoundarySelector`). `import_cookies` into a Bot profile is refused for everyone.
  - `hold` / `release` (by hold id) set `BrowserTab.heldForPerson {reason}`; agent commands on a held tab throw `BROWSER_HELD_TAB_REFUSED`.
  - `transferOwner`, `hasOwner`, `probeAgentTarget`, `closeBotTabs`, `clearBotProfile`, `agentAccessDefaultAllowed`. `BrowserCommandContext` is exported.
- `files.ts` refuses Bot workspaces (403).
- `main/handlers/browser.ts` `browser:get-state`: a Bot workspace moves ownership to the asking document (`transferOwner`), so the window showing the Bot owns its browser.

## Credential boundary (`credential-fields.ts`, `credential-mask.ts`, `credential-boundary.ts`)
- Sensitive: `input[type=password]`, autocomplete `current-password`, `new-password`, `one-time-code`, `cc-*` (section-, shipping, billing, home, work … prefixes ignored). The walker reads `DOM.getDocument({depth:-1, pierce:true})` through `CdpPort.call` (renamed from `send` so the IPC contract test doesn't read `port.send("DOM.…")` as a notification).
- Text: `scrubBrowserSnapshot(snapshot, reach)` drops a sensitive field's AX value and its subtree; the element entry keeps label and placeholder. Since the role-name fix below it also blanks names, descriptions and values that could include a field's content (`reach` from `scanSensitiveFieldReach`).
- Image: boxes read before and after capture, union painted gray (0x8a) in main, then `redactBrowserData`. The image is dropped with a `BROWSER_IMAGE_OMITTED` note when a **visible** opaque frame (cross-site iframe; OOPIF masking is not supported), pinch zoom, a navigation or a scroll change happened.
- Selectors: `assertBoundarySelector` refuses CSS/Playwright `[value…]` (checked as written and with CSS comments removed), backslash escapes and, since the text-oracle fix below, all XPath (it replaced the XPath attribute-step rules), in main and in `bot-browser-approval.ts` before the probe runs the selector. The Chromium oracle test in `credential-fields.test.ts` proves each refused form really distinguishes a value.
- Text oracle (review of #559, 2026-10-21): XPath string tests (`starts-with(.,'4111')` on a `cc-number` textarea or any ancestor), every text engine (`text=`, `internal:text`, `:has-text`, `:text*`, `internal:has-text`/`has-not-text`) and `internal:label` (label text includes the textarea's child text) told a protected field's text apart, so `browser_wait_for` (no approval) could read it by prefix. Fix: `assertBoundarySelector` refuses all XPath (`BROWSER_XPATH_SELECTOR_REFUSED`; `xpath=`, or `//`/`..` at the start, after `>>` or after `"`); the old XPath attribute-step rules are gone. A boundary command's locator resolves through `browserBoundaryLocatorExpression` (`service.ts` `target(tab, command, boundary)`, threaded through `elementPoint`, `wait`, `type`, `scroll`, and always for `probeAgentTarget`): Playwright's own `parseSelector` refuses XPath anywhere (nested `internal:has="//…"` too), then `__aidenPlaywright._evaluator._cacheText` is seeded inside `evaluator.begin()`/`end()` with empty text for every sensitive field and everything inside it (light, shadow), so all text engines and the label engine see none of it; a missing cache fails closed (`BROWSER_LOCATOR_UNCHECKED_REFUSED`). More than one match throws its own `strict mode violation: this locator matches N elements…` (Playwright's previews quote attributes and up to 50 chars of text). `boundaryRefusalOf` knows the new sentences, and `elementPoint`/`wait` rethrow them at once instead of retrying to a timeout. Tests: Chromium oracle in `credential-fields.test.ts` (isolated world, bundled runtime), e2e step "2 text locators".
- Role names (second round of the #559 text-oracle review, 2026-10-21): Playwright's accname reads an embedded textbox's live `.value` (a password's too) into the name of a cell, row, checkbox label, button or `aria-labelledby` target around it, and the `role`/`internal:role` engines compute names themselves (not through `_cacheText`), so `internal:role=cell[name=/^hunt/]`, `row[name=/Password h/]`, `checkbox[name=/Save 5555/]` and `form >> internal:has="internal:role=cell[…]"` read it by prefix, as did `generateSelectorSimple` (`internal:role=button[name="4444…"]`), Chromium's AX tree (cell names, superseded sources, `relatedNodes[].text`; a password cell shows its bullets, so its length) and the rules' probe name. Fix:
  - `credential-boundary.ts` splits the page code into `BROWSER_BOUNDARY_NAME_SOURCE` (`__aidenNameReadsField(e, body)`, `__aidenBoundaryName(e)`) and `BROWSER_BOUNDARY_SCOPE_SOURCE` (`__aidenBoundaryScope(run)`): inside `evaluator.begin()` it clears every `_cache*` Map, seeds blank text, and swaps `_engines` `role`/`internal:role` for wrappers that drop matches whose name (body mentions `name`) or description could read a field; restored in `finally`. Missing cache, begin/end or either role engine → `BROWSER_LOCATOR_UNCHECKED_REFUSED`. Reach is structural and over-approximates: children, shadow roots, slot assigned elements, `aria-owns`, `aria-labelledby`, `.labels`, followed transitively (budget 20000, exhausted = reads); a field's own label doesn't count unless reached through its `aria-labelledby` (Playwright includes self's value there; Chrome doesn't); an element named by its own non-empty `aria-label` with no `aria-labelledby` attribute keeps its name; elements inside a field and non-native sensitive fields (contenteditable) never match by name.
  - Snapshot locators: `browserBoundarySelectorsExpression("globalThis.__aidenElements")` runs `generateSelectorSimple` inside the scope (it verifies candidates by querying, so it never picks a value-dependent one); fallback `noText`+`omitInternalEngines` CSS when the scope throws. Preserved selectors come only from `annotation_preview`, which a Bot can't run.
  - AX tree: `credential-fields.ts` `sensitiveFieldReach(root, sensitive)` (one DFS over the pierced DOM: reverse edges for parent→child incl. shadow/contentDocument/pseudo, labelledby/owns refs, `label for`, ancestor labels, slot→host children) gives `known`, `inside`, `reads` (node → fields it reaches), `holds` (ancestors), `describedBy`, `selfNamed`. `scrubAxName` keeps a name whose winning source (first non-superseded with a value) is a static attribute (not `aria-labelledby`) or placeholder; a `relatedElement` source is blanked if a linked node reads a field other than self; anything else is blanked if the node reads another field or is a non-native field. Blank = `{type, value: ""}`; a kept involved name keeps only its winning source. Descriptions blanked by `describedBy` reach; values dropped from nodes holding another field; `relatedNodes[].text` dropped where the related node reads a field; nodes in `inside` or unknown to the DOM read are dropped with their subtree. The DOM is read after the AX tree (`scanSensitiveFieldReach` in `service.ts` snapshot), so a node added in between is unknown and dropped.
  - Rules' probe: `probeAgentTarget` takes its name from `__aidenBoundaryName`, so the classifier (and the docs' "never field values") holds.
  - Hit-target errors: with the boundary on, `elementPoint` throws `BROWSER_COVERED_TARGET` and the click interceptor `BROWSER_COVERED_OR_MOVED_TARGET` (Playwright's `hitTargetDescription` previewed a covering card field's `value=` attribute). Not added to `boundaryRefusalOf`, so retries keep running.
  - Main's `XPATH_SELECTOR` quote case is narrowed to nested-engine bodies (`internal:has|has-not|and|or|chain`, `left-of`… `="`), so `text="//comment"`, `a[href^="//cdn…"]` and `:has-text("...more")` pass; the page parser still refuses nested XPath exactly.
  - Tests: `credential-fields.test.ts` "Chromium: a Bot's locator can't tell…" (role pairs on live `page.fill` values: table rows with password, one-time-code and cc-number inputs, a checkbox label wrapping a cc input, button name/description; ordinary names still resolve; generated selectors) and "Chromium: a Bot's snapshot names no element with what a field holds…" (real CDP AX tree); e2e step 2 `/card-table` (`roleLocators`, `tableSeen` incl. `probed`) and `/covered`. Mutation-checked: removing the role wrapper, the scope around generation, `scrubAxName` or `__aidenBoundaryName` each fails a test.
- Third round of the #559 review (2026-10-21, cherry-picked onto `claude/project-thread-oredvh`):
  - Remembered fields before every Bot locator: `__aidenSensitive` only knows a remembered field (a password shown as text) once `recallSensitiveFields(tab, signal)` (mark=true) marked it in the isolated world. It ran before type, press and the probe only, so `wait` (`internal:role=row[name=/Password hunt/]`, no approval), `elementPoint` (scroll's target) and the snapshot's generated locators (`internal:role=button[name="hunter2xyz"i]` for a `role=button` around a toggled field) read it. Now also called once before `wait`'s loop (with a target), at the start of `elementPoint` (not for a `ref`), and before the snapshot's evaluation when `credentialBoundary`. The held-tab watcher still uses mark=false. Left open: a field that is still a password field at that read and is toggled during the same call (one `wait` of up to 60 s) isn't marked for that call; the next call marks it.
  - State pseudo-classes: `STATE_PSEUDO_CLASS` in `assertBoundarySelector` (`BROWSER_STATE_SELECTOR_REFUSED`, as written and comments removed, anywhere in the string, so inside `:has()`/`:is()`/`:not()` and nested engine bodies too): `:checked`, `:default`, `:indeterminate`, `:placeholder-shown`, `:empty`, `:blank`, `:valid`, `:invalid`, `:user-valid`, `:user-invalid`, `:in-range`, `:out-of-range`, `:autofill`/`:-webkit-autofill`/`:-internal-autofill*`, `:dir(` (dir=auto takes direction from the value), `:state(` (custom element states). Allowed: `:required`, `:optional`, `:read-write`, `:enabled`, `:focus`, `:visible`, role `[checked]`/`[selected]` (options inside a sensitive select never match a role locator anyway). False positive accepted: text like `text=Status:valid` (no space) is refused. Chromium oracle in "every selector that can tell a field's value or state apart…" (each refused state flips between an empty and a filled form; allowed states don't).
  - Role filter scope: `BROWSER_BOUNDARY_AUTHOR_NAMED_ROLES` (exported) lists roles Playwright 1.62.1 never names from the target's own content (`allowsNameFromContent` is true only for button, cell, checkbox, columnheader, gridcell, heading, link, menuitem*, option, radio, row, rowheader, switch, tab, tooltip, treeitem, plus `<summary>`). For those, `own(c)` follows only legend/caption/figcaption/title children (Playwright's native alternatives); labelledby, `.labels` and `aria-owns` are still followed, and everything below whatever is followed. A deny list, so a role a newer runtime names from content is still followed. Premise test: Playwright's name of a `div[role=X]` holding text and a filled input never includes either, for every listed role. Also the role wrapper is skipped when `hide()` found no sensitive or recalled field, so a large field-free page no longer hits the 20000 budget (`internal:role=row[name=/Order 42/]` over 25000 spans).
  - Unknown engines: `__aidenBoundaryScope` refuses (`BROWSER_LOCATOR_UNCHECKED_REFUSED`) unless every key of `__aidenPlaywright._engines` is in `BOUNDARY_SELECTOR_ENGINES` and every key of `_evaluator._engines` in `BOUNDARY_CSS_FUNCTIONS` (both copied from the vendored runtime; update them with a Playwright upgrade after checking what a new engine reads). Test adds a fake `value=` engine that reads `.value`.
  - Tests: unit lists in `credential-boundary.test.ts`; Chromium cases in `credential-fields.test.ts` (containers `dialog[name=Billing]`, `group[name=Card details]`, `dialog >> button`; legend holding a field still read: `group[name=/Expiry 1229/]`); approval refusal in `bot-browser-tools.test.ts`; e2e step "5 remembered fields and locators" (`/reveal-table`, three fresh documents: wait, scroll with `AbortSignal.timeout(800)` since scroll ignores `timeoutMs`, snapshot). All failed on the pre-fix code.
- `scrubBrowserSnapshot` also replaces a sensitive element's text-engine selector (`internal:text="…"`, which Playwright generates for a textarea with content) with a structural one.
- Held tabs: `Network.responseReceived` and `console-message` are not recorded while `tab.hold` is set, so a released tab's snapshot never replays the person's sign-in (e2e `heldTraces`).
- Field memory (H3, 2026-10-21): `SensitiveFieldMemory` (`credential-fields.ts`) per `LiveTab` keeps backend node ids of fields any scan saw as sensitive, keyed by `wc.getProcessId()` (ids are unique and never reused within a renderer process; 512 ids x 4 processes, newest kept). `scanCredentialTree(root, remembered)` treats them as sensitive (`recalled` = sensitive only by memory). Fed by the snapshot scans, `recallSensitiveFields` before Bot type/press/probe and, since the third #559 round, before any Bot locator runs (wait, elementPoint, the snapshot's generated locators) (which marks recalled fields in the isolated world with `BROWSER_RECALL_FIELD_FUNCTION` -> `__aidenRecalledFields` WeakSet; `__aidenSensitive` = `__aidenSensitiveNow` || recalled; the probe reports a recalled field's `type` as `password`), and `watchHeldFields`: a held tab is read every max(500 ms, 20x the last read) until released or closed. The 4-process cap is safe only because Electron 43 doesn't restore pages from the back/forward cache (H3 review probe: Back gives a new document in a new process, and form restoration never refills a `type=password` input), so a forgotten process can't bring a revealed field back; revisit the cap if bfcache is ever enabled. e2e step 5 "show password" in `bot-browser-native.ts`: each path's own recall is checked on a document nothing has marked yet (the isolated-world WeakSet persists for the document, so a later check would pass on an earlier one's mark): the probe before the Bot's typing on the Bot-shown field, and a printable press into the focused field first after the person's release; the person's toggle there is page-timed (`/reveal?show=2000`) because a `source:"user"` click command on the held tab didn't toggle in Electron (not investigated: the person's real clicks are native input, not commands).
- Typing guard: `browserTypingGuardSource` refuses a sensitive named target and a sensitive or opaque focused target (through shadow roots and same-origin frames); `browser_press` of a printable key (`browserKeyInsertsText`) runs the same guard. Page-world errors come back with the page stack; `boundaryRefusalOf` turns them into the bare sentence.
