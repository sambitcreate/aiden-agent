# iOS Home header and compact dock (concepts 01/02)

Branch `claude/ios-home-chrome`, stacked on `claude/ios-home-aurora` (#931). Owner decision 2026-11-25: custom Home header and an icon-only dock at compact width; regular width keeps the system `.sidebarAdaptable` sidebar. Plan: `docs/plans/ios-new-direction-upgrade-plan.md` Phase 2 "Home header and dock".

## Where it lives
- `Features/Shell/AidenDock.swift`: `AidenTabChrome` (`resolve(besideList:)`, `besideList(horizontal:vertical:)`, `keyboardTakesBottomEdge(keyboard:screen:window:)`, `showsDock(besideList:showsConversation:keyboardIsUp:)`), `AidenAppTab.title/dockSymbol/accessibilityCount(needsYou:)`, `AidenDock`, `AidenChromeIconButtonStyle` (Home header's round glass button).
- `AidenAppShellView`: `splitTab` hands `AidenListTab` a `dock: (AidenAppRoute?) -> AnyView`; `AidenListTab.stack` puts `.toolbar(.hidden, for: .tabBar)` + `.safeAreaBar(edge: .bottom)` + `.aidenComposerSoftScrollEdge()` on the root and on every `navigationDestination` screen. `dockBar(under:)` returns the running accessory (when `runningHome == .accessory`) above `AidenDock`, or nothing in a conversation / with the keyboard up. Home header: `homeHeaderBar` in a top `safeAreaBar` on `chatsList`, nav bar hidden at the Chats root in the dock layout.
- Dock recents (2026-11-26): `AidenDockRecents.swift` (pure model: `AidenDockRecent`, `AidenDockRecentsList`, `AidenDockRecents.chats/bots/workspaces/inbox`, cap 4, running first then newest, ties by host-scoped id) and `AidenDockRecentsPopover.swift` (`AidenDockHost`, the cover, the card, and the shell-side `AidenDockRecents.list(for:store:isArchived:canStart:)` / `start(_:with:)`). `dockBar(under:)` builds `AidenDockHost` with closures; `isAtRoot` is `route == nil`. Tests: `AidenDockRecentsTests`, `AidenDockRecentsUITests`.
- `AidenDock` is concept 02's dock: no glass capsule, bare line icons, one pill (`matchedGeometryEffect`) with the chosen tab's name. It is `Equatable` on `selection`, `needsYouCount`, `chosenTabHint` and used with `.equatable()`.
- `AidenAppNavigation.selectFromDock(_:)`: select, or pop to root on reselect. The host calls it for every tap except the chosen tab at its root, which opens the recents. `aidenUsesDock` environment entry (`AidenMachineChrome.swift`).
- `AidenRunningAccessory`: `isInBar`; the host is a glass capsule; no more `tabViewBottomAccessory`, so no iOS 26.1 gate: `AidenRunningHome.resolve(_ chrome:)` is `.accessory` with the dock, `.inboxRow` beside the list.

## Rules (review round 1, 2026-11-25)
- Landscape: `besideList = horizontal == .regular && vertical != .compact`. A Plus/Pro Max sideways (regular/compact) keeps the stack and dock; iPad and open Duo (regular/regular) keep the split. `AidenListTab` passes the same rule as `widthIsRegular` to `setPath`, so the laid-out guard agrees.
- Keyboard: `keyboardWillChangeFrame` + `keyboardTakesBottomEdge(keyboard:screen:window:)`: the on-screen part of the keyboard must reach the screen bottom, span the full screen width, be at least 120 pt tall, and cover the bottom of the shell's own window (`AidenWindowReader` converts the `UIWindow` bounds into the screen space). Floating keyboards, the hardware shortcut bar, and a keyboard beside a Slide Over or Stage Manager window leave the dock.
- `@ScaledMetric` reads the environment above the dock's `.dynamicTypeSize(...xxxLarge)` clamp, so the icon sizes are capped by hand (dock 27, header 24).
- Reselect at a tab's root does not scroll to top yet (deferred: needs a scroll hook across the four list containers alongside `AidenListScrollKeeper`).

## Push/reveal drawer (concept 03, 2026-11-25)
- Owner: "the whole view shifts to the right and shows the drawer underneath". Compact width only (`drawerPushesContent = !navigation.besideList`, so the closed Duo pushes too); beside the list it stays an overlay with a scrim.
- Still a clear `fullScreenCover` (modality and VoiceOver). The shared `@Observable AidenDrawerReveal.progress` (0...1) drives both `AidenDrawerPush` on the TabView (offset by `travel * progress`, continuous corner radius 40 while moved) and the cover, which masks the drawer to the revealed width and puts a clear **Close menu** button (`aiden.drawer.close`, `.cancelAction`) over the slice.
- Geometry is pure in `AidenDrawerGeometry` (`AidenDrawerModel.swift`), unit-tested in `AidenShellIATests`. `AidenDrawerEdgeSwipe` reports began/changed/ended in window space; the shell's `beginDrawerSwipe` puts the cover up at progress 0 and tracks.
- Close always animates progress to 0 first, then sets `drawerIsOpen = false` in `settle`'s completion (guarded by a settle id). External closes (`navigation.dismissDrawer`) are caught by `.onChange(of: drawerIsOpen)` and slide back.
- UI test `testOpeningTheDrawerSlidesHomeAsideAndTheSliceClosesIt` checks the menu button's frame moves past half the window and the slice tap restores it (it waits for Home to settle: the closed Duo is still sliding when the slice appears).
- Sideways (phones keep the stack in landscape, Pro Max too) the drawer column starts at the safe leading inset, so Home travels column + inset (`AidenDrawerGeometry.travel`, `AidenDrawerReveal.travel`) and the column is sized from the usable width. Before this the drawer's compose sat under Home's slice. Note: a fixed-width mask/overlay child with `.ignoresSafeArea()` lays out from the screen's x=0, not the safe edge. Covered by `testSidewaysTheDrawerStartsPastTheCameraAndHomeMovesPastBoth` (unit) and `testSidewaysHomeMovesClearOfTheWholeDrawer` (UI). Right-to-left mirrors correctly; Reduce Motion crossfades over a still, dimmed Home.
- Closed Duo: the cover screen keeps a trailing system rail the TabView's safe area doesn't report (TabView ≈383 pt vs the cover's 466 pt), so travel measured on the TabView was short and the drawer hid Home's leading edge. `AidenDrawerReveal.travel` now prefers the drawer cover's own measurement (`drawerSpace`, set by `AidenDrawerOverlay`, cleared on disappear) over the screen's (`screenSpace`). The closed Duo's cover screen doesn't rotate, so the sideways UI test skips there.

## Gotchas
- A `safeAreaInset`/`safeAreaBar` outside a `NavigationStack` doesn't reach the list inside it; the dock must be each screen's own bar.
- The closed Duo draws a hard scroll edge under a bottom bar unless `.scrollEdgeEffectStyle(.soft, ...)` (via `aidenComposerSoftScrollEdge()`).
- Inside an `.isTabBar` container the children become tabs and their AXValue is the selection (1/0), so `accessibilityValue` is lost: the Inbox count goes in the label (`accessibilityName(of:)`), with `accessibilityInputLabels` the bare name.
- Closed Duo: hiding the tab bar leaves the system rail (status bar plus the nav bar's items at the trailing edge, no TabBar element). UI tests detect the rail by posture (`showsSideRail`: a non-Home "Open menu" outside every navigation bar), the dock by `aiden.dock` / `aiden.dock.<tab>` (`AidenStateMatrix.dock/dockTab/bottomTabs`).
- UI tests wait for Chats' root with `AidenStateMatrix.homeRoot` (`aiden.home.menu`, or the Chats nav bar beside the list) and `tabRoot(_:)`; `navigationBars["Chats"]` does not exist at compact width.
- The recents are a transparent `fullScreenCover` with animations disabled (the drawer's pattern), so the page is inert under them. The real dock is under the cover; a copy is drawn at its measured global frame (`onGeometryChange`, kept in a non-observed box) with the same identifiers, and the real one is `accessibilityHidden` meanwhile. The footer's action runs in the cover's `onDismiss`, because the compose flow's sheet can't present while the cover is still up.
- `AidenStateMatrix.openArea` no longer taps a dock tab that is chosen and at its root: that tap opens the recents. Tests that want the recents tap `dockTab` directly.
- The dock no longer minimizes on scroll (the old `testTheTabBarMinimizesOnScrollDownAndComesBack` became `testTheDockStaysInReachWhileTheListScrollsUnderIt`).
- The accessibility audit (`testEveryMainScreenPassesTheAudit`) counts the dock as a bar running from its capsule's top to the window's bottom edge, full width (`AuditFinding.dock`). Rows that scroll under it are bars-touching, and its chosen tab's name has its own allowance (Dynamic Type, one per tab screen).
- A row XCUITest calls hittable under the dock or running accessory still takes the tap on the bar; drag the list first (`openLongChat`).
- Closing the drawer gives the Home field its keyboard back. The default `scrollDismissesKeyboard` did not dismiss it, so `chatsList` sets `.scrollDismissesKeyboard(.immediately)` and `AidenTranscriptTap` (UIKit; a SwiftUI tap on a scroll view never fires on iOS 26) that calls `homeComposer.session.putAwayKeyboard()`: a tap on the list or a drag down it puts the keyboard away and the dock returns. The tap modifier sits before the bottom composer inset so a tap on the composer keeps the keyboard.
- While the Home field has focus the ambient aurora keeps animating, so XCUITest waits 60 s for idle before every action; a keyboard-up UI test takes minutes.
- `app.cells` includes rows just past the window's edge; filter by `frame.minY < window.maxY` when looking for the last visible row.

## Home composer: where the chat runs (2026-11-26)
- Opening Home's composer shows the `home.composer.environment` chip ("Studio Mac · Just chat"); it opens `AidenHomeEnvironmentSheet` (`AidenHomeView.swift`): a Computer section only when more than one machine is paired (`picker.showsPicker`), Folder (Just chat plus the machine's folders), and a New worktree toggle when the chosen folder qualifies (`flow.homeOffersNewWorktree`). The choice persists per machine in `AidenHomeComposerModel` (demo runs use isolated defaults).
- Send goes through `flow.startChat(sending:on:in:inNewWorktree:)` and hands an `AidenLaunchSend` to the chat screen; `queueLaunchSend` sets `startsInNewWorktree` and `sendForLaunch` sends once `canSend`.
- Gotcha: the chat screen's model uses `AidenChatCache.shared` and `AidenChatDraftStore.shared`, not the demo coordinator's caches. Both are isolated to a fresh temp folder in demo runs; before that, a running stream an earlier simulator run saved for `chat_demo_new` was restored into the new chat and blocked the launch send (chat opened "Thinking" with the prompt still in the composer).
- The demo answers `GET /streams/stream_demo_new` with a running status, so a probe after a dropped event stream finds the run instead of a 404.
- UI test `testHomeComposerChoosesWhereTheChatRuns`: on the closed Duo the sheet opens at the medium detent, so the test taps the Sheet Grabber to raise it before looking for the Notes folder.
- Known UI-test flake (2026-11-26, undiagnosed): the first UI test of an `xcodebuild` run sometimes gets an app that ignored its launch arguments ("No computers connected" on the default tab). Seen on iPhone 18 Pro and the closed Duo in Home and dock tests. `simctl launch` with the same arguments works, and the tests pass when they don't run first (`-test-iterations 2` shows it).
