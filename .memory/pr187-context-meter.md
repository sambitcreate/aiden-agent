# PR #187 composer context meter (0.50.0 update, 2026-09-26)

- PR #187 originally shipped ordered thinking traces + the context meter. PR #224 (4f91b799, 05f01dc2) landed chronological thinking on main with `reasoningStartOffset`/`reasoningEndOffset`, reasoning rows, and iOS/Android parity. The merge took main's side for all trace files (timeline, activity feed, message list, presentation rows, protocol/openapi/fixtures, native models/tests) and deleted `thought-disclosure.tsx`.
- Kept: `ChatContextPressureV1` DTO (`renderer/shared/context-pressure.ts`), `projectChatContextPressure` in `generation-context.ts`, `main/services/context-pressure.ts` (ambient profile + journal snapshot caches), `chats:contextPressure` invoke + `chat:context-pressure` push, harness `onContextProjection`, `ContextMeter` in the composer beside the thinking control.
- `buildSystemPrompt` now lives in `main/services/chat-system-prompt.ts` and carries main's device guidance suffix. llm-client imports it.
- llm-client remembers the harness's live projection options on each `onContextProjection`, because the harness mutates its own options object with host-disclosed tools and prompts. llm-client's `generationContextOptions` object is not the same object.
- Ambient estimates skip MCP tools, MCP server instructions and generation-scoped tools, so they read as "estimated" until the chat generates again.
- Ambient estimates do include global + workspace AGENTS.md (Pullfrog on b98bf202): `withAgentsInstructionsEstimate` reuses the runtime refresher, and `agentsInstructionFingerprint` is part of the ambient cache key so edits refresh the estimate. Files the runtime would refuse fall back to the host prompt.
- Remembered generation profiles carry a `createAgentsInstructionTracker` (Pullfrog on 4fc97350). llm-client passes `agentsInstructionRoots`, but not for bot or assistant runs. When AGENTS.md changes after the prompt was captured, the stale nonce block is stripped (`withoutAgentsInstructions`) and re-estimated. The re-estimate is cached per fingerprint.
- `main/services/context-profile.ts` `rememberedContextOptions` discards a remembered profile when the chat's current AGENTS.md roots (workspace path or permission) differ from the generation's roots. It never reads the old roots (Pullfrog on 48b2385b). It also discards the profile when the effective workspace permission changed: `ask` and `full` build different host prompts (Pullfrog on 1a818db9). ChatPane re-fetches when the workspace permission or folder changes.
- Renderer: `renderer/lib/context-pressure-feed.ts` (`ContextPressureFeed`) gates ambient readings. ChatPane is intentionally NOT keyed by chatId, so the feed clears the reading and cancels the draft debounce on chat switch. While a turn is live (streaming or starting), ambient reads and the post-send draft refresh are dropped, so harness pushes own the meter. Compaction flash/pending is guarded by `chatIdRef` (Hermes on 48b2385b).
- The feed keeps the composer's latest draft, so model-switch, settle and workspace refreshes price it. `showChat` clears it (Hermes on 1a818db9). A push outside a live turn (manual compaction, where main only knows the persisted model and no draft) triggers a re-read instead of painting. Mid-turn harness pushes still paint directly (Pullfrog on c3d6b753). `setScope(permission+folder)` clears the reading when the workspace scope changes, so a pending or failed re-read never shows the old scope's pressure. The scope is pane state: `showChat` keeps it, because ChatPane's effect only re-reports it on change. Switches between sibling chats and draft→saved transitions therefore keep a real baseline (Hermes P2 on c301abc9). Empty `providerId`/`modelId` are dropped at the IPC parser and fall back with `||` in the service, so an unsettled picker never shadows the chat's saved pair (Hermes P2 on c301abc9).
- `nextRequestContextOptions` (context-profile.ts) applies the selected model's `applyCustomModelToolPolicy` after the identity override, so a `toolCall: false` custom model is priced without tools (Pullfrog on c3d6b753). Remembered profiles hold post-policy tools, so each profile records `toolsDisabled`. A policy flip discards the profile and the ambient rebuild supplies the full tool list (Pullfrog on 7c45dd7a).
- `parseChatContextPressureRequest` caps the aggregate attachment `textLength` at 16 MiB, because the projection materializes text lengths (Pullfrog on c3d6b753).
- The ContextMeter popover body is `ContextMeterDetails`: labels are `<dt>` and token values are tabular `<dd>` (Hermes on 1a818db9).
- Chat deletion releases the per-chat caches through `releaseChatContext: forgetChatContextProfile` in chat-application-service-main.ts.
- The context-meter, context-pressure and feed tests run in `npm test` and are listed in `scripts/ci-test-registry.json` (renderer-other). `test:preflight` alone is not run by CI.
- Pi 0.87.1 merge (#246): the prompt now lives in transcript system messages and the AGENTS refresher appends a section patch (`apply(AgentContext)`). `withAgentsInstructionsEstimate` builds a one-message transcript (`createInitialSystemMessage`), applies the refresher and reads `getCurrentSystemPrompt`. `withoutAgentsInstructions` also strips a block rendered with no base prompt. llm-client registers the generation profile after the initial AGENTS apply, so the captured prompt and the tracker baseline agree. The harness emits projections from `installCompactedMessages`' result. Journal system messages count zero in `messageTokens`, so static context is counted once. Pullfrog on 5186fe54 pointed out that Pi sends later system messages in place for `supportsMidConvoSystemMessages` models, including superseded AGENTS revisions. `GenerationContextOptions.retainsSystemUpdates` (from `modelRetainsSystemUpdates(model)`; set in llm-client, the harness projection options, and `nextRequestContextOptions`, which defaults it to false) makes whole-transcript estimates (`projectNextContextUsage` and compaction) add the rendered updates beyond the replayed prompt. Compaction's replay into one head removes that extra.
