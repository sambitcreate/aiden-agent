# Local Cua Space E2E runner

PR #672 syncs uncommitted work into a Linux Space. Archive symlinks as links and exclude paths reached through a symlink ancestor, even if Git still tracks them. Stop the run when the guest cannot clear its previous checkout. Hash both extracted npm manifests before reusing dependencies, so live edits are validated by the same npm ci that CI uses. Regression tests exercise all three through the host runner.

Spaces used to stay running after every run and piled up on the host. The runner now suspends the Space after a run and deletes only a custom-named Space that same run created, so naming an existing Space cannot destroy it. It skips teardown on the busy exit (75), `--watch` and `CUA_SPACE_KEEP=1`. Each new Space can pin a newer image digest of about 4 GiB, so `cua cache prune` matters after deleting old Spaces. Pruning alone returns nothing to macOS: the runtime's sparse `datadisk` is mounted without `discard` and only trimmed weekly. On 2026-11-05 a manual `sudo fstrim -v /mnt/lima-colima-cua` in the VM (`LIMA_HOME=~/.cua/runtimes/linux/vm/_lima`, then cua's bundled `limactl shell --workdir / colima-cua`) cut it from 36.1 to 20.9 GiB with containers running, so no rebuild is needed.

Teardown takes the Space's run lock first and leaves the Space up if it can't, because several agents share `aiden-e2e`. This narrows the race but does not close it: a run still starting has not taken the lock yet. The runner trims after teardown through cua's internal `limactl` path, and ignores a missing or failing one. Tests must set `CUA_HOME` so they never reach the real VM.
