# Hybrid new chat and composer context — 2026-10-15

Phases 1, 2, 3a (main + draft model) and 4 implemented. Plan: `docs/plans/hybrid-new-chat-workspace-plan.md`. Prototype: `docs/plans/assets/hybrid-new-chat-prototype.html`.

## Decisions (owner-approved direction)
- The owner chose the "Hybrid" option over a Codex-style chip bar and a T3-style "ask first" picker. ⌘N stays an instant draft in the workspace being viewed. Choosing or adding a workspace happens inside the draft: from the headline name, the composer chip, or ⌘⇧N "New chat in…".
- The owner explicitly asked for **progressive disclosure**:
  - Git and PR controls must not appear for folders that aren't git repos.
  - The PR chip appears only for a GitHub remote when there is something to open (branch ahead, linked or pending), and never on a draft.
  - The machine chip appears only with paired Macs.
- After the first send the composer top bar shrinks to branch + PR instead of fully collapsing. The workspace is not repeated there because the header `WorkspaceChip` (`chat-top-bar.tsx`) already shows it. For a folder that isn't a git repo the bar is hidden.
- "New worktree" becomes a draft setting (base branch, from origin, auto `aiden/<slug>` name). It is created on first send through the existing managed path, with an idempotency key per draft. This replaces today's create-on-pick with a typed name.

## Findings that motivated it
- `ChatPullRequestsChip` renders unconditionally in the composer context bar. It reads "Pull Requests" even on drafts and plain folders.
- The whole bar is hidden after the first message (`autoHideComposerContext`).
- ⌘O is already `workspace.openPreferredEditor`, so Open folder uses ⌘⇧O. ⌘⇧N is free.
- Remote worktree creation (`aiden-remote-git`) is used by the phones. Creating worktrees on send for remote targets needs a Remote revision plus iOS and Android work (plan Phase 5).

## Phase 2 main process (implemented 2026-10-15)
- `main/services/workspace-intake.ts` (pure `parseWorkspacePathInput`, inspect/open/previewClone/clone service), `main/services/git-clone-runner.ts` (spawned `git clone`), `main/handlers/workspace-intake.ts` (DI handler registration, wired from `registerWorkspaceHandlers`), shared contract and `parseCloneUrl` in `renderer/shared/workspace-intake.ts`.
- Channels: `workspaces:inspectPath`, `workspaces:openPath`, `workspaces:clonePreview`, `workspaces:clone`, `workspaces:cloneCancel`; progress notification `workspaces:clone-progress` goes only to the requesting document, and a reload cancels the clone.
- Repository detection while typing is a `.git` stat only: no Git process runs on user-typed folders (a hostile repo config such as `core.fsmonitor` could otherwise execute).
- Opening registers through `workspaceApplicationService.createFromFolder`, the same path as the native picker; an already registered folder (matched by realpath) is returned instead. Create makes one folder, never intermediates.
- Clone base: `~/projects` when it exists, else home (no existing setting). Clone runs `git -c core.hooksPath=/dev/null -c protocol.{ext,fd,file}.allow=never clone --progress -- <url> <dest>` in a new session (no TTY), `GIT_TERMINAL_PROMPT=0`, 16 KiB stderr tail, 60 min timeout. Accepted URLs: https, ssh://, scp-like `user@host:path`, GitHub `owner/repo`; https credentials in the URL are refused.
- Tests clone a local bare repo through the runner's `extraConfig` seam (`url.file://….insteadOf` + `protocol.file.allow=always`); the production IPC path has no way to pass config.
- Review fixes (b0a374868): repo names may not start with `.` (a `.git` name would make the clone base a repo with the remote's config, e.g. `core.fsmonitor`), and destinations with any `.git` component are refused. Clone claims its destination with a non-recursive mkdir (adopting only an empty folder), cleanup empties only that folder and `rmdir`s it only if Aiden created it, and in-flight clones are keyed on realpath(parent) + case-folded name so aliases report busy.

## Phase 2 UI: workspace menu (implemented 2026-10-15, 8a1976b08 + e2e d7509bd3e)
- `workspace-picker.tsx` (composer chip on drafts): cmdk with `shouldFilter={false}` and a controlled selection. Rows come from pure `renderer/lib/workspace-menu.ts` (`workspaceMenuList`: 5 recent via `newChatWorkspaceChoices`, "All workspaces (n)" expands, typing scores all; `workspacePathRow`; `cloneFailureMessage`; `cloneProgressLabel`; `newCloneId`; `isScratchWorkspace`). The cmdk `label` prop must be set: the input's `aria-labelledby` points at it and an empty label hides the input's `aria-label`.
- Typed paths: `useWorkspacePathIntake` (150 ms debounce, answer kept only for the current input) and `useOpenWorkspacePathRow` (`openPath`, then `adoptWorkspace` puts the workspace in the `workspaces` cache before selecting, because the active-workspace provider ignores unlisted ids). Shared by the picker and the New chat in… palette.
- Clone view lives in the same popover. Esc: cancels a running clone, else back to the list, else closes. Closing the menu or unmounting cancels the clone (chosen over keep-running-with-toast). The destination is sent only when edited; otherwise main picks `<clone base>/<repo>`.
- Focus returns to the composer via `returnFocusRef` (`onCloseAutoFocus`). Scratch chat keeps `onCreateScratchWorkspace` (`~/aiden`).
- Headline: `NewChatHeadline` in the draft empty state; the name requests the composer's picker (`workspaceMenuRequest` nonce prop on Composer), so there is one menu. Scratch detection is a renderer heuristic: `~/aiden/<word-word-word>` named after its slug (workspaces carry no scratch flag).
- App-level reach: `renderer/lib/draft-workspace-menu.ts` registry keyed by chat id (chat-pane registers while the draft is new; requests for a pane that mounts later are kept once). `workspace.openFolder` (Command+Shift+O, File menu "Open Folder…") moves the viewed draft via it, else `openFolderForNewChat`. The palette's Clone row opens the viewed draft's menu in Clone view or creates a draft first (`cloneRepositoryForNewChat`); the menu opens two frames later so the composer focus request cannot dismiss it.
- The picker test replaced the picker greps in `composer.test.tsx`'s blocked-picker contract. Onboarding has no workspace step; the feature-tour Workspaces tile description now mentions opening a folder and cloning (no art change).

## Phase 4: entry points (implemented 2026-10-15, branch `claude/workspace-creation-patterns-581b17`)
- `chat.newIn` ("New chat in…", ⌘⇧N, native File menu, palette, Settings) opens the command palette in `newChatIn` mode: workspaces by latest chat activity (`renderer/lib/new-chat-workspaces.ts`, managed worktrees left out, current marked), plus **Open folder…** (native picker → draft there). Path rows, Clone and ⌥↵ are Phases 2/3.
- All new-chat entry points go through `openNewChatIn` in `renderer/main/root-view.tsx`, exposed to the sidebar and palette via `renderer/lib/new-chat-actions.tsx`. It reuses an open empty draft (`findReusableChatDraft` in `chat-draft.ts`; content reported by `chat-pane.tsx` through `setChatDraftHasContent`), selects the workspace, and asks the composer for focus (`requestChatDraftComposerFocus` / `subscribeChatDraftComposerFocus`, which also covers a pane that mounts after navigation).
- Reuse applies only to the open, empty draft. A draft with text outlives its view (review fix `40e2c5b56`): it is never swept by a new activation, shows as its own italic "New chat" row under its workspace, reopens with its saved composer text, and goes away when sent or when cleared and left. Attachment-only drafts are not restored (attachment bytes are never persisted). ⌘N already used the viewed chat's workspace (chat-pane syncs the active workspace), so its default did not change.
- Sidebar: chevron beside New Agent (`SidebarPrimaryNav.onNewChatIn`), hover/focus **+** on local workspace rows ("New chat in <name>"), italic "New chat" draft row (`data-draft-chat=<id>`) in the projects view only, hidden while searching and once the real chat is listed. Opening a draft expands its workspace.
- `chat.newIn` is listed after `chat.search` in `COMMANDS`: cmdk kept a stale DOM order after a disabled-only query and selected the barely matching New chat in… for "Search chats" (pre-existing palette quirk, exposed by chat-shell-interactions e2e).
- `INTRODUCED_DEFAULT_COMMANDS` in `keybindings.ts` (currently `chat.newIn`): if a saved custom binding already uses the new default, repair saves the new command as disabled once instead of resetting the user's binding.

## Phase 3a: worktrees created on first send, main + draft model (implemented 2026-10-15; UI is Phase 3b)
- Commits a819b02cf (service), 7604e6cc5 (draft model), 17154719a (first send). Shared contract `renderer/shared/worktree-on-send.ts`: `FirstMessageWorktreeRequest` `{ sourceWorkspaceId, baseRef, fromOrigin, branchName?, idempotencyKey }`, `FirstMessageWorktreeResult<C>` (`{ ok: true, chat, worktree: FirstMessageWorktreeInfo }` or `{ ok: false, code: "worktree-failed", reason, detail? }`), `FirstMessageWorktreeProgress` (`fetching` → `creating` → `ready`), and pure `isValidBranchName` (tested against `git check-ref-format --branch`), `worktreeBranchSlug`, `autoWorktreeBranchName`, `uniqueBranchName`.
- `workspaceWorktreeApplicationService.createFromBase(owner, sourceId, { baseRef, fromOrigin, branchName? | autoName: { seed }, onBranchResolved, onProgress })` shares `createIn` with `create` (unchanged signature, still used by `git:createWorktree`, Remote and the CLI). Base = local branch, `origin/x` remote-tracking branch, or `HEAD`. From origin uses the local branch's upstream, else `origin/<base>` if that tracking ref exists, else falls back to the local base (`baseSource: "no-upstream"`). Fetch: `git fetch --no-tags --no-recurse-submodules --no-write-fetch-head -- <remote> refs/heads/<b>` with hooks off, `protocol.ext.allow=never`, `maintenance.auto=false`, `gc.auto=0`, push timeout; the worktree then starts at the fetched commit itself. `GitService.createWorktree` gained `options.startPoint` (resolved inside the mutation queue; `createdFromHead` is the base commit).
- Auto names: `aiden/<slug>` (NFKD, ascii, whole words up to 40 chars, fallback `aiden/new-chat`), then `-2`, `-3`… against local branches, case-folded and including folder conflicts (`aiden` blocks `aiden/x`). An explicit `branchName` that exists is an error, never renamed.
- `chats:createWithFirstMessage` with `worktree` (parser requires `sourceWorkspaceId === workspaceId` and `idempotencyKey === draftId`) goes through `createWorktreeFirstMessageCommitter` → `createFirstMessageWorktreeCoordinator` (`main/services/first-message-worktree.ts`) → the ordinary committer with the new workspace id. Renderer wrappers: `chatsApi.createWithFirstMessageInWorktree` and `chatsApi.onFirstMessageWorktreeProgress` (notification `chats:first-message-worktree-progress`, sending document only). The plain path is unchanged and rejects a `worktree` field.
- Idempotency: attempts for one draft id are serialized in main; a `pending` record with the chosen branch is written to `userData/first-message-worktrees.json` before Git creates anything, `ready` (+ workspace id) after. A retry or double send reuses the ready worktree; a pending record whose branch has a saved managed workspace is adopted after a restart. A renderer reload aborts an in-flight creation (owner-bound like every workspace operation, so it rolls back) and the retry starts fresh. A ready record whose workspace was removed fails with worktree-failed instead of recreating.
- Draft model (`renderer/lib/chat-draft.ts`): `gitMode` (`checkout` default) and `worktree?: { baseRef, fromOrigin, branchName? }`; `createChatDraft(..., { gitMode })` for ⌥↵; `setChatDraftGitMode`, `updateChatDraftWorktree`, `chatDraftWorktreeRequest`. Moving a draft to another workspace resets mode/base to that workspace's memory. Memory: `renderer/lib/chat-draft-git-memory.ts` (localStorage `aiden-agent.draftGitMemory.v1`, 100 most recent workspaces; base and from origin remembered, branch name not) and `resolveDraftWorktreeDefaults` (remembered base if it still exists → default branch → current; from origin defaults on with a remote; undefined when unborn).
- Not changed: Remote protocol, `aiden-remote-git`, iOS/Android (desktop-only optional IPC field). `chat-pane.tsx` send path, branch menu UI, progress row and Retry / Run in this checkout are Phase 3b. Tests: `npm run test:worktree-on-send` (real temp repo with a bare origin and a hook probe).
