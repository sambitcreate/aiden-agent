# Keep awake while Aiden works — 2026-11-22

- Plan: `docs/plans/proactive-aiden-plan.md` C1. C3 (check-backs and Bot wake-ups due within 60 minutes, AC power only) is not built yet.
- Core `main/services/keep-awake/keep-awake-core.ts` (pure, fake-clock tested): `KeepAwakeController` holds one blocker while any `KeepAwakeInput` reports a reason. 60 s grace keeps one hold across back-to-back runs; system idle >= 4 h releases (polled every 60 s only while reasons exist) until idle drops; switch off releases at once; `dispose()` at quit. Inputs may return `recheckAt` for time-based changes (floor 1 s).
- Inputs `keep-awake-inputs.ts`: host runs in state `working` (not `needs_approval`/`needs_input`; a chat run whose usage-limit wait is >10 min away doesn't hold), usage-limit waits ending within 10 min (chat or Bot), running background jobs with no ports and not `origin: "command"` leftovers, `/until` checks in state `running`.
- To add an input later (C3, goals): write an adapter returning `{reasons, recheckAt?}`, add its kind to `KEEP_AWAKE_REASON_KINDS` and label in `renderer/shared/keep-awake.ts`, then add it in `startKeepAwake` (`keep-awake-main.ts`; the unused `addKeepAwakeInput()` helper was removed in the 2026-11 dead-code sweep, so call `KeepAwakeController.addInput` there if it must arrive late) and trigger `update` on the source's change event.
- Electron binding `keep-awake-main.ts`: `powerSaveBlocker.start("prevent-app-suspension")` (exported from `main/platform.ts`), `powerMonitor.getSystemIdleTime()`. Change signals: `hostRunRegistry.onChange`, `usageLimits.gate.onChange`, and `onBroadcast` for `chats:follow-through-changed` (jobs, ports, checks) and `schedule:updated` (re-reads the setting). Started after `startFollowThrough()` in `main/index.ts`; stopped at the top of `shutdownAndQuit` and in `cleanupApplication`.
- Capability `keepAwake: darwin || linux` in `host-platform-capabilities.ts`; Linux is best-effort (desktop inhibit service over D-Bus), documented in `docs/linux.md`. Not verified with `systemd-inhibit --list` on a real GNOME/KDE box yet.
- Setting: `AppSettings.keepAwakeWhileWorking` (only `false` stored; `scheduledSettingsPatch` writes `undefined` for on), surfaced as `ScheduledTaskSettings.keepAwakeWhileWorking`. `aiden-remote-schedules.ts` projects only the six phone fields, so phones never see or set it (no Remote revision).
- UI: Settings → Scheduled tasks → "While you're away" group after "Background execution" (C2 adds "Let chats check back later" / `chatCheckBacks` to the same group). Live line from `schedule:keepAwakeStatus` + push `schedule:keep-awake-changed` via `useKeepAwakeStatus()`; row hidden when status says unsupported. Search words: awake, sleep, caffeinate, keep awake.
- Tests: lane `test:keep-awake` (core, inputs, `renderer/shared/keep-awake.test.ts`, appended to `test:serial`); `scheduled-tasks-settings.test.tsx` in `test:settings-design`; search in `renderer/lib/settings-section.test.ts`; settings store in `scheduled-task-application-service.test.ts`; phone projection in `aiden-remote-schedules.test.ts`.
