# Android provider logos

Android now draws the same 42 provider marks as desktop (`renderer/components/provider-icon.tsx`) and iOS (`ProviderLogo-<slug>` image sets). Before this, `AidenProviderIcon.kt` resolved the slug but only used it to pick a brand fill for a letter tile.

- Drawables: `android/app/src/main/res/drawable/ic_provider_<slug_with_underscores>.xml`, generated by `python3 android/scripts/generate-provider-logos.py` (standard library only; `--check` fails on drift). Never hand-edit them; change the SVG in `renderer/assets/provider-logos/` and rerun.
- The converter supports only the SVG subset those files use (shapes, nested svg/g, translate/scale/rotate, clipPath, `.class` CSS rules) and fails loudly on anything else. It drops elements entirely outside the viewBox (Fireworks, Together, and Grok wordmarks) and merges same-paint nonzero shapes only when their bounds are disjoint, because overlapping opposite-winding subpaths would cancel.
- Mono marks are written with one black fill and drawn with `Icon(tint = tint ?: colorScheme.onSurface)`; `multicolorSlugs` (fireworks, groq, opencode, opencode-go, together, zai, zai-coding-cn) render with `Image` in brand colors. Keep that set identical across desktop, iOS, Android, and the generator.
- Unknown/custom providers get a neutral initial (`surfaceContainerHigh` fill, `onSurfaceVariant` letter). The old brand-fill helpers were removed. Custom `artwork.boundedPNGData` still wins.
- The mark is decorative (`hideFromAccessibility`); every call site puts the provider or model name next to it.
- Notice: `android/app/src/main/assets/ThirdPartyNotices/ProviderLogos-NOTICE.md` mirrors the iOS notice.
- Tests: JVM `AidenProviderIconTest` (every slug has a distinct drawable, Android slugs equal the desktop SVG set, mono drawables use one paint, multicolor ones keep brand color, resolver cases). Instrumented `AidenProviderIconUiTest` captures pixels: tinted logo vs no initial, neutral fallback fill, artwork precedence, and every bundled logo inflating with visible ink.
- Verification during the change: each generated drawable was converted back to SVG and rasterized next to the source with Quick Look. Shapes matched; the remaining pixel differences came from resampling.
