# Quick View cards — 2026-10-15

Quick View is now Claude-Code-style stacked cards (owner decisions 2026-10-15; plan `docs/superpowers/plans/2026-10-15-quick-view-cards.md`, merged in PR #487, shipped in 0.57.0). The old single "Quick View" card with its header and `+` menu is gone. Renderer-only except one optional field on the desktop context projection: no new IPC channel, no network call, no Remote protocol, iOS, Android or `packages/cli` change.

## Shape
- Cards: Environment, Changes, Context, Subagents. Each is a borderless raised card (`bg-popover`, `rounded-dialog`, `shadow-popover`) with an 8px gap and no "Quick View" heading. `QuickViewCards`/`QuickViewCard` in `environment-panel.tsx` stack them; `renderer/components/quick-view-section.tsx` is one card; `renderer/lib/quick-view-layout.ts` is the pure model.
- The stack scroller is `p-2` with `-m-1.5` and 12px extra width, so shadows, a dragged card's lift and its overshoot aren't clipped while the cards keep their position.
- Density copies `SidebarListItem` (`min-h-9`, `px-2.5`, `gap-2.5`, `text-regular`, `size-4.5` icons, `text-small text-tertiary` secondary text); titles are `text-strong font-medium`. The chevron (`ChevronDown`) sits after the label and rotates -90° when collapsed.
- Right-edge grip: shows on card hover and `focus-visible`, stays visible while dragging. Pointer drag has a 4px threshold, clamps travel to the first/last sibling (8px overshoot) and shifts siblings with a preview; ArrowUp/ArrowDown on the grip moves the card and the parent's single stable `role="status"` region (`QuickViewMoveStatus`, outside the keyed list) announces "<Title> moved to position n of count"; grip focus is restored after the DOM node moves. Reduce Motion: no scale or translate transition, and collapsed bodies hide immediately (the Subagents list also unmounts).
- Three tiers per card: (1) collapsed header with a trailing summary (also exposed to assistive tech via `aria-describedby`); (2) expanded inline detail (the body is `inert` and `aria-hidden` while collapsed, the header reports `aria-expanded`); (3) a header button left of the grip. Changes, Context and Subagents use **Open ... in sidebar** (`PanelRightOpen`) to open Review, Context or Subagents in the Environment tools. Environment uses an open-external button (`ArrowUpRight`, "Show <workspace> in Finder", "Files" off macOS) calling `workspacesApi.openFolder`; failures toast. The Changes, Context and Subagents "Open … in sidebar" buttons are disabled while a Git operation runs; Environment's Show in Finder is not.
- All cards start collapsed. Persisted layout (`aiden-agent.quick-view.layout`, device-local localStorage, not per workspace) is `{ order, expanded }` where `expanded` holds only the cards the user opened, so a card that shows up later also starts closed. Parse drops unknown ids and duplicates, appends missing defaults, and never throws on corrupt values. There is no setting for any of this.
- Reorder rules (`moveSection`): hidden cards keep their place relative to the visible card they followed (anchor semantics; a hidden card anchored to the dragged one travels with it, and one at the front stays at the front). `dragTargetIndex` uses the leading edge (top when moving up, bottom when moving down) against the neighbour's midpoint, so a tall card can pass a short one.
- Toolbar order is now Quick View | Terminal, Changes, Browser, Device, Files | Open in editor, ⋯ | Environment toggle (`WorkspaceToolButtons` got `leading`/`trailing`/`end` slots; `leading` and `end` stay visible when the tools fold into ⋯).

## Visibility
- `quickViewVisibleSections` (`quick-view-layout.ts`) applies the rules below to the saved order; `QuickViewCards` feeds it and keeps whether Changes was shown in state (set in a layout effect), never by reading a ref during render.
- Environment: always, when the workspace has a folder and access is not `none`; otherwise the old explanatory empty card (`QuickViewUnavailable`).
- Changes (`useChangesVisibility`): a Git repo with working changes, commits ahead of the last-fetched upstream, or a PR for this chat. A clean repo shows no card. The card stays mounted while a commit or push dialog is open or `panel.gitOperationBusy`, so an in-flight dialog is never unmounted (only a card already on screen is held). The visibility hooks run only while Quick View is live and file access is available, so a No Access workspace sends no `git:review`.
- Rows inside cards: Environment = Folder (Browse files, Show in Finder, preferred editor), Local, Branch. Changes = Changes, Commit or push, Compare branch, Pull request. The Pull request row renders only when `pullRequestsApi.current(chatId)` returns a PR (a merged PR without a title is named by its branch); there is no Create PR button. The Folder row's `usePreferredEditor` passes `silentDiscoveryErrors`, so only the toolbar picker toasts a failed editor discovery. The Folder row replaces the old `+` menu's Browse files, and focus handoff to tools from these rows is covered by `environment-focus.spec.ts`.
- Context: only once the chat has a context projection (`panel.contextDetails?.pressure`, after the first message). Percentage matches the composer `ContextMeter` (`contextPressurePercent`).
- Subagents: only once the chat has started a subagent (`panel.subagentViews.length > 0`, subagents enabled); it stays for the session after runs finish. Its body mounts only while the card is open, since rows tick elapsed time once a second.
- When a card leaves the stack while focus was inside it (focus fell to the body), focus moves to the first remaining card's header button. A leaving card also clears any drag preview it owned.
- A card that appears mid-session enters with `quick-view-card-enter` (opacity + scale .97 → 1, `--motion-large-duration`); none under Reduce Motion. Cards present when Quick View opens do not animate.

## Context breakdown
- `ChatContextPressureV1.breakdown?: ContextBreakdownV1` (`renderer/shared/context-pressure.ts`), built by `estimateContextBreakdown` in `main/services/generation-context.ts`. `parseChatContextPressure` treats it as all-or-nothing: a malformed entry, a repeated category, or categories not summing to `staticTokens` drops the whole breakdown. It is also omitted when the options changed after the projection (tokens differ from `staticTokens`). The UI then falls back to two segments, Messages and "System prompt & tools".
- Categories (ids): `system-prompt`, `builtin-tools`, `mcp-tools`, `skills`, `memory`, `project-instructions`, `mcp-instructions`, `bot-instructions`; zero-token ones are omitted. They use the same chars/4 rule as `estimateStaticContextTokens`, apportioned by largest remainder so they sum exactly to `staticTokens` (leftover tokens go to the biggest fractional remainders, ties to System prompt first).
- Measured: built-in vs MCP tools by tool size (`isMcpTool` = codemode tool with discovery); project instructions = the AGENTS.md block measured from the final system prompt (`withoutAgentsInstructions`); MCP server instructions = the admitted `<mcp_servers>` transcript section measured from the same replayed prompt (`withoutMcpServersSection`, after the AGENTS.md block is stripped), so its initial patch, refreshes and removal are reflected automatically and it is never also recorded; skills, memory and bot instructions = text recorded where the prompt is assembled (`promptSections`), scaled down if recorded longer than the prompt sent; system prompt = what is left, never negative. An idle (ambient) chat's estimated prompt never carries the `mcp_servers` section, so it has no MCP server instructions row (never a row of 0).
- Deferred MCP tools (held behind tool search) are listed per server (`discovery.label`, grouped by `discovery.namespace`) with tool count and tokens, shown in muted text with "—" for % and never counted toward the window. Tools already declared are not double-counted.
- Detail UI (`renderer/components/context-breakdown.tsx`, tiles in `context-tiles.tsx`, redesigned 2026-10-19): 100 tiles over the whole `contextWindow` (each 1%), used tiles per category by largest remainder (any used context or reserve gets at least one tile), then Free, then the hatched reserve; a row per category with tokens, % of window and a bar relative to the largest category; quiet Reserved, Free and deferred ("not counted") rows; a folded "MCP tools by server" list; a soft status pill on compaction state, `compressibleHistoryMessages`, and deferred tools. `layout="panel"` puts a square grid beside the bars in the Context tool. The composer meter and the Quick View summary use 10 pips (`ContextPips`); the popover warns from the 80% approaching phase on. Colors use `--chart-1..8` only: Messages 1, Built-in tools 2, System prompt 3, MCP tools 4, Skills 5, Memory 6, Project instructions 7 (shared with Bot instructions), MCP server instructions 8.
- Prompt cache timer (2026-10-19): `ChatContextPressureV1.promptCache` ({ttlMs, lastRequestAt}) drives a countdown under the breakdown in Quick View and the Context tool. TTL comes from `promptCacheTtlMs` in `main/services/prompt-cache-lifetimes.ts`: the catalog's `promptCache.short` first, then a sourced table for providers that publish a fixed idle lifetime refreshed on each read (Claude via Anthropic markers or Bedrock 5 min, Bedrock Nova 5 min, OpenAI/Azure GPT-5.6+ 30 min, Moonshot and MiniMax 5 min, Copilot Claude 1 h / OpenAI 24 h). Best-effort ranges (older OpenAI, DeepSeek, Fireworks, Groq) and undocumented caches (Gemini implicit, xAI, Z.ai, Mistral, Codex) get no timer. Ambient `lastRequestAt` is the newest same-model cached response; live is the request's preparation time, and successful cache-warming refreshes re-send it (`onCacheRefreshed`). Cache warming itself still uses only the catalog TTL.
- When provider usage anchors the projection, `contextTokens` (max of local estimate and provider-anchored usage) can exceed `messageTokens + staticTokens`; the excess is its own used segment, "Provider-counted, not itemized" (faded `--chart-1`), in tiles, legend and image label (omitted at 0, also on the fallback path), so used + Free + Reserved spans the whole `contextWindow` and Messages stays the local estimate.
- Subagent detail (`SubagentStatusGroups` in `subagent-status-groups.tsx`, grouping by `groupSubagentRunsByStatus` in `renderer/lib/subagent-panel-state.ts`): every run grouped Running, Needs attention, Failed, Stopped, Completed; Completed starts folded; Stop on hover or focus for foreground v2 runs that are still active (disabled "Stopping…" while pending, inline error until the next attempt); a row opens that run. Everything derives from `panel.subagentViews[].snapshot`.

## Left out on purpose
- MCP server status, outputs, background tasks and Aiden Remote cards; no invented data.
- Create PR from Quick View (only an existing PR is shown).
- Showing the breakdown in the CLI or on phones: `ChatContextPressureV1` is desktop-only and the new field is optional, so `packages/cli` built and passed untouched.
- A `+` menu or any way to hide a card by hand; relevance decides.

## Known gaps (accepted in review)
- The bot-session-main path records no `bot-instructions` prompt section, so bot chats there fold bot instructions into System prompt.
- The deferred-tool list can be stale after an MCP config change until the next generation; the memory category is measured at generation start.
- The preferred editor in the Folder row is not synced between hook instances, so its label can lag the toolbar picker choice until remount.
- Context and Subagents cards have no dedicated e2e; they are covered by component tests.
