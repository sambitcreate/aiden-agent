# Project Context

## Identity and repository

- **App:** Aiden Agent
- **Repository:** `https://github.com/sambitcreate/aiden-agent`
- **Ownership:** Privately owned, self-contained Electron codebase with no external host application or private SDK requirement.
- **Purpose:** A native macOS AI workspace agent that chats with local or hosted models and can act inside user-selected folders with explicit permissions.

## Current architecture

- **Desktop runtime:** Electron. `main/index.ts` owns lifecycle, windows, application menus, shortcuts, and cleanup.
- **Platform boundary:** `main/platform.ts` centralizes Electron exports, logging, native dialogs, theme, microphone permissions, and renderer notifications.
- **Security bridge:** `renderer/preload.ts` exposes `window.aidenAPI` through `contextBridge`. Renderer invokes are prefix-allowlisted and notifications are channel-allowlisted. Renderer sandboxing and context isolation are enabled; Node integration is disabled.
- **External editors:** `main/services/external-editors.ts` discovers a curated set of installed macOS editors from bundle metadata and standard application locations, deduplicates related bundles, caches native icons, and opens only a stored workspace folder through `/usr/bin/open -b` without a shell. The renderer stores the global preference under `aiden-agent.preferredEditorId`; Finder is always the final fallback.
- **Environment surfaces:** A compact, rounded Environment summary card floats at the top-right of the chat without resizing, dimming, or disabling the conversation. Changes and Compare open the larger Review surface; the header action also opens Files. Review and Files share a persistent, resizable right-side work surface that stays inline when the conversation region is wide enough and becomes an inert, dismissible overlay at compact widths. Open view and width persist, while the mounted Files editor preserves selections and drafts when the summary card is shown.
- **Renderer:** React 19, TanStack Router, TanStack Query, Tailwind CSS 4, local UI components in `renderer/components/ui.tsx`, Radix primitives, cmdk, Sonner, Lucide, and MIT-licensed `thinking-orbs`. The transcript maps real preparing, thinking, responding, discovery-tool, working-tool, approval-wait, and stopping signals to compact inline canvas motion. Prefix-stable prose preserves exact boundary whitespace and enters with a 160ms opacity-only reveal so inline baselines never move or blur; long run-on prose settles in bounded word groups, while Markdown structures grow through stable canonical blocks with a restrained one-time 180ms 4px entrance. A persistent schedule prevents fast-provider chunk bursts from starving the reveal, while completion drains through bounded waves and settles before a single canonical Markdown handoff with matching reserved geometry. LM Studio and Ollama reasoning streams into a compact muted, borderless, scroll-faded surface above the final answer; safe tool milestones remain as compact, unboxed steps beside the associated assistant message. Live event, label, approval, and error changes crossfade with bounded exit layers, while historical steps stay static, unpersisted error responses remain copyable, and app-level light/dark and Reduce Motion settings are honored. The local component layer preserves the established macOS visual contract: translucent materials, native-density controls, a light/dark elevation ladder, shared hover/pressed/focus/disabled states, collapsible/resizable split views with compact focus isolation, measured toolbar/footer scrolling, content-aware scroll-edge fades, command pickers, fields, menus, and dialogs.
- **Appearance:** `renderer/shared/appearance.ts` owns the versioned paired light/dark configuration, presets, strict import/IPC parsing, contrast checks, and token resolution. `renderer/lib/appearance-runtime.ts` prepaints a cached safe theme before React and propagates semantic color, font, motion, cursor, sidebar, and diff preferences. Settings persist only safe configurations; native theme and Dock changes are applied before their preference is committed.
- **Build:** Vite emits `build/renderer`; esbuild emits `build/main/index.js` and `build/preload/preload.cjs`; SwiftPM builds a background helper app for Apple Foundation Models after selecting the newest compatible full Xcode without changing global `xcode-select`; electron-builder packages the `.app`, DMG, and ZIP. Development runs through a cached ad-hoc-signed Aiden-branded Electron bundle while retaining explicit development runtime semantics. Enabled `main` releases use a GitHub run-number patch version, Developer ID signing/notarization, transactional artifact verification, and public binary-only generic-feed metadata for `electron-updater`.
- **Computer Use foundation, adapter, and product gate:** Aiden packages the exact-pinned external `cua-driver` 0.8.3 behind a separately identified Rust broker/bridge in `Contents/Helpers/CuaDriver.app`. The broker owns macOS TCC responsibility and launches the untouched driver as embedded MCP with its exact broker bundle attribution; it implements no capture or input behavior. Anonymous fd-3 parent authentication, full audit-token peer checks, kernel launch requirements, occupied process groups, retained exact child identities, and one-shot broker leases make privileged startup and teardown fail closed. A generation-owned TypeScript adapter exposes the reviewed Hermes-style action contract only when the persisted global beta gate, the chat-local opt-in, live signed-helper readiness, both macOS permissions, and the current generation ownership snapshot all agree.
- **Persistence:** JSON under `app.getPath("userData")`; chat mutations are serialized across the shared index so background metadata updates cannot race message writes. The main-process generation owner atomically appends assistant content, explicit local-model reasoning, and its terminal renderer-safe timeline before emitting completion; only assistant messages may retain validated reasoning/timeline data, and renderer-authored chat writes cannot inject either field. The private usage profile stores only aggregate request, token, cost, model, and calendar buckets in a serialized `usage.json` ledger; it never stores prompts, generated content, chats, workspace identifiers, or paths. Provider keys, type-tagged Pi OAuth credentials, MCP OAuth sessions, and built-in MCP preset API keys are encrypted with Electron `safeStorage`.

## Agent and tools

- Pi is embedded in-process through `@earendil-works/pi-agent-core` and `@earendil-works/pi-ai`.
- Workspace tools include `read_file`, `list_dir`, `glob`, `grep`, `edit_file`, `write_file`, and `run_command`.
- Every filesystem path is resolved inside the active workspace root. Commands run with the workspace root as their working directory.
- Permission modes are Full, Ask, and No Access. Ask mode pauses write/edit/command calls for inline Allow once or Deny approval. Permission, folder, and workspace changes cancel both active and initializing generations before any newly disallowed tool continuation can begin.
- On an untouched new chat, the composer folder control opens a searchable workspace plate and can reassign that same empty chat without leaving a duplicate. “Don’t work in a workspace” creates a private, collision-safe `~/aiden/<word-word-word>` scratch folder using three- or four-letter words, persists it as an Ask-mode workspace, and binds the chat to it. Chats with messages cannot be moved this way.
- Git IPC is workspace-ID scoped: main re-resolves the stored directory and rejects No Access workspaces instead of accepting renderer-provided paths. Folder grants come from a main-process system picker. Permission changes, workspace removal, and renderer teardown abort active Git operations.
- `main/services/git.ts` runs direct argv-only, noninteractive Git subprocesses with bounded output, read/mutation timeouts, process-group cancellation, path/credential-redacted failures, inherited Git-routing-variable removal, NUL-safe porcelain parsing, one-second bounded caches with mutation epochs, and a mutation queue keyed by Git's canonical common directory.
- Git status reports the current, detached, or unborn ref, uncommitted count, upstream, ahead/behind divergence, default branch, remotes, and local/remote refs. Tracking information uses local refs and is labeled “last fetched”; Aiden never fetches implicitly. The composer branch menu polls local state, switches or creates local branches, and can create an isolated branch checkout under Electron `userData/worktrees`.
- Review uses the same workspace-ID authorization boundary to list staged, unstaged, conflicted, renamed, copied, deleted, and untracked files, then renders bounded combined worktree-to-`HEAD` diffs. Untracked text receives a synthetic patch; binary and truncated output are explicit states. Files indexes up to 4,000 workspace entries without following escaping symlinks and opens only bounded UTF-8 text. Saves are atomic and SHA-256 version-checked so a newer on-disk file is never overwritten silently.
- Managed worktrees are persisted as separate workspaces with the source permission and ownership provenance. Creation preserves nested workspace scope and rolls back both Git and filesystem state on failure. Explicit deletion refuses dirty checkouts and deletes the managed branch only when it still points to its original creation commit.
- Agent Skills are loaded from workspace and user `.agents/*/SKILL.md` folders.
- MCP supports stdio, HTTP, and SSE transports plus native-app OAuth with a loopback PKCE redirect and encrypted tokens. A built-in preset catalog (`main/services/mcp-presets.ts`: Composio, Notion, Linear) offers one-step setup in Settings → MCP Servers; preset API keys live encrypted in the keychain-backed secrets store under `mcp:<serverId>` and are injected only after main binds the deterministic preset identity to its exact official HTTPS origin. Credential-bearing API-key requests reject redirects. Notion and Linear use explicit browser OAuth; re-authorization preserves dynamic client registration, replaces tokens only after a verified login, and restores the prior encrypted session on failure. Adding a provider requires a catalog entry plus an explicit allowed origin.
- Optional Exa search becomes an agent tool when enabled and configured.
- Scheduled Tasks is implemented through Phase 4. Electron main owns timezone-aware cron jobs, launch catch-up, serialized per-task lifecycle changes, bounded script process groups, dedicated chats, macOS notifications, 50-run history, workspace-revocation and shutdown cancellation, and privacy-safe scheduled usage attribution. `/scheduled` and Settings provide management/defaults; interactive agents receive one compressed `schedule_task` tool whose mutations always require live approval. Read-only LLM schedules withhold mutating built-ins and MCP tools with unknown capabilities; scripts require explicit Full permission. Invalid stored tasks are quarantined as disabled `Needs attention` rows rather than preventing launch.
- The reviewed Computer Use boundary exposes exactly 20 upstream MCP tools internally and filters every other driver method/tool. One sequential, consolidated `computer_use` AgentTool provides zero-based AX targeting, pinned-schema mapping, Pi-native transient image results, action-aware fail-closed validation, exact target-bearing approval prompts, prompt-time generation/args/target-revision grants, structured verify/escalate verdicts, and generation-owned helper teardown. Every mutation requires approval, dangerous typing/shortcuts are hard-blocked, stale snapshots are invalidated after actions, and production registration is conditional on the global and per-chat gates plus current readiness.

## Models, attachments, and voice

- Providers support OpenAI-compatible and Anthropic-compatible APIs, with presets for common hosted services and local Ollama/LM Studio endpoints.
- ChatGPT / Codex is a dedicated Pi-native provider backed by exact `@earendil-works/pi-ai` and `@earendil-works/pi-agent-core` `0.80.10` pins. Settings owns browser/device-code OAuth, the composer exposes Pi's available Codex models only while the stored credential is usable, and request-time auth refresh/health remains in Electron main. Reasoning-capable signed-in models reuse the compact Thinking control with an atomically persisted exact-model preference: Low, Medium, High, and XHigh across the current catalog, plus Max only for GPT-5.6. The duplicate `minimal` alias and a misleading Off state remain hidden; unsaved selections default to Medium.
- A new chat immediately uses the first prompt or attachment name as a temporary title, then generates a concise title in the background. Provider Settings offers Automatic, Apple Foundation Models, or the selected chat model. Automatic prefers Apple on supported macOS 26+ Apple Intelligence hardware when the model is ready; the Apple-only mode never silently falls back to a network model after a native attempt. Each populated chat also exposes an explicit `Rename with Apple` context-menu action that uses the original request plus a bounded recent transcript and never falls back to a network model. Manual renames win over late generated results, and failures leave the existing title in place. Successful generated title replacements fade the prior sidebar title out over 200ms, then run a 500ms character-by-character opacity and 2px-rise reveal; Reduce Motion renders the final title immediately.
- Model metadata follows a strict offline-read precedence contract. LM Studio and Ollama discovery use their native model endpoints, persist chat-only local names/capabilities/context/parameters/format, and take precedence for local providers. Hosted models prefer the current user's normalized Artificial Analysis cache when its generation matches the encrypted credential; the release-bundled models.dev snapshot fills unmatched models and fields. Provider-facing IDs never change, and unknown values stay unknown instead of being treated as unsupported. Ordinary reads never contact a public catalog.
- The composer model picker uses a compact 316px surface with `List` and `Pad` tabs. The Personal Model Pad contains only models the user has saved in Settings and preserves their exact device-local capability/response-pace positions; it opens first once populated and otherwise hands off to the complete searchable List. The Pad's puck snaps directly to the nearest saved model during hover, drag, or arrow-key navigation without animating its position or scale, then fills from white to the active theme accent over 250ms when pointer release, Enter, or Space confirms a model. Uncommitted hover still returns to the selected model. List pinning remains independent, while a separate 224px read-only sidecar shows provider, capability, context, output, release, and knowledge metadata outside the main picker on windows wide enough to support it.
- Settings owns direct two-dimensional Model Pad arrangement: users add any usable chat model, drag or arrow-nudge it vertically by personal capability and horizontally by perceived response pace, then explicitly save the versioned local layout. Cached Artificial Analysis rankings are optional suggestions for unplaced hosted models only; they never override a personal placement, never gate the Pad, and retain visible attribution. Credentials and Artificial Analysis data are never packaged.
- Text files are inlined with size limits; images are base64 encoded and sent only to vision-capable models.
- Cloud transcription supports configured OpenAI and Gemini providers.
- Local transcription uses bundled `sherpa-onnx-node` and downloaded Parakeet models. PCM conversion happens in the renderer; recognition happens in the main process.
- Global dictation: the dictation hotkey (default `⌘⇧D`) works from any app while Aiden runs. `main/services/dictation-coordinator.ts` serializes starting → recording → transcribing → delivering, while `main/windows/pill-window.ts` hosts a transparent, non-focusable, always-on-top pill whose renderer owns MediaRecorder capture. The pill uses a dedicated least-privilege preload and its lifecycle IPC is bound to the current main document. Pending capture/transcription work is generation-gated and time-bounded. `main/services/dictation-paste.ts` performs a compiled atomic AppleScript transaction that snapshots the complete native pasteboard, revalidates the exact process/focused element, pastes, and conditionally restores without overwriting a newer user copy. Accessibility is refreshed after returning from System Settings; without it the transcript remains on the clipboard.

## Privacy boundary

- Local data and credentials remain on the Mac unless a configured feature sends a request.
- The Profile route reads only privacy-safe aggregate usage summaries. Its optional share card is rendered locally, validated and re-encoded as a fixed 1200×1600 PNG in Electron main, exposed through the native macOS share menu, and removed from a private temporary directory after the bounded share session.
- Apple Foundation Models title prompts stay on-device. Electron main launches the bundled background helper app through LaunchServices and exchanges one bounded, versioned JSON request through a private temporary directory that is deleted after completion.
- Hosted model calls, cloud transcription, Exa, remote MCP servers, and model downloads require network access and share the minimum data needed for that request. models.dev refreshes happen only through the explicit development refresh or guarded release build step. Artificial Analysis uses the fixed Free endpoint only for an explicit user-requested Connect & fetch or Fetch latest action.
- A local-only session requires a local model endpoint, local voice, Exa disabled, and no remote MCP servers.

- The existing seven declarative API-key providers remain on their compatibility runtime for now. Codex is reserved from those generic key/edit/remove paths and is projected into the composer only when configured and not proven unhealthy.
- Arbitrary executable Pi extensions remain excluded until Aiden has a separate trusted plugin design. The paired Pi packages are exact-pinned at `0.80.10`; Codex is forced to SSE until Pi checks an already-aborted signal before constructing its WebSocket handshake.
- Every fresh Pi `Agent` now receives a model-aware `transformContext`. Pi's latest provider usage remains anchored to the exact prefix it measured while later tool results are estimated independently. Aiden preserves the two newest user turns and recent completed tool evidence, compacts older tool results without mutating persisted state or inviting repeat calls, and retains valid assistant tool-call/result pairs. If an active turn still cannot fit, only the outbound context becomes a bounded non-tool recovery notice; a static system/tool context that cannot fit is rejected before provider I/O.
