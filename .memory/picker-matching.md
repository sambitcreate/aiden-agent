# Picker matching and highlight (UI SDK lessons, Unit 3)

2026-11-19. Plan: `docs/plans/ui-sdk-lessons-plan.md` row 3.

- `renderer/lib/text-match.ts` is the one matcher for pickers. `fold()` lowercases and strips accents (NFD, marks removed) one UTF-16 unit for one, so ranges in the folded text are ranges in the label; a character whose fold would change length keeps its plain lowercase or itself (Hangul syllables stay as they are; `İ` folds to `i` through NFD). The query is NFC-normalised first, so a decomposed query matches a composed label. Adjacent initials join, so an emoji's surrogate pair is never split across marks. `matchText` tiers: prefix 400, word start 300, contains 200, word initials 150 ("gp" → Git push, camelCase counts), letters in order 100. `matchItem` adds keywords (contains only, 140/120, never highlighted) and an all-words pass (110). `rankMatches` is a stable sort; an empty query keeps input order.
- `MatchText` (`renderer/components/match-text.tsx`) renders `<mark class="bg-transparent text-match">`; `--text-match` aliases `--accent-text` (styles.css `:root`, `--color-match` in `@theme`). No fill, no border.
- Command palette: cmdk runs with `shouldFilter={false}`; `rankPaletteResults` filters and ranks each mode's rows and the render order is the selection inventory. cmdk `value` is now the plain stable identity, so the JSON identity+keywords value (the alias-cache workaround from Upgrade 12) and `filterPaletteResult` are gone. `reconcilePaletteResult(selected, visible)` keeps the selection by identity, else the first enabled ordinary row, else a forced Retry. Root, Models and Settings rank mixed row kinds together (commands + appearance, models + unavailable providers, appearance + destinations); single static rows (New chat, Open folder, Refresh) keep their place when they match.
- Chat rows match on the title only. Dates were removed from keywords: "11" matched every November chat. The workspace folder path stays a keyword (matches, no mark).
- Model picker List: `shouldFilter={false}`; with a query, `rankMatches` over the label with provider name, provider ID, model ID and format as keywords; pinned → Recent → rest is unchanged for the empty query.
- Slash palette: keeps `rankSlashResults` ranking and marks `titleRanges(title, query)` (whole, word-start or initials matches only, so an alias or description match marks nothing); `revealInList` (`renderer/lib/reveal-in-list.ts`) replaces `scrollIntoView` so only the listbox scrolls, honouring scroll-padding. The composer's slash keys skip `isComposingKey` (keyCode 229).
- Announcements: `useDebouncedAnnouncement` (`renderer/lib/use-debounced-announcement.ts`) backs the slash palette's 180 ms count and a 500 ms "N results"/"No results" polite region in the palette and model picker list (silent for an empty query).

## Long pickers (Unit 4, plan row 4)

- Measured in jsdom before the cap: 1,000 models took 1.2 s to open the List, 140 ms per arrow key and 2.5 s to apply a typed query; 3,000 chats in the palette took 3 s, 430 ms per arrow and 21 s. cmdk mounts, registers and re-renders every item and `querySelectorAll`s them on each key. Capped: 1,000 or 3,000 models open in under 170 ms, about 16 ms per arrow, about 65 ms per query.
- `renderer/lib/list-limit.ts`: `useListLimit(page, resetKey)` (resets with the adjust-state-during-render form, so a key that comes back, like reopening or deleting back to an earlier query, also starts at one page), `limitRows(sections, limit, keep?)` → `{ sections, hidden, next }`, `showMoreLabel` → `{ title, detail, label }` (`label` is the option's `aria-label`, "Show 30 more, 30 not shown"). Pages: 100 models (`MODEL_LIST_PAGE`), 50 chats (`CHAT_RESULTS_PAGE`). Reset keys: picker `open:view:search`, palette `open:mode:query`.
- Cap, not virtualization: every row stays reachable by pressing Show more (End, Enter), the option count stays honest (rendered rows + Show more), and cmdk keeps owning selection. The reference SDK virtualizes with `aria-posinset/setsize` and keeps the focused row rendered; that would mean fighting cmdk's DOM-order selection.
- Show more selects `next` (the first hidden row) in the same render as the reveal. cmdk's item cleanup selects the first row when the unmounting item was selected (its cleanup runs before the new value syncs), so after the last page the Show more item stays mounted with `hidden` + `disabled` while `grown`. The palette's hidden item uses a disabled placeholder result and stays out of the selection inventory. The palette's Show more result is ordinary (not `forceMount`), so `reconcilePaletteResult` lets it be selected; the count adds `hidden - 1` back.
- The model picker's `keep` holds the current model and the highlighted one (`previewValue`) past the cap, in their place before Show more, so the current model is selected on open and Enter chooses it, and a row unpinned with ⇧⌘P that falls past the cap stays mounted. A keyboard pin or unpin then reveals the highlighted row (`revealInList` in a layout effect on `pinned`). cmdk's `aria-activedescendant` comes from its internal `selectedItemId`, which a controlled `value` never sets, so it is empty on open until the first arrow key, on any page (cmdk 1.1.1, pre-existing).
- Row actions (Pin, Pad): no longer buttons. `aria-hidden` spans with `title` ("Pin (⇧⌘P)"), mouse-only, visible on hover, on the highlighted row, or when active. ⇧⌘P / ⇧⌘A (Command = Ctrl off macOS, via `matchesAccelerator`) act on cmdk's highlighted row, only if rendered; the option has `aria-keyshortcuts` and its description says pinned / on the Pad and what each shortcut does. The shortcuts ignore `event.repeat` and IME composition (`isComposingKey`). `togglePin`/`toggleOnPad` resolve to the new state (null on failure), and Pinned/Unpinned/Added is announced only after the save, in a second polite region that is cleared first and set 100 ms later so a repeat is said again (cleared on open); a Pad removal relies on its Undo toast. The description span is `aria-hidden` (read through `aria-describedby` only), so the option's name is the model's. Listed in `built-in-keys.ts` ("In a chat") and docs/keyboard.md. This removed the `nested-interactive` axe exclusion.
