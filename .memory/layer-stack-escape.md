# Layer stack and IME-safe Escape (UI SDK lessons unit 1, 2026-11-19)

- `renderer/lib/layer-stack.ts`: module-level stack, no provider. `openLayer(kind, {name, onEscape})` returns `{isTop, close}` (close is idempotent); `useLayer(open, kind, options)` wraps it in a layout effect (StrictMode-safe: the double mount closes then reopens) and returns a stable `{isTop}`. `hasOpenLayer(match?)` and `isOverlayLayer` answer "is a dialog/menu/popover open".
- Kinds: `modal`, `menu`, `popover` (the Radix overlays), `sheet` (compact sidebar), `panel` (environment Quick View/tools, Bot panel). Covering rule (review fix): tiers panel < sheet < Radix overlays, whatever the order; within a tier the later layer covers, and panels never cover each other (focus picks which panel closes, as before). The tier stops a sheet that opened after a dialog (programmatic open) from trapping Tab or auto-focusing its first control; the sidebar's first-control rAF also checks `isTop()`. This replaced environment-panel's `[data-compact-sidebar-open]` sniff.
- Known limit, documented in `useLayer` and the design guide: layout effects run child first, so a nested layer opening in the same commit as its parent joins first and sits below it within a tier. Not fixed: Radix content is portalled, so DOM containment cannot order it.
- One bubble-phase document keydown listener exists while any layer has `onEscape`; it runs `isDismissKey` first, then calls uncovered layers newest first until one calls `preventDefault()`. Radix's own capture-phase Escape always `preventDefault()`s when it dismisses or is kept open, which is what stops custom layers under an open Radix layer.
- Registration in `components/ui.tsx`: `Dialog`/`AlertDialog` use their `open` prop; `DropdownMenu`, `Popover`, `Select` are now function wrappers that make the root controlled through `useRootLayer` (keeps `defaultOpen`/uncontrolled callers working); `ContextMenu` tracks `onOpenChange` only (no `open` prop). The command palette registers as `modal` named `COMMAND_PALETTE_LAYER` (command-system's foreign-dialog check), onboarding as `modal`. HoverCard, Tooltip and the info hint do not register.
- `renderer/lib/dismiss-key.ts`: `isComposingKey` (isComposing, nativeEvent.isComposing, keyCode 229), `isEscapeKey` (Escape, not composing), `isDismissKey` (also not defaultPrevented). Field-level `onKeyDown` handlers use `isEscapeKey` because the Radix layer around them already marked the key handled (workspace settings name revert relies on its dialog's `onEscapeKeyDown` keeping it open). Listeners that competed with others, and handlers that already checked `defaultPrevented`, use `isDismissKey`. Handlers with a combined `nativeEvent.isComposing` guard for Enter and Escape were left alone. `rich-link.tsx` was left as is (a link has no composition; a source-grep contract test pins its line).
- `keepOpenWhileComposing` in `ui.tsx` wraps `onEscapeKeyDown` on Dialog, AlertDialog, PopoverContent and the command palette: Radix's Escape does not check composition.
- `bot-computer-float.tsx`: "Escape docks" was already true via the shared `FloatingPlayerFrame` (device-mini-player); the screen's stream key handler `preventDefault()`s keys, so Escape on the screen goes to the VM. Comment clarified only.
- Left for later: `harness-runtime-section.tsx` still uses a window capture listener to beat the Settings dialog's Radix Escape; `sidebar/inbox-view.tsx` still watches the DOM for `[role=menu|dialog]` with a MutationObserver (tied to pointer re-checks after a menu's exit); no outside-press planning (no concrete Aiden bug).
- Tests: `renderer/lib/dismiss-key.test.ts`, `renderer/lib/layer-stack.test.tsx` (stack order, panel rule, Escape dispatch, StrictMode, a sheet under a real `Dialog`, composing Escape keeps the Dialog open, uncontrolled DropdownMenu registers), in `test:command-system` and the `renderer-other` CI lane. `focus-regions.test.tsx` and `chat-approval-card.test.tsx` open real layers instead of faking overlay DOM.
