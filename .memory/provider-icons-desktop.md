# Desktop provider and model marks

Every desktop surface that names a model or provider uses `ProviderIcon` (`renderer/components/provider-icon.tsx`), with `modelId` for model rows (Claude/Grok marks) and the provider's `artwork` for custom connections. The rule is written in `docs/design-guide.md` ("Model and provider marks").

- 2026-10-30 sweep (thread "Fix missing provider icons everywhere") fixed the places that showed a generic Bot/Server glyph or nothing: ⌘K Change model (models and "X models · Setup needed" rows), ⌘K Manage providers, the Bot model picker (Bot catalog ids are opaque `bc_provider_…`/`bc_model_…` grant ids, so the picker finds the real provider by a unique label match against `useProviders()`, which gives the logo id and artwork, and passes the model's display name as the Claude/Grok hint; an ambiguous label keeps the initial), the scheduled task Provider and Model selects, the paired-host model menu (`RemoteModelPicker`), the composer's "Sign out of a provider" list, the connector "Provider API key" select, and the chat Session panel's provider chip.
- The ⌘K model list and the scheduled-task model select now name models with `resolveModelDisplay(model, info)` from `useProvidersModelInfo`, the same cached names the composer picker uses (before: ⌘K showed humanized ids like "Claude Fable 5 1", scheduled tasks showed raw ids like `glm-4.6v`). The Session panel's model chip also uses the display name.
- Test harness notes: `BotModelPicker` now needs a QueryClientProvider (its test seeds `queryKeys.providers`); `installBotTestIpc` answers `providers:list` with `[]` by default. `composer-attachments-mounted.test.tsx` bundles composer.tsx with esbuild and must stub `./provider-icon` (its `new URL(..., import.meta.url)` asset URLs break the CJS bundle).
- Pi providers with no bundled logo (initial fallback) as of Pi 1.4.0: baseten, meta, qwen-token-plan, qwen-token-plan-cn, qwen-token-plan-individual, radius, typesafe. Adding one means an SVG in `renderer/assets/provider-logos/`, the slug lists on desktop/iOS/Android, the Android generator, and the NOTICE files.
- iOS Bot model rows get the opaque catalog id too, so `AidenProviderIcon` there shows the initial. The earlier `modelID:` change was a no-op and was reverted; giving iOS real marks needs the label match (or a display slug in the catalog) on iOS, not done.
