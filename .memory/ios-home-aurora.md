# iOS Home and Aurora (Phase 2 lane)

Branch `claude/ios-home-aurora`. Plan: `docs/plans/ios-new-direction-upgrade-plan.md` (Phase 2 progress is the source of truth).

## Home
- `Features/Shell/AidenHomeView.swift`: `AidenHomeHeader` (greeting, sprites, "From your Bots"), `AidenHomeFeedModel` (shell-owned in `AidenAppShellView.Built`, refreshes every 60 s while Home shows and on pull to refresh), `AidenHomeComposerSlot`.
- Ranking and states live in `Models/AidenHomeDigest.swift`: needs you > failed > working > news; news cutoff `newsWindow` (24 h) via `since:`; `AidenHomeBotsState` (bots, loading, noBots, offline, none) and `AidenHomeFeedState` (rows, loading, failed, offline, partial, quiet). "Nothing new" (quiet) needs every shown machine to have Home's own full read (`reader.hasFullRead`, i.e. a cursor); the notifier records delta pages without a cursor, so they never count. A connected machine with no outcome is loading; skipped/failed count as failed; known-offline or revoked counts as offline.
- `AidenBotRoutineFeedReader.shared` is shared with `AidenScheduledRunNotifier`; `beginFetch`/`waitForFetch` dedupe a machine's fetch. `forget(instanceId:)` runs from `purgeInstallationDataUnlocked` (unpair) and on narrowed grants.
- Send: `AidenNewWorkChatFlow.startChat(sending:on:)` creates a Just chat on exactly `homePicker.target` (separate from New chat's picker). `aim` picks the last-used machine but leaves a hand pick alone (it remembers what it last set). The shell's `onCreated` only queues the launch send for Home's sends; `AidenHomeComposerModel.place` (set by the shell: `isOnHome` = Chats tab with an empty path) decides whether to open the chat — only the latest Send, only on Home — else the "Chat started. Tap to open it." notice (`home.composer.ready`). Each Send is its own Task with its own prompt; failure gives the words back via `AidenDraftSendReconciliation.failedDraft`. `.needsChoice` (no Chats home) only restores and shows a notice. Model writes set `ownWrite` so the view's `.onChange` → `textChanged()` doesn't clear the notice. The saved draft (`aiden.home`/`composer`) holds in-flight prompts ahead of the field until their chat exists. `startChat` re-checks `isLive(owner)` before `onCreated`. r1: `queueLaunchSend` sets `hasLaunchSend`, so `load` saves the composer's current text over the seeded stored draft instead of restoring it (no words back, no second send); `finish(.started)` saves Home's draft with `scheduleSave(immediately: true)`. `isOnHome` stays `chatsPath.isEmpty` because the split selection is `chatsPath.first`. The composer slot is an `.contain` container, so UI tests find the field inside `home.composer`. The demo host answers `POST /chats/chat_demo_new/turns` by echoing the sent text and holds that stream's events, so `testHomeSendStartsAChat` sees the words in the transcript.
- See all: Catch Up when something waits, else the Bots tab (no Inbox Bots filter on iOS). "Make your first Bot" opens the Bots tab.
- Follow-ups noted in the plan: m2 grant back-fill, m3 away line after fold, m4 See all to unrelated Catch Up, m9 demo body read under lock.
- Deferred: onboarding name field, spec composer controls (U-m4), Hi-bit until #925 merges, `setVoice` wiring (Listening from Home).
