# Bot memory and soul (Track A, 2026-10-09)

Spec: `docs/superpowers/specs/2026-10-09-bot-memory-soul-proactivity-design.md`. Plan: `docs/plans/2026-10-09-bot-memory-soul-proactivity.md` (Track A).

## Layout (`main/services/bot-memory/`)
- `files.ts`: `<profile>/bots/<botDirectoryName(id)>/memory/{MEMORY.md,USER.md}`, `\n§\n`-separated entries. Usage = length of the serialized valid entries (the fixture's `usedChars` 58/68 are off by one; real values are 59/69). Entry id = first 16 hex of sha256(target + "\0" + text). Revision = first 16 hex of sha256 over both files' bytes. Strict UTF-8 decode; any unreadable file makes the whole memory `readable: false`.
- `scan.ts`: original threat/secret scan (invisible/bidi code-point ranges on raw text; NFKC + lower-case patterns for override, role hijack, exfiltration, persistence, secrets; Luhn 13–19 digits, repeated-digit placeholders ignored). Emoji ZWJ and variation selectors are allowed. Person copy: `BOT_MEMORY_BLOCKED_MESSAGE`.
- `store.ts`: per-Bot keyed promise queue; validated reads (blocked, oversize, delimiter and duplicate entries dropped); `apply` (tool batch, budget on the final state, refused only when the final state is over the limit AND the batch adds or grows; remove-only batches may still shrink an over-budget store; `addOnly`); `edit` (person: replace/remove by id, clear). Writes rewrite from validated entries, `writeFileAtomic` mode 0600, and create `memory/` **non-recursively**, so a deleted Bot's directory is never resurrected (`BotMemoryDeletedError`). `forgetBot` refuses later writes.
  - Undo rule: a `replace` whose `entryId` is missing but equals `memoryEntryId(target, text)` re-adds the entry (Delete → Undo). Any other missing id is `entry_not_found`.
- `service.ts`: `view`, person `edit` (marks the snapshot stale + announces), tool `apply` (announces only), `snapshot` (cached until `beginSession`/`markStale`), `forgetBot`, `onChanged`. `bot-memory-main.ts`: lazy singleton `botMemory` (safe to import before app ready) + Step 0 `botMemoryService`; pushes `bots:memory:changed` to all windows.
- `tool.ts`: `bot_memory` (flat TypeBox ops `{action, content?, match?}`, 1–8), JSON result, `isError` on failure, `details {changed, targets}`. `withBotMemoryIngress(botIngressAllowsTool)` withholds it on `routine:` and `intro:` runs. Replay `unsafe`; `checkPolicy` short-circuits to allowed in `bot-session-main`.
- `prompt.ts`: `renderBotMemorySection(snapshot, {memoryOffered})`; escaped via the exported `escapePromptText` (`bot-system-prompt.ts`).
- `review.ts`: `runMemoryReview` (one-off `Models.completeSimple` loop, add-only tool, newest 16,000 chars) and the scheduler (`afterReply` 10 s debounce, `runNow`, `cancel`, `shutdown`). Person inputs are counted from the transcript since the newest `aiden.memory-review` entry or successful `bot_memory` result; a `routine` / `hidden_input` notice marks the next `pi.user` as unattended. Failure writes `{failed: true}`; cancel writes nothing.
- `compaction.ts`: `beforeCompact` steering = flush (add-only review, 20 s, 2 rounds, marker only when something was added) → steered summary (Pi Durable's prompts borrowed with MIT attribution + `BOT_COMPACTION_FOCUS`) → `markStale` in `finally`. Any summarizer error returns `undefined` so Pi summarizes itself.

## Runtime wiring
- `bot-extension.ts`: `BOT_SECTION_KEYS` gains `aiden-memory` last. **Deviation:** the memory section renders per request through `deps.memorySection(botId, {memoryOffered})` instead of a fifth `systemSections` string, so a compaction mid-turn and routine-turn withholding take effect on the very next request; `systemSections` still returns 4 strings. `onYield` calls `deps.afterReply` (never awaited); `hook(CompactionTask, {beforeCompact})` delegates to `deps.beforeCompact`.
- `bot-session-service.ts`: `onSessionOpen(botId)` fires from `buildRegistry` on every harness open (first use, after idle close) → `memory.beginSession`. `compactionInstructions` + `BotSessionRuntime.compact(botId)` (manual compaction with the focus; Telegram `/new` is not wired to it yet).
- `bot-session-main.ts`: memory tool appended to `currentTools`, review + compaction steering wired, delete effect (`review.cancel` + `forgetBot`) right after the live projection closes, `review.shutdown()` on quit, and `setBotFileToolProtectedRoots(<userData>/bots)`.
- `live-projection.ts`: `memory_update` from a successful `bot_memory` result with `changed > 0` (id `<entry>:memory`, source `turn`) and from `aiden.memory-review` with `added > 0`; `aiden.routine-proposal` cards fold the newest status entry; status entries are hidden. Memory and proposal entries survive a `[SILENT]` turn.

## Legacy removal (A9)
- `MemoryScope` is workspace-only; `scope_kind='bot'` rows are deleted on every open (CHECK constraint untouched). `memoryScopeForChat` throws for a Bot chat; `llm-client` never builds workspace memory for Bot chats; `chat-renderer-mutations` no longer deletes a Bot scope (its `memoryStore` dep is gone — `main/handlers/chats.ts` must stop passing it).
- `bot-file-tool-router.ts`: `write_file`/`edit_file` refuse any target whose real path (nearest existing ancestor resolved) is under a protected root; `protectedRoots` option, process default set by `bot-session-main`. Reads are not fenced.
- `openingGreeting` removed from `BotDefinition`, `BotCreateInput`, `BOT_LIMITS`, store normalization (legacy key ignored on read, deleted on the next update; a too-long legacy greeting no longer drops the Bot), `bots:create/update` params and `ChatStore.create` (`initialAssistantMessage` gone).
