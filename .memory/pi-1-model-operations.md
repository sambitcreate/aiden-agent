# Pi 1.0 desktop model operations

Ordinary attended workspace chats now receive `list_operation_models`, `generate_image`, and `classify` using the active runtime's authenticated Models authority. Custom chat-only runtimes correctly list no secondary operation models. Inventory exposes bounded public image/classifier metadata only; tools accept no endpoints, credentials, auth options, or refresh operations. Provider/model identities are type-checked before dispatch. Classification uses bounded JSON with upstream choice/score/bool schemas and validated answers.

Paid operations are disclosure approvals even under Full permission, callable through the normal nested codemode host, and never crash-replayed. Inventory is safe to replay. Every actual provider attempt reports local usage once at the provider boundary, including failures and cancellation; codemode aggregate results are not charged again. Response token totals add only the individual paid-operation events, never the aggregate parent event. Local ledger failure cannot suppress a paid result or replace a provider failure.

Generated raster images share the existing display-image runtime's serialized per-response/chat count, byte and decoded-pixel budgets. Both image sources use the same artifact staging, deduplication, terminal recovery and chat:artifact payload. Generated image identities combine generation, call and content; no network download is added. Images are validated before presentation; failures after successful inference retain usage. Earlier successfully staged images in a partially failing batch remain recoverable by the established artifact lifecycle.

Onboarding's existing Model Freedom and Attachments & Vision tiles disclose classification/image generation and approval/charges; their existing illustrations remain appropriate. No new native wire fields or client rendering contracts.

Coordinator ran Android AidenChat 62 and iOS AidenChat 230 tests successfully. Coding tools 55/56 passed; existing `foreground glob agrees with native glob on normal patterns, hidden paths and safe links` fails for **/* because foreground traversal follows in-root links while this Node native fs.glob oracle excludes them. One targeted rerun reproduced it; no timeout or assertion weakening. This lane does not alter glob implementation.

Reference-image parity: `list_image_references` exposes metadata for current-generation admitted chat images and images presented in the current response. `generate_image.referenceImageIds` accepts up to four IDs, never paths, URLs or model-provided base64. The host checks original transcript identity against fresh same-chat persistence; removed, changed, foreign and colliding identities fail closed. Reference inputs share an 8 MiB/40-million-pixel bound, are validated before provider dispatch and require model image-input support. The paid disclosure names each image/ID and actual decoded bytes before approval; dispatch resolves again. The same image-artifact and usage paths handle edited outputs.
