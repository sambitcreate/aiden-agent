# Saved helper conversations — 2026-11-22 (helper chat plan, Phase 2)

Plan: `docs/plans/subagent-helper-chat-plan.md` (PR 2 section). Branch `claude/subagent-helper-chat`; Phase 3 (the side-panel helper chat UI) reads what this phase saves.

## Shape

- `renderer/shared/subagent-transcript.ts`: `SubagentTranscriptV1` {version 1, runId, revision, trimmed, entries}. Entry 0 is `{kind: "task", text}`; later entries are `{kind: "message", text, steps: AgentStep[], startedAt, finishedAt?}`, using the main chat's `GenerationTimeline` step format. Strict parsers for the transcript, the live update and the `{streamId, update}` notification. Caps: 2 MB serialized, 600 entries, 200k chars of text per entry.
- Live update `SubagentTranscriptUpdateV1`: {runId, baseRevision, revision, trimmed, entryCount, changes[{index, entry}]}. Only changed entries are sent; the current message is re-sent whole on each update.
- Late joiner: subscribe first, then read the saved copy; `mergeSubagentTranscript(saved, live)` returns `{transcript, complete}` (`complete: false` on a revision gap). `foldLiveSubagentTranscript` keeps the newest 16 runs per window.

## Recording

- `subagent-transcript-recorder.ts` maps Pi events as the main chat does (`observe`: thinking, `toolcall_start` as a pending step, text with content offsets, `message_end` with `terminalAssistantActivityAnchors`, tool update/end with `result.details`), or takes the CLI's direct calls, into `GenerationTimelineProjector`. MCP tool labels are not special-cased (left as the generic label); `textStart` is 0 because text is per message; reasoning is not stored, so reasoning segments are not reconciled. Terminal status follows the main chat: cancelled once the runner calls `cancelling()` (before each `child.cancel` and on parent abort), blocked when the wrapped `beforeToolCall` refused the call (`toolBlocked(id)`; CLI: the approval rejected while the helper was not stopping), else failed/completed. In the CLI, as on the desktop, a tool that ends after the stop (even successfully) shows as cancelled. A failed final save is always reported once, even after an earlier failure was. Throttled to 250 ms with backoff after failures (2^n steps, cap 20); failures are reported once per run of failures and retries pause after `SUBAGENT_TRANSCRIPT_RETRIES_BEFORE_PAUSE` (5) until the next change; one save in flight at a time; revision 1 (task alone) is enqueued from the constructor.
- Each revision is persisted, then published. A failed persist publishes nothing, keeps the state dirty and retries; the final save tries 3 times, with unref'd backoff timers. Revision numbers advance only on a successful save, so the stream always chains.
- Trimming uses cached per-entry sizes (`trimSubagentTranscriptToBytes(..., entryBytes)`), and what a trim dropped is applied back to the recorder (closed messages frozen, dropped step ids and characters remembered), so later saves never bring it back.
- Text and every step string (label, target, detail) go through `sanitizeSubagentWorkText` (`subagent-work-text-filter.ts`, built on `sanitizePartialFindingsForParent`), the parent/helper credential filter: `[REDACTED CREDENTIAL]` / `[REDACTED]`, private key blocks (complete or cut off) hidden, same-line secret-named values (`OTP:`, `PIN=`, `PASSCODE:`, `CVV:`, `SEED:`) hidden, wrapped secret tails and recovery phrases hidden, prose such as `OTP: sent by SMS` or integer seeds kept, paths kept. The panel's `sanitizeVariant` also runs `redactSecretNamedSameLineValues`. Not the panel's `sanitizeSubagentSnapshotText`. While a message streams, `streamingVisibleText` holds back the unfinished last word and any open `-----BEGIN` block. Sanitizing is per entry, so a secret split across two entries is not caught. The filters are best-effort heuristics and cannot catch every layout. Round 3 coverage: phrase names after a leading word ("Secret recovery phrase", "My seed phrase"), "seed words", unindented/numbered/split/other-case phrase blocks (`redactUnindentedPhraseBlocks`, standard lengths 12–24 preferred) and unindented recovery codes; weak names (`otp`, `pin`, `cvv`, `seed`, `signature`, `private`) keep only values in `PLAIN_WEAK_VALUE` (algorithm/type/method words), and "PIN code"/"PIN number" are names; token counts (`max_tokens: 4096`) and path/file/version lines after a hidden value stay. Wrapped tails (`isWrappedSecretTail`, shared by both filters; the panel runs `redactWrappedSecretTails` too) chain, and accept a 16+ character piece without digits or a first token followed by a space. Known limit: a tail that reads as one capitalised word with punctuation ("Word.") is kept, because it cannot be told apart from "Done.".
- Edits: the helper's `write_file`/`edit_file` (`subagent-workspace-write.ts`) return `file_line_changes` details; the desktop passes `result.details` through `observe`, the CLI forwards them in `subagent-process.ts`, so steps carry `lineChanges`.
- `SubagentTranscriptRecordings` in `subagent-supervisor-core.ts` wraps every child (in-process and inference-process helpers). It hands the result back without awaiting `finish` (the final save is tracked and awaited by `supervisor.flush()`), and the supervisor's seal settles a recorder whose child never returns. `supervisor.flush({ transcriptWaitMs })` caps the transcript wait; `llm-client` passes `SUBAGENT_TRANSCRIPT_TURN_END_WAIT_MS` (250 ms) before `appendMessage`, while the CLI flushes fully before closing its store. On quit, `main/index.ts` waits up to 1 s (`SHUTDOWN_BUDGET_MS.subagentConversations`) on `flushPendingSubagentTranscripts()`, a module-level set of every pending final save across chats and Bots, once after the subagent runtime stops and once after the Bot runtime stops. `transcriptStatus` maps interrupted and timed_out to cancelled, other non-completed statuses to failed. CLI recorder calls are wrapped so a throwing recorder is reported once and never breaks the helper.

## Storage and deletion

- `subagent-transcript-store.ts`: `<root>/transcripts/<sha256(chatId)>/<runId>.json`, mode 0600, `writeFileAtomic`, 512 per chat (oldest by mtime pruned; stale `*.tmp` files older than 60 s from a crashed save are removed first). Reads: O_NOFOLLOW, size cap, strict parser, runId must match. An in-memory deleted fence refuses late writes after a chat delete.
- Desktop root `userData/subagent-runs-v2`. `subagentRunStore.deleteChat` removes transcripts early (best effort); `completeChatDeletion` removes them first and rethrows, so the tombstone stays for `reconcilePendingChatDeletions` on the next start.
- `subagents:get` returns `transcript` only after ownership is proven (the request comes from an active app window, the run belongs to that chat and workspace, and the chat's history references the run), asked with the owning chat id. A run the current turn still tracks under the same chat, workspace and generation can also be read (late join, before the history references it). No window-to-chat binding exists, so any live app window can read a chat it names.
- Live stream `chat:subagent-transcript`, sent only to the owning window, not journaled.

## Bots and the CLI

- Desktop Bot helpers record through the same factory; there is no read path for them (Bot runs have no history snapshot view).
- `aiden serve`: `bot-subagents.ts` saves under `<agentDir>/bot-subagent-history/<sha256(chatId)>/transcripts/…` with chat key `cliSubagentIdentity(chatId)`; `deleteCliBotSubagentHistory` removes them. Thinking steps are not recorded there. No Remote protocol revision was claimed; phones get nothing.

## Correction to the Phase 1 notes

The panel label rule is not an allow-list. `colonBlockNameIsLabel` accepts a bare all-capital word of letters with no secret hint; `blockNameHasSecretHint` applies the secret-ending match only to setting-shaped names (all caps, `_`/`-`, or camelCase) and otherwise needs an exact secret word, plus a few whole names and a whole-segment `PIN`. The plan's Risks row now says this.

# The helper chat — 2026-11-22 (helper chat plan, Phase 3)

Plan section "## The helper chat". Same branch; all three phases ship as one PR.

## Where it lives

- `renderer/components/subagent-helper-chat.tsx`: the read-only chat for one helper (header with status dot, name and "Role · Status · elapsed"; the task as the first bubble; each message drawn with the main chat's step rows via `subagentHelperTimeline`; problem box with **Ask the main chat to retry**; bottom bar with Stop, Expand, Technical details). `subagent-helper-chat-expanded.tsx` fills the main pane (composer hidden; Back or Esc returns focus to the opener).
- `renderer/lib/subagent-helper-chat-state.ts`: pure helpers (tone, active, work summary, problem text and retry request, `subagentHelperApprovalFor`, timeline). `renderer/lib/subagent-helper-chat-store.ts`: per-chat store (saved copies, live updates merged with `mergeSubagentTranscript`, refetch on a revision gap, approvals routed to the main chat's handler, expanded run and opener). `chat-pane.tsx` and `environment-panel.tsx` wire it; `subagents-panel.tsx` and `subagent-detail.tsx` show it in the side panel, and the old summary view only as the fallback for helpers with no saved conversation (what it was asked, what it did, result; the context line moved into Technical details).
- `ui.tsx` ScrollArea gained a `bodyReplacement` path so the expanded chat stays visible (covered in `scroll-area-follow.test.tsx`).

## Status words

- One set everywhere: Queued, Running, Waiting on you, Done, Failed, Stopped (`STATUS_LABELS` in `subagent-view-state.ts`; starting→Queued, timed_out→Failed, interrupted/unknown→Stopped). `subagentStatusCounts` builds every count summary (card header, pill, overview, live announcement) in the order Waiting on you, Running, Queued, Failed, Stopped, Done. Status groups: Running, Waiting on you, Failed, Stopped, Done (unknown is Stopped). Stale leads: "Still running", "Still queued".
- A helper asking for a run grant stays `running` in its record ("Preparing a workspace update"). While it holds a matched approval, `withSubagentApprovalWaitSnapshots`/`withSubagentApprovalWaitViews` overlay a display-only `needs_attention` (returning the same array when nothing changes), so the helper chat, card rows, pill, tray and Subagents list all say "Waiting on you" in the window running the chat (approvals live there). The overlay matches by run id, or by label only when the helper is active and no other helper (of any state, judged against the full helper views) shares it; the main working line also reads "Waiting on you". `subagentHelperApprovalsFor` returns every approval the helper owns (in queue order); all of them are excluded when deciding whether the main chat waits on something else.
- Writing step: "Writing its report" while it runs, "Wrote its report" once done (the projector no longer adds a duplicate milestone).
- The pill's narrow fallback and aria label still say "N finished" for a settled batch (a batch word, not a status word).

## Round 2 decisions (2026-11-22)

- Approvals: the main chat's card is canonical. The side panel shows a compact row ("Needs your approval in the main chat.", or "…, after 1 other request." / "after N other requests." when others are ahead in the main queue; Go to approval, or Go to main chat when others are ahead → `focusMainWaiting("approval")`, see Round 4); the full card renders only in the expanded helper chat. `mainChatWaitingFor(state, ownIds)` picks what the bar points at: "approval" when the main card's first approval is not this helper's, else "question" when one is pending, else "approval" if any later approval is someone else's. So Go to approval never lands on the helper's own card when a question waits.
- Waiting bar (expanded only): `Callout role="note"`, warning fill, no border; "The main chat needs your approval." / "The main chat has a question for you."; one polite announcement via `announceSubagentDetail`; button Go to approval / Answer question calls `store.returnToMainWaiting(kind)`, which collapses then focuses on the next frame (approval: the main approval card itself; question: `focusRegion("composer")`, where the questionnaire carries `data-focus-region="composer"` and an entry on the current option or custom textarea).
- Back: the footer Back to main chat is the only Back; the side-panel placeholder reads “<label>” is open in the main chat, with no button.
- Stop vs Stop all: `subagentHelperHasActiveHelpers(runId, views)`.
- Failure reasons: `subagentFailureReason` maps the runner's "the child …" sentences to plain ones (`RUNNER_REASONS`), drops duplicates, passes unknown reasons through.
- Second windows: `subagentHelperTranscriptRefetchReason(run, merged, streamingHere)` gives `gap:<rev>`, `join`, or `run:<state>:<revision>`; a window without the live stream re-reads the saved copy on each new reason, including the terminal state. A failed read (late join or re-read) shows the refresh-error row with Try again (`SubagentDetail refreshErrorKind="conversation"` for the no-transcript fallback).
- Model line: `subagentModelDisplay` is depth-aware ("Same as main chat" at depth ≤ 1, "Same as the helper that started it" deeper); Effort hidden when off; Technical details show tokens with `toLocaleString`, the model name and a copyable run id.

## Known limits

Other approvals are out of view while a helper chat is expanded (the waiting bar points to them) and their shortcuts are off; with two approvals queued, own first, Go to approval focuses the main card, which shows the helper's own first (its queue count shows the rest); a running helper that missed early updates shows the fallback until its next save; the timed_out warning colour folded into red.

## Round 3 decisions (2026-11-23)

- Covered surfaces: `SurfaceCovered` (in `ui.tsx`) marks content that something else covers; `HoverCardContent` and `Tooltip` render nothing inside it, and a covered parent keeps nested surfaces covered. `ScrollArea` wraps its body while `bodyReplacement` shows (the expanded helper chat), (superseded in Round 4 for the narrow floating panel). This replaced the chips' own special case, since Radix layers over the hidden body swallowed Esc.
- Collapse focus: back to the opener, else the same helper's new Expand button (`data-subagent-helper-expand=<runId>`), else the message box.
- Transcript re-reads go through `subagent-transcript-reader.ts`: one read in flight per run, at most one a second, reasons coalesced. Only a rejected read shows "Couldn't load" with Try again; an empty answer means nothing is saved yet, and a failure clears once the conversation arrives by the live stream or the run's own detail read.

## Round 4 decisions (2026-11-23)

- Covered surfaces: `SurfaceCovered` now marks only the expanded helper chat (`ScrollArea` `bodyReplacement`). `DialogContent` (inside its content since Round 5), `AlertDialogContent` and `PopoverContent` reset it to false, so an overlay opened from covered content shows its own tooltips. The narrow floating side panel no longer covers the transcript: `DismissHoverSurfaces when={transcriptUnderFloatingPanel}` in the chat pane closes open hover cards and tooltips once when the panel opens (the `HoverCard` wrapper and `Tooltip` use `useDismissibleHoverOpen`), and the visible strip shows them again on the next hover.
- Copy: the side-panel row says "Needs your approval in the main chat." so "waiting on you" appears once (the header). When others are ahead the button reads Go to main chat.
- Go to approval calls `revealApprovalCard` (`chat-approval-card.tsx`): focus the card (`preventScroll`), `scrollIntoView({ block: "nearest" })` (smooth, or at once under Reduce Motion), and a 1.2 s `[data-approval-arrival]` tint from `--status-accent` mixed into `--surface-popover` (held still, without the fade, under Reduce Motion; see Round 5).
- Button type size: `text-*` on a `<button>` has no effect because the unlayered `button, input, textarea { font: inherit; }` rule in `styles.css` beats Tailwind's `@layer utilities`; size helper-chat buttons by putting `text-small` on their container. Known systemic issue (moving that rule into `@layer base` needs an app-wide visual pass).
- Transcript reader: `switchChat(chatId)` keeps reads when the chat is unchanged; a rejection that `noteLoaded` already covered counts as success; a skipped request settles with `null` (clears a failure); the panel resets the reader on unmount and only subscribes to the store while a failure may need clearing.
- Label-only approval matching applies only to an active helper, so a finished helper with a reused label never claims a new write approval.
- Onboarding Helpers tile: at the narrowest gallery widths (about 140 px tiles at a 561 px window, 157 px at 421) the raised Implementer chat at `left: 154` and its live dot sat fully outside the art. It was anchored `right: 10` with a `min()` width; Round 5 replaced that (below). Checked in light, dark and Reduce Motion in a Cua Space at 561, 560, 421 and 390.

## Round 5 decisions (2026-11-23)

- Dialog exit animation: a context provider placed directly under a Radix `Portal` drops the ref `Presence` reads, so the dialog unmounted at once and skipped its exit animation. `DialogContent` and `AlertDialogContent` now reset `SurfaceCovered` with `UncoveredSurface` inside the Radix `Content`, as `PopoverContent` does. `focus-return.test.tsx` checks that a closing Dialog and AlertDialog stay mounted with `data-state="closed"` until `animationend` (happy-dom needs a live `getComputedStyle().animationName` and a `CSS.escape` shim).
- Approval tint: 1.2 s, eased with `--motion-decelerate-easing`; under Reduce Motion the tint holds still for the same 1.2 s with no fade, and `revealApprovalCard` removes `data-approval-arrival` after 1.2 s either way.
- `ChatApprovalCard` was keyed by `approvalId` at its call sites, so a new approval never inherits the old card's state. Round 6 moved the key inside the card (below).
- Environment panel: the "a transcript re-read may have failed" ref is set from each `setTranscriptRefetchFailures` updater's result (`withFailureFlag`), not from a passive effect.
- Onboarding Helpers tile: the art sits in `.oa-sub-stage` (`container: oa-sub / inline-size`). Below a 200 px tile the raised chat (`.oa-sub-chat`) drops to `top: 56px` and runs off the right edge (`right: -12px`), so the heading and the selected row stay visible; the one-column 390 layout is unchanged. Below 150 px (the 561/560 px window) `.oa-sub-state` is hidden, since the status word would be clipped. Round 6 replaced these breakpoints (below).

## Round 6 decisions (2026-11-23)

- `ChatApprovalCard` keeps one stable sr-only `role="status"` line (and the `LiveGuard`) outside an inner body keyed by `approvalId`, so each new approval is announced by a text change on the same live region and the body (including form-fill ticks) starts fresh. Callers (`chat-pane.tsx`, `remote-chat-view.tsx`, the helper chat) no longer key the card. `ComputerUseAccessApproval` lost its own `LiveGuard`, wrapper and status line, since the card now provides them. Focus is unchanged: Deny on arrival, return on close.
- The round 3 "Request from <requester>: Review before <tool>" region name broke the Bot tests' name queries; `bot-chat-pane.test.tsx` and `tests/e2e/bot-access-requests.spec.ts` now query the prefixed name.
- `scroll-area-follow.test.tsx` checks that a popover, a Dialog and an AlertDialog opened from a covered transcript are surfaces of their own with working tooltips.
- Onboarding Helpers tile breakpoints (container `oa-sub`): the list window is `left 10, width 150` (right edge 160) and the wide chat `right 10, width 136` clears it only at a 306 px tile. At `max-width: 259px` the chat opens under the selected row with `top: 60px; left: 16px; right: -12px; width: auto`, and its header More icon (`.oa-sub-more`, scoped `.oa-sub-chat .oa-sub-more`) is hidden. `.oa-sub-state` is hidden below 160 px and from 260 to 305 px, where a status word would be cut.
