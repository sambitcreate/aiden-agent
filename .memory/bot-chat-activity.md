# Bot chat activity (2026-10-14)

Spec: docs/superpowers/specs/2026-10-14-bot-chat-activity-design.md (§17 lists the slice B rulings). Slice B plan: docs/superpowers/plans/2026-10-14-bot-chat-activity-b-status-line.md. Branch `claude/bot-chat-activity-b-status-line`, stacked on PR #475.

## Slice B (desktop) — what shipped
- Phase vocabulary and tool classifier: `renderer/shared/bot-activity.ts` (shared with main, the CLI, and slice D's phones). Unknown ids → `working`. Always "Thinking" keeps waiting/stopping/reconnecting.
- Main derives `BotLiveSnapshot.activity` + `activity` event in `live-projection.ts` (`liveBotActivity`), gated on session state `running` (a paused Bot still has `pi.live.run`). Stop reaches it through `notifyStopping` in the `bots:stop` handler; Resume reaches it through the service's `onResumed` callback (`bot-session-main.ts`) → `notifyResuming`, so a Resume from any surface marks it; approvals refresh it via `botApprovals.onChange`.
- Run identity is the run's first input (`inputs[0]`), not the generation task id. Resume is marked by the service's `onResumed` callback inside the per-Bot serialize; Stop/Resume flags are run-scoped (a double Stop never leaks "Stopping" into the next turn). `startedAt` renews for a queued follow-up turn.
- Transcript tool calls carry `kind/label/detail/app` (`bot-activity-detail.ts`). Command steps never show the command: only the model's `description`, redacted with `sanitizeDiagnosticText` before cutting to 80. Tool results carry `status: ok|failed|blocked|stopped` (Pi's `blocked` diagnostic; `stopped` for Stop/restart, rendered neutrally) and `durationMs`.
- `BotDefinition.chatActivity?` `{ level: quiet|summary|detailed, wording: follows|thinking }`; absent = Quiet/Follows; an update without it keeps the stored value. It is stored last in the Bot record (the revision hashes the record JSON); identity updates merge a partial `chatActivity` onto the freshly read Bot. Remote identity PATCH still rejects it (slice D).
- Renderer: `BotStatusLine` (hides only while reply text streams with no active tool step; the visible line is a `role="group"` named by its words; announcements go to `BotStatusAnnouncer`, one always-mounted, initially empty `role="status"` region in the pane that clears while words stream, 2 s throttle), `BotActivityRecap` (Bot-specific, not ActivityFeed), progress narration as bubbles (`BotUpdates` and `bot-reply-projection.ts` deleted), "You stopped this reply." derived from an `aborted` reply or a `stopped` tool result (a Stop during a tool run writes only the round's results; a later `interrupted` notice turns it back into a restart). The still-going note hides while the line reads Waiting or Stopping. Every user entry begins a turn (pi-durable places steers after a round's tool results).
- Queue/Steer: `pi.inbox` projected as `snapshot.queued` — the person's own inputs only, classified by durable submission requestId (`routine:`/`intro:`) plus the hidden flag, failing closed. Follow-ups show faded with Remove (`bots:withdraw` → `Harness.abortSubmission`: withdrawn | started | gone); steers are normal bubbles.
- Advanced → Chat activity (`?page=chat-activity`, `bot-chat-activity-page.tsx`): saves on pick through a serial queue, per-level Reduce Motion still frames, Reduce Motion read live.
- `BotAvatar` faces glance via `data-working` with a shared off-screen observer; list's green dot removed. Under Reduce Motion (setting or OS) a working face holds the glance's look-aside pose (`translateX(-2.6px)` on the eyes, no animation), so it still differs from idle.
- Onboarding: the Bots gallery tile (`BotsArt`: name pill, one exchange, routine chip) shows neither the list nor the Updates line. C2 changed only its header (panel toggle instead of a back chevron).

## For slice D (phones)
- Remote wire is unchanged by B. D adds `activity` (phase, app ≤ 40, startedAt only) to the session stream and `chatActivity` to detail/PATCH behind `bot-activity-v1`; reuse `botActivityDisplay`, `botElapsedLabel` and `nextBotAnnouncement` semantics and the §5 table as the shared fixture.
- Remote Stop bypasses the `bots:stop` handler, so a phone Stop doesn't show Stopping on the Mac; D's planned `botTurnIntents` covers it. A phone Resume already shows "Picking up where it left off" on the Mac (the same runtime resume fires `onResumed`).
- Choosing Chat activity changes the Bot revision, so a phone's next identity edit gets `revision_conflict` and refreshes (safe).

## Follow-ups and deferred minors
- Pre-existing on main: adding a description to a Bot that had none gives a save/reload revision mismatch (projectBot key order vs update append), a spurious conflict after restart. A canonical-JSON hash would fix it but changes every revision once.
- Accessibility: the always-mounted status region is in place (final fix wave); it still needs a manual VoiceOver check before merge.
- `botToolApp` derives the app label from the sanitized MCP tool name (lossy for punctuation or ~50+ char names); a real label from `facts.mcpTools()` would be better. `botToolPhase(toolName, app?)` gives `working` if `app` is forgotten.
- Untested step phrases (editing, photo, computer, helper, remembering plural, routine, waiting, working); "Using an app" fallback is not in the spec.
- Model-authored command descriptions pass only the generic redactor (a repeated `-pSecret` flag would show). Infrastructure throws in `checkPolicy` also yield "blocked".
- Recap: rows/header are not memoised per partial delta; `aria-controls` points to an unrendered region; truncated header has no title; `durationMs` default 0 shows "Worked for 1s"; missing tests for non-adjacent repeats, interrupted-with-unfinished-call, toggle across turn change; stale previous-turn recap when running precedes the new user entry.
- Transcript: live recap may jump after commit when the partial becomes narration; possible one-frame duplicate partial/committed bubble and remount flash on commit (key "partial" vs entry id) — check manually; desktop no longer de-dupes repeated paragraphs (phones still do).
- Queue: Remove focus moves before the withdraw resolves; the fade couples to `MessageBubble`'s private `bg-control` class (prefer a variant prop); the hidden flag is not durable (latent); a missing-id streak is never logged; no backoff on permanent inspect failure (1/s per live feed); an `openFeed` failure could orphan a retry timer.
- Runtime: `deps.state` rejection at run end leaves `{preparing}` stuck (pre-existing fallback); interrupted-with-run and approval-flip lack projection-level tests; `onResumed` → projection wire (`bot-session-main.ts`) is untested end to end and unguarded inside serialize.
- Chat activity page: `useReducedMotion` subscribe closure re-subscribes every render (hoist); Summary still-frame folded state not asserted; Pause under Reduce Motion freezes mid-loop.

## Slice C2 (desktop) — what shipped
- Bots sidebar: `renderer/main/bots/bot-sidebar.tsx`, rendered by `ChatSidebar` on any Bots path (`isBotsPath`, `renderer/lib/bot-routes.ts`). Rows from `useBotRows` (`bot-sidebar-rows.ts`): `bots:live:summary` now carries `needsYou` and `lastReplyAt`; `bots:attention` (questions/approvals) and `bots:changed` re-read only the affected Bot's row, synced once per window by `useBotNotificationsSync` (`renderer/lib/bot-notifications-sync.ts`, mounted in `root-view.tsx`). Back to Aiden, Search and New Bot sit at the top of the sidebar body, not the title bar (window controls overlap it). Back goes to `lastNonBotRoute()` (recorded by `ChatLayout`).
- Pin, last-viewed and seen reply: `aiden-agent.bots-sidebar.v1` (`renderer/lib/bot-sidebar-preferences.ts`, hook `use-bot-sidebar-preferences.ts`, selector `useIsBotPinned`), with `since` so old replies are never unread. Unread is `lastReplyAt > (seenReplyAt[bot] ?? since)`: `seenReplyAt` is `botLastReplyAt` of the entries the chat showed (main's clock; a reply streaming when the person leaves is not in them yet), `lastViewed` (this Mac's clock) only picks the Bot `/bots` opens. Pruned only after a settled successful load. Not synced to phones.
- `/bots` (`BotsIndex` in `bots-view.tsx`) redirects (replace) to the last viewed Bot's chat, else the newest-activity Bot (summaries awaited up to 800 ms, then `bot.updatedAt`), showing `BotPageSkeleton` meanwhile; the starter carousel when there are none; the create flow suppresses the redirect. `bot-list.tsx` is gone.
- Bot panel: `BotPanelProvider` (`bot-panel-context.tsx`, keys `aiden-agent.bot-panel.*`) at the root; `BotWorkbench` (`bot-workbench.tsx`) on the C1 `WorkbenchPanel` (`id="bot-panel"`, optional `surface`, `tabMenu` and `widthBounds` props added to the shell; `BOT_PANEL_WIDTH_BOUNDS` 400–720, default 440, in `environment-panel-layout.ts`, so it sits inline beside the chat where the chat keeps 560px and floats only where the workspace panel would too), fixed tabs Activity (`bot-panel-activity.tsx`, `bot-activity-log.ts`; always the full log, independent of the Chat activity level), Files (`bot-panel-files.tsx`, replaced `bot-files-dialog.tsx`), Memory (`BotMemoryContent` shared with Profile → Memory), Routines (`BotRoutines`). Chat route only.
- `environment.toggle` → `environmentToggleTarget(pathname)`: Bot panel in a Bot chat, nothing elsewhere in Bots, workspace otherwise. `EnvironmentWorkbench` is suppressed (state kept, `data-state="covered"`) on Bots paths.
- One live subscription per Bot per window: a refcounted store behind `useBotLive` (`renderer/lib/use-bot-live.ts`); the chat holds it while shown and the Activity tab (memoised on entries/running) shares it. A consumer joining a failed store keeps the last view (flagged failed) while it retries.
- Turns: `walkBotTurns` (`renderer/main/bots/bot-turns.ts`) is the one stop/interrupted/carried-on state machine; `botTranscriptRows` and `botActivityLog` both build on it.
- One ••• menu: `bot-menu.tsx` (`BotMenuItems` with leading icons, `MemoryCardIcon` for Memory; `useBotMenuActions` reads the open chat from `router.state` when an item is chosen, so a Bot switch hands rows no new callback); closing it returns focus to the trigger unless it opened the panel. Deleting a Bot navigates to `/bots` only when that Bot's page is on screen.
- Bots on paired Macs: `RemoteBotsSection` rows in the sidebar ("On {Mac}"), filtered by `remoteBotGroupsMatching` before they are passed in. Search (`renderer/lib/search-fold.ts`) folds only Latin accents.
- "All Bots" stays only where no Bot chat exists to go back to: Profile's loading and not-found shells and the chat's not-found shell.
- Test harness: Bot renderer suites run with `NODE_ENV=test` (`renderer/main/bots/test-env.ts`, first import of `test-dom.ts`, which throws if the router's server build loaded anyway) so TanStack Router behaves as on a client and routed pages re-render; `mountWithBotRouter` takes `sidebar` and mounts inside `act`. Wrap test navigations, sleeps and emitted notifications in `act` (bot-sidebar, bot-chat-pane, bots-home and bot-panel print no act warnings).
- e2e: `tests/e2e/bots-sidebar-panel.spec.ts` (1280×800: the panel leaves the composer uncovered; the workspace surface is inert; `bots:attention` reaches a row through the app's own sync).
- Parked: workspace sidebar remount loses its local state after a Bots visit; batched `bots:live:summaries` IPC (N reads on mount); Profile→Chat pushes history (pre-existing); remote-only shows "Meet your first Bot"; the device mini player reconnects while suppressed (pre-existing); panel close returns focus to the toggle, not the composer (briefed); chip names are basenames (pre-existing); test debt: `lastNonBotRoute` module-state seam and edge cases, dead `deferred()` lines in the Files keep-on-refresh test, the render probe never uninstalls, Task 2 review minors 3, 4 and 6.
