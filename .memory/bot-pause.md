# Pause a Bot (plan §7, package P2) — 2026-10-20

Plan: `docs/plans/bot-handoffs-rules-computers-plan.md` §7. Code names say *pause/unpause*; the button reads **Resume** because `resume` already means "continue an interrupted turn".

## Layout
- `main/services/bot-pause-store.ts`: `<root>/bot-pauses.json` (mode 0600, `{version: 1, bots: {<botId>: {since, by}}}`, strict parse: exact keys, `by` ∈ `mac|phone|cli`, non-negative safe-integer `since`). Desktop root `<userData>/bot-service`, CLI root `<agentDir>/bot-service`. Kept out of `BotDefinition` so pausing never bumps the identity revision. Pausing again keeps the first `since`/`by`. **Fail closed**: an unparseable or newer-shape file is kept byte-for-byte, reads throw `BotPauseStoreCorruptError`, writes are refused; each read re-checks the file, so fixing it takes effect without a restart. `forgetBot` returns quietly on an unreadable file so a delete always finishes.
- `harness-host.ts` `suspend(botId, timeoutMs = 5 s)`: the per-Bot forced close (inside `serialize`), raced against a timer → `closed | timed_out | not_open`. Never sets `deleted`. On timeout the close keeps running and is reported through `onReport`; a reopen waits for it.
- `bot-session-service.ts`:
  - State `{kind: "paused"; since; by; interrupted?: submissionId}` (checked after `deleted`, before the `isOpen` inspect). Error/skip reason `paused_by_person` ("This Bot is paused. Resume it to continue."); `bot_paused` still means *interrupted*.
  - `send` refuses after the dedupe lookup (a redelivered request id still dedupes); `resume`, `dismiss`, `compact` refuse. A corrupt pause file refuses too (fail closed), while `state()` reports and treats it as unpaused for display.
  - `pause(botId, by)` (serialized): write the pause → `onPaused` (memory review cancel) → if the Bot has live work, `suspend` then `inspect` (reopens paused; the turn reads as interrupted) → `afterPaused` → publish. A timed-out suspend publishes `paused` without `interrupted`, then reopens in the background (`suspending` set) and publishes again. A suspend or inspect that throws (a harness close or reopen that fails) is reported through `onReport`, and `afterPaused` and publish still run (2026-10-21, H1): the pause is already written, so the Bot's other work must stop too.
  - `unpause`: clear → publish → `onUnpaused(botId, record)` outside the queue.
  - `appendEntry(botId, kind, data)` = `conversation.commit(tx => tx.appendEntry(...))`: **never resumes the scheduler**. `markSilent` and routine-proposal status writes now use it (a `{type: "write"}` submit resumed a paused/interrupted Bot — latent bug).
  - Notice `routines_skipped {since, routines: [{routineId, name, count}]}` → transcript entry `routines_skipped` (owned by no turn, so `[SILENT]` never hides it).
- `bot-pause-main.ts`: the one desktop pause store (`botPauses`, `isBotPaused`), shared by `bot-session-main.ts` (writes), `llm-client.ts` and the Remote chat route (reads).
- `bot-session-main.ts`: `onPaused: memoryReview.cancel`, `afterPaused` = `runBotPauseSteps([{run: stopLegacyChatWork}, {background: true, run: pauseBotComputer}], logger.warn)` (`bot-runtime/bot-pause-steps.ts`): steps run in order, a background step starts once the earlier ones finish and is not awaited, and every failure goes to the logger. The Bot computer's graceful `lume stop` can take about 30 s, so the pause answers without waiting for it; the computer reads Stopping until it is off. `onUnpaused` restarts memory review and appends the skipped-routines notice when `countSkippedWhilePaused(...) > 0`. `deleteEffects` forgets the pause after `deleteRoutines`.
- Memory review (`bot-memory/review.ts`): its `aiden.memory-review` marker is appended (`conversation.commit` + `tx.appendEntry`), never submitted, and a cancelled run writes none; the cancel check runs again after the conversation lookup, right before the append. The compaction flush marker is committed passively on the compaction's own `offer.conversation` (`recordFlush` in `bot-memory/compaction.ts`), never through the session service. Fix for review finding: a review cancelled by the pause while it looked up the conversation for its marker used to `submit({type: "write"})` on the reopened harness, which resumed the interrupted turn (another provider request while `state()` said paused).
- IPC `main/handlers/bot-pause.ts`: `bots:pause(botId)` (always `by: "mac"`, refuses a Bot that does not exist: its `getBot` dep is the Bot store's `get`, which answers `null`, not `undefined`, for a missing Bot) and `bots:unpause(botId)`, both return the state. `bots:routines:runNow {botId, routineId, expectedUpdatedAt?}` in `bot-routines.ts`.
- Routines: a paused Bot's fire is `skipped / paused_by_person`, `surface: false`, never caught up (catch-up trigger treats `paused` like `interrupted`). A run that a pause interrupts mid-turn is recorded as `paused_by_person` too. `countSkippedWhilePaused(store, botId, since)` counts skips with `startedAt >= since`.
- Telegram (`bot-reply-outbox.ts`): a message for a paused Bot gets one fixed line ("{Name} is paused. Resume it in Aiden to continue.") with no outbox row and no typing action; a reply cut short by a pause is delivered after unpause + Resume.
- Remote legacy projection (`aiden-remote-bot-session.ts`): shipped phones decode a closed state enum, so `paused` → `{state: "unavailable", interrupted: false}` everywhere (snapshot keeps its transcript), and send/resume/dismiss → `operation_stale` 409, which the idempotency ledger forgets so the same key runs after unpause. The `routines_skipped` entry is dropped on the wire (default branch). Only rev-37 `bot:handoffs` devices may see `paused`/`bot_paused` (P4).
- Legacy chat route (`aiden-remote-chats.ts` `startTurn`, `POST /chats/{id}/turns`): paired desktops still drive a Mac's Bots through the Bot's canonical chat, outside the durable session. Its `botPaused(botId)` option refuses a paused Bot's chat with `operation_stale` 409 before preflight, appends or provider calls, wrapped as `AidenOperationNotExecutedError` so the same Idempotency-Key runs after unpause. Desktop wires `isBotPaused` (`bot-pause-main.ts`, re-exported by `bot-session-main.ts`; throws on an unreadable file, so the turn is refused); the CLI wires `bots.isPaused`. The route checks twice: before anything else, and again once the turn holds the chat (`beginChatTurn`), so a pause landing during model resolve or preflight still refuses it before any append.
- Legacy work already running when the Bot pauses (fix for review finding): the first pause step → `stopBotLegacyChatWork` (`bot-runtime/bot-legacy-chat-pause.ts`) → for every chat of the Bot (`chatStore.listByBot`), `llmClient.stopChatWork(chatId)`: cancels its starting and running generations as `user_stop` (tools, approvals, subagents with them), keeps the chat and its side questions, and waits (5 s grace, never throws) until nothing runs on it. Other Bots' and workspace chats are untouched. `llm-client.ts` also refuses a paused Bot's generation once it is registered ("This Bot is paused. Resume it to continue."), so a start that slips past the route's checks is either refused there or found and stopped by `stopChatWork`. The CLI's `pauseBot` already cancels and drains its Bot chats, through the daemon's own `cancelChat` (abort): the run ends `cancelled` with its partial answer and no `cancellationOrigin`, where the desktop's records `user_stop`. `docs/aiden-remote-api-v1.md` says so. On a desktop with Bots, `durableBotSessions` answers every Bot-chat turn `400 invalid_request` before either pause check, so the two `409 operation_stale` checks matter on the CLI host.
- Renderer: Bot ••• menu (chat header, sidebar rows, pinned Bot) and Profile ••• menu: Pause Bot / Resume Bot (after Pin). `BotPausedCard` ("Ada is paused." + Resume, neutral tone) beside the interrupted card; composer `ready=false` with "Ada is paused.". Row labels (G2): interrupted = "Interrupted — tap to resume", paused = "Paused". `RoutinesSkippedCard` lists each routine with Run now (settles to "Started"). `useBotLiveSummary(botId)` shares the sidebar's summary cache.
- CLI (`packages/cli/src/bots.ts`, via the running `aiden serve`): `CliBotGenerationRuntime.isPaused(botId)` (contract) and `assertNotPaused(botId)`; `aiden bots pause <id>` → `{botId, paused: true, since}` (writes first, then cancels and waits for the Bot's live chats), `aiden bots unpause <id>` → `{botId, paused: false}`. `preflight` (phone Bot turns) throws `operation_stale` 409 "<Name> is paused."; `daemon-chats.ts` refuses a paused Bot turn (`chat:error`, no provider request). Legacy (non-durable) CLI has no Bot delete path, so it never calls `forgetBot`. Durable CLI sessions (#577, merged into #559 on 2026-10-22): `createCliDurableBots` gets the same `pauses` store instance (`CliDurableBotPorts.pauses`, passed to `createBotSessionService`), `bots pause`/`unpause` call `durable.runtime.pause(id, "cli")`/`unpause`, so a running durable turn is suspended and left for Resume/Dismiss; durable `bots delete` forgets the pause. The CLI's `AidenRemoteBotSessionService` wires no hand-offs, so it never advertises `bot:handoffs` and phones see a paused CLI Bot as `unavailable`. Test: parity.test.mjs "a durable Bot paused from the CLI…".

## Verified behaviour
- `harness.close` signals and joins every task without writing; a running turn stays placed and reopens with `scheduling: "paused"`, i.e. interrupted. Questions, approvals and hand-off waits reject on that abort signal (cards withdrawn) and are re-asked under the same `waitId` after Resume.
- `conversation.commit(... appendEntry ...)` does not resume the paused scheduler; `submit` (including `{type: "write"}`), `compact`, `abort` and `waitForIdle` do.
- The deadlock class (2026-10-21, H1): code that runs inside a harness task (a tool's `execute`, a hook) must never reach the Bot's conversation through the session service (`conversation`, `appendEntry`, `state`). A pause, quit or delete holds the harness host's per-Bot `serialize` lock while its close waits for that very task, so the task waits on the lock forever and the Bot is wedged (pause times out, shutdown hangs). Use the call's own API instead: `call.appendEntry`, `call.entries()` (newest first), `call.submissions()`, or the hook's conversation. Fixed on that rule: `suggest_connection` (`suggestConnectionCandidate` in `bot-tool-candidates.ts` appends and checks for a waiting card through the call), `routine_notes` binding (`routineTaskIdOfCall`: the oldest placed submission of the call), the compaction flush marker, and routine proposals (`propose` settles a cut-short card through its own call's append). `bot-pause.test.ts` pauses while a connect card is being suggested and checks the pause and quit finish.

## Seams for later packages
- Hand-offs (P1): withdrawn by the close like other waits; no code needed. Anything that keeps running on its own goes into the pause steps in `bot-session-main.ts` (run via `afterPaused`, after the turn is closed; failures are logged, never block the pause). A slow step that the pause need not wait for, like the Bot computer stop, is a `background` step.
- Rev-37 Remote pause/unpause routes and the `paused` wire state are done host-side in P4 (`.memory/remote-rev37-bot-handoffs.md`; a phone pause is `by: "phone"`); the phone and paired-desktop clients (iOS `pausedSubtitle` / Android `PAUSED_ROW` copy (G2), Pause/Resume, the paused card) landed in P5 (`.memory/bot-handoffs-clients.md`).
- Hardening H2: no client shows a pause before the host confirms it (iOS's unused optimistic `AidenBotSessionModel.pause()` was removed; Pause stays on the profile). Android's paused card offers Resume only with `canWriteBots` and a connection (`aidenBotPausedChatOffersResume`).

## Known limits
- The only manual run of a Bot routine is Run now on the skipped card (`bots:routines:runNow`): the scheduled-tasks page and the Remote schedules API exclude Bot routines, and Remote has no Bot routine run route. A Run now on a paused Bot (a card left on screen from an earlier unpause) is refused with "This Bot is paused. Resume it to continue." before any run starts (`isPaused` dep of `scheduled-bot-routines.ts`, wired to `isBotPaused`; 2026-10-21, H1); it used to be recorded as a `paused_by_person` skip that counted in the next notice.
- A pause whose close outlives its 5 s bound publishes `paused` without `interrupted`; if the person unpauses before that close ends, the Bot reads `idle` until it ends, then `interrupted` is published.
- Run now state on the skipped card is per mount; reopening the chat offers Run now again.
