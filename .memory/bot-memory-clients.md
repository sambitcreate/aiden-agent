# Bot memory, soul and proactivity: clients (Track C, 2026-10-09)

Plan: `docs/plans/2026-10-09-bot-memory-soul-proactivity.md` (C1–C5). Spec: `docs/superpowers/specs/2026-10-09-bot-memory-soul-proactivity-design.md` §11.5, §11.6, §14, §15. Core: `.memory/bot-memory-soul.md` (A), `.memory/bot-proactivity.md` (B).

## Desktop (renderer)
- IPC (`renderer/lib/ipc.ts`, `botsApi`): `memory.get(botId)`, `memory.edit({botId, edit})`, `onMemoryChanged` (`bots:memory:changed`), `routineProposals.respond({botId, proposalId, decision})`. Types come from `renderer/shared/bot-memory.ts` and `bot-routine-proposals.ts`.
- **`bots:memory:changed` must be in `renderer/preload-channels.ts` `NOTIFICATION_CHANNEL_VALUES`** or the preload drops it (orchestrator-owned file; A's `bot-memory-main.ts` push also fails type-check without it).
- `renderer/main/bots/use-bot-memory.ts`: one react-query per Bot (`["bot-memory", botId]`), refetched on a change event whose revision differs from the cached view; edit results are written straight into the cache (`storeBotMemoryView`). Profile row and the Memory page share it.
- `renderer/main/bots/bot-memory-page.tsx`: `?page=memory` sub-page in `BotPageShell` (`bot-page-search.ts` accepts `memory`; `bots-view.tsx` routes it). Groups "About you" (USER) and "{name}'s notes" (MEMORY) as `settings-group` cards, rows with ••• (Edit, Delete), a neutral `role="meter"` (track `bg-control`, fill `bg-tertiary`, aria-valuetext "563 of 1,375 characters", visible "41% full"), over-budget note, footer destructive **Erase memory** (AlertDialog "Erase everything {name} remembers?" / "This can’t be undone."), unreadable red callout whose only action is Erase, load-failure callout + Try again, skeleton while loading.
- Edit dialog: textarea with `n / 500` count, Save; refusals map to person copy (`botMemoryEditErrorText`): blocked → "This can’t be saved because it looks like a password or an instruction to the Bot."; over_budget → "That would make “{group}” too long…"; entry_not_found → "This memory changed since you opened it…" (the fresh view from the result is shown underneath).
- **Delete is deferred, not re-added (deviation from spec §15 "Undo re-adds through the replace path").** The person edit contract has no `add`, and `replace` on a removed id answers `entry_not_found`, so Undo can't restore through main. The row hides at once with a sonner "Deleted from memory" toast + Undo (6 s); the `remove` edit is sent on toast auto-close/dismiss or when the page unmounts; Undo cancels it so nothing reaches main. Erase cancels pending deletes.
- Profile (`bot-profile.tsx`): "Memory" row with `MemoryCardIcon` + quiet count ("1 thing"/"6 things"/"Nothing yet"/"Couldn’t be read") after Instructions in About.
- Chat: `bot-transcript-rows.ts` maps `memory_update` → `{kind:"memory_update"}` (consecutive ones collapse; never folded into Updates) and `routine_proposal` → `{kind:"routine_proposal", proposal, status, routineId?}`. `bot-chat-pane.tsx` renders a centred quiet caption button "Memory updated" (aria "Memory updated. Open Memory") that navigates to `/bots/$id?page=memory`, and `renderer/components/bots/routine-proposal-card.tsx` (on `BotNoticeCard`, CalendarClock neutral tile): "Add a routine?", "{name} · {label}", prompt `line-clamp-2`, Not now / Add routine; settles locally from the respond result ("Added ✓ · {label}" with a green check tile, or "Not added"); a failed respond toasts and keeps the actions. Accept invalidates the routines query.
- Routines (`bot-routines.tsx`): with an empty list, a "Try a daily check-in" row (label from `formatBotRoutineLabel(BOT_DAILY_CHECKIN_SUGGESTION.schedule)`) opens `BotRoutineEditor` with the new `draft` prop prefilled; nothing is created until Save.
- Greeting removed: `bot-advanced.tsx` (section, draft, save path), `bot-identity.ts` (no longer forwards `openingGreeting`). Instructions description: "This is {name}’s personality and how it should help. Memory is separate." Onboarding Bots tile: "…remembers what matters to you, and can check in on a schedule."
- Tests: new `renderer/main/bots/bot-memory-page.test.tsx` (8; register in `test:bots`); extended `bot-chat-pane.test.tsx` (+4), `bot-routines.test.tsx` (+2), `bot-profile.test.tsx` (greeting tests rewritten to access-only), `onboarding-flow.test.tsx` copy.
- Test gotcha: never `assert.equal(<happy-dom element>, null)` inside `waitFor` — a failing assertion util.inspects the element (whole window) and the process stalls until SIGKILL. Assert `x === null` as a boolean instead.
- Screenshots of the Memory page and proposal card were rendered through a throwaway Vite harness (scratchpad), light and dark.

## Android (C5, done)
- Models: `models/AidenBotSession.kt` adds `MemoryUpdate` and `RoutineProposal` entries; unknown entry types are dropped from snapshots and an unknown `entry` frame becomes `SkippedEntry` (only advances `seq`); a missing `type` and malformed known types still fail closed. `models/AidenBot.kt` drops `openingGreeting` (decoders accept and ignore a bounded string; encoders never write it). New `models/AidenBotMemory.kt`; `AidenBotRoutine.kt` has the respond, suggestion and notification shapes.
- Protocol: `protocol/AidenRemoteProtocol.kt` has the two tokens, `BOT_CARDS` (negotiable and phone-known) and the new error codes. The privacy guard allows `prompt` only on `routine_proposal` entries and suggestions; it still runs before decoding, so a future unknown entry type carrying a private-looking key drops the stream. The coordinator asks for `bot:cards` when either token is announced (`AidenServer.offersBotCards`).
- Client: `networking/AidenRemoteClient.kt` serves the five routes; both POSTs send an Idempotency-Key and never auto-retry.
- UI: `features/bots/AidenBotMemoryController.kt` + `AidenBotMemoryScreen.kt` (`AidenScreen.BotMemory`). Profile has an SdStorage Memory row; the session shows one caption per run of memory updates plus the proposal card (read-only without `bot-proactive-v1`). Routines has the check-in suggestion. Advanced no longer has a greeting.
- Notifications: `AidenScheduledRunNotifier.kt` `deliverBotRoutines` runs on ON_START, on connect and from Bots home. It reuses the scheduled-runs channel, and the first poll for a Mac only records the cursor.
- Tests: `AidenBotMemoryTest` and `AidenBotRoutineNotificationDeliveryTest` are new; the Bot contract (including the revision-25 test, now covering 27), session, profile and navigation tests are extended. The full `:app:testDebugUnitTest` passes (654). There is no Compose UI test for the new screens. JDK: Android Studio's bundled JBR.
