# Running-subagent visibility — 2026-10-27

Owner request: people must always see that subagents are working, even with Quick View and the Environment panel closed, and the inline subagent items must not scroll away. A t3code-inspired HTML mockup was approved; the "floating pill" option was built in three phases, each followed by an Opus high review.

## Phase 1 — composer pill and tray (`renderer/components/subagent-composer-pill.tsx`)
- `useSubagentComposerPill(chatId, views, enabled)` latches with `{generationIds, ongoing, dismissedRunIds}`. Generations with active runs are latched (per chat). Once every run settles the pill shows a finished summary until it is dismissed or the next batch replaces the latch. The effect is keyed by `activeRunsKey`: sorted `gen\trun` lines of the active runs.
- ChatPane passes `null` views while `environmentPanel.subagents.chatId !== chatId` (the panel rebuilds its views after a chat switch renders); the hook then neither updates the latch nor shows a pill. A batch ends (`ongoing: false`) only once nothing is active and every latched generation has been seen during this visit to the chat (`seenRef`, reset on a chat switch or `null` views), because a returning chat's views load in pieces (references, then saved and live snapshots). This fixed Phase 1 review finding 12, where returning mid-run dropped the batch's finished generations. A generation that vanishes (a failed turn) and never returns still ends the batch once it has been seen and nothing is active. The visit also records `sawActive`: if a run was active during this visit and nothing is active now, the batch ends even when an older latched generation never reappeared (Fable review F1). Without that, a batch latched before a failed turn could never end and the next turn's runs joined the old summary.
- Dismiss records the run IDs shown at that moment (`dismissedRunIds`), not the generation. A new run in the same generation brings the pill back. `subagentPillModel(views, latchedGens, dismissedRunIds)` drops dismissed runs first, except a run in `needs_attention`, which comes back until it is answered. "Hide background subagents" is offered only when every active run is a v2 snapshot with `execution: "background"`; a v1 or snapshot-less run counts as foreground. The pill's `returnFocus` prop (ChatPane passes the composer) takes focus when the pill or its open tray unmounts while holding focus.
- The pill has no live region of its own. The provider-level `SubagentLiveAnnouncer` in `EnvironmentPanelProvider` already announces active counts, attention and terminal summaries, so a second pill announcer was removed as duplicate speech.
- Dismissed run IDs are capped at 200 per chat, and the transcript group's remembered collapsed set at 200 groups.
- Width: `ComposerFloatingRow` uses the composer's own `aiden-dock-inset chat-content-column` classes, so the task chip and pill row is exactly as wide as the chat box at every window size and Appearance chat width (owner asked 2026-10-29; before, it used the bare dock gutter and ran past the composer on wide windows).
- Narrow windows: `ComposerFloatingRow` is a size container (`@container`). The chip details use `line-clamp-1 [overflow-wrap:anywhere]` instead of `truncate`, so a chip's minimum width is its icon and count; `truncate` text counts at full width in min-content and made the pill overflow its own background. Below a 30rem row the pill drops the headline, separator and elapsed time and says "N running" or "N finished". Below 15rem it also drops the marks. Below 24rem the task chip and pill wrap onto two lines. `ComposerFloatingRow` measures its row with a ResizeObserver (`onHeightChange`), and `composerFloatingRowOffsets(visible, height)` uses at least one 36px line, so a wrapped pair pushes the transcript up instead of covering it.
- The tray offers Stop, Show in chat and Open Subagents panel. `onOpenPanel(returnTarget)` passes the pill trigger to `environmentPanel.showTools(tab, returnTarget)`, which makes that trigger the panel's return-focus target. `openSubagent(runId, returnTarget)` also routes through `showTools`, so closing the panel after opening a run returns focus to the chip or tray row that opened it.
- `subagents.toggleTray` (default `⌘⇧S`, `allowInEditable`) is claimed only while the pill is visible. It is listed in `INTRODUCED_DEFAULT_COMMANDS`, so legacy custom bindings win.
- The todo chip and the pill share `ComposerFloatingRow` in `todo-panel.tsx`; `composerFloatingRowOffsets` gives the 44/56 px scroll clearance while either is shown (see `.memory/todo-scroll-clearance.md`).

## Phase 2 — collapsible transcript group (`renderer/components/subagent-chips.tsx`)
- `SubagentChips` is a card with a header ("Kicked off/Ran N subagents", a coloured state summary from `subagentGroupSummaryParts`, live elapsed time via `useNow`) and a body that animates with `useCollapsibleBody`. Collapse state is a module-level `Set` keyed by group (session memory only, not persisted).
- The header's `aria-label` excludes the elapsed time so it does not re-announce every second.
- `subagentRunTranscriptTarget(runId)` returns the run's chip, or the group header when the group is collapsed. `revealSubagentRunInTranscript(runId, {instant})` is what Show in chat calls: it expands a collapsed group with `flushSync`, then scrolls to and focuses the run's own row.
- Collapse state is derived per `groupKey`, so a reused component instance for another generation does not inherit a collapsed body. The body keeps `aria-hidden` next to `inert`, because Testing Library and some assistive tech ignore `inert`.
- Focus handoff across remounts uses `SUBAGENT_CHIP_FOCUS_SELECTOR` (run chips and `data-subagent-chip-group-toggle`) with a `{key, element}` capture keyed `run:<id>` or `group:<gen>` (`renderer/lib/subagent-panel-state.ts`, used by `message-list.tsx`).

## Phase 3 — top-bar badge (`renderer/components/chat-top-bar.tsx`)
- `SubagentsRunningButton` sits in `WorkspaceToolButtons` outside the compact fold, so it stays visible on narrow windows. It shows the active count in `status-accent` fills, or `status-warning` while any run `needs_attention`, and toggles the Subagents tab. It counts runs only when `panel.subagents.chatId` matches the header's `chatId`, the same ownership check as the pill. Like the other tool buttons it is disabled while `gitOperationBusy`. If it unmounts while focused (the last run settled), a layout-effect cleanup hands focus to the More trigger (`data-workspace-tools-menu`), or the toolbar's first enabled button when More is absent or disabled. At 680–900px the title keeps 366px or more with the badge showing. Phase 3 review: all four findings fixed.

## Deliberately not built
- Sidebar running dot: background subagents are not wired up. The `subagent` tool has no execution field, launch hard-codes `execution: … ?? "foreground"` and `rollout.background: false` in `subagent-foreground-persistence-v2.ts`, and `BackgroundSubagentCoordinatorV2` is only constructed in tests. `AIDEN_SUBAGENT_BACKGROUND_ENABLED` / `subagentBackgroundEnabled()` default on but have no callers, so every run happens inside an active turn, which the sidebar's Working state already shows. Do not overload `activeChatIds`, because it also drives lifecycle reconciliation. Revisit when background subagents ship.

## Full review (Opus high, after Phase 3)
Fixed: finding 12 (see Phase 1), return focus from `openSubagent`, a batch whose generation vanished never ending, collapse state leaking between generations, duplicate pill announcer, uncapped dismissed/collapsed sets, the top-bar focus fallback, pill overflow in narrow windows, and the shared elapsed helper (`longestSubagentElapsedLabel` in `subagent-view-state.ts`). Kept on purpose: `aria-hidden` beside `inert`, and `subagentStatusLabel` (it reads activity, so it is not an alias). Open: the task chip's pre-existing `outline-none` hides its keyboard focus ring.

## Fable adversarial review (after the full review)
Fixed: F1 (`sawActive` batch end), F2/F3 (focus handoff when the pill or tray unmounts), F4 (attention resurfaces a hidden run), F5 (tray row name excludes elapsed; elapsed is `aria-hidden`), F6 (a failed Stop shows on the collapsed row), F7 (v1 runs count as foreground for hiding), F9 (measured clearance instead of the overlap), F12 (Show in chat expands a collapsed group and focuses the run), and the `MarkStack` alias removal. Owner answers: keep `⌘⇧S`; push the chat up by the measured row height; bring a hidden run back when it needs attention; Show in chat expands and focuses. Skipped: F10 (only active groups tick, so a handful of timers), F11 (negligible memory), F13 (the palette greys out the command while no pill is shown, the same as other handler-less commands), F14 (no Playwright e2e yet; a suggested follow-up).
