# PR #198 attachment picker review follow-up

The native iOS attachment picker uses a bounded PhotoKit current rendering rather than loading original image bytes into the upload pipeline. The request preserves transparency through PNG encoding, uses JPEG otherwise, and validates the encoded size. Its checked continuation must resolve on PhotoKit error or cancellation even if the same callback is marked degraded; only a nonterminal degraded preview may be ignored.

Photos library refreshes are generation-fenced across authorization suspension, dismiss/reset, menu and camera transitions, and commit. The final result-application method checks the same generation and Photos mode before publishing assets, selection, or status; the focused regression exercises that publication seam, not only the helper predicate.

On iPad, picker layout classifies landscape against actual UIWindow bounds while clamping its panel to the detail container. The circular SwiftUI camera controls intentionally follow the approved native picker reference; the shared Electron squircle component does not apply to them. Physical iPad visual acceptance remains open.

The hosted deterministic Electron E2E job reached test 103/103 on the review head but was canceled at its 30-minute job limit before completion. The limit was raised to 45 minutes with a CI-policy assertion, preserving test coverage. This is a CI scheduling change, not an Electron feature change.

The picker presentation adapts Hermex `409c66c`'s quieter motion without copying its sheet lifecycle: Aiden's always-mounted overlay uses a small attachment-button-anchored scale and 8-point offset, with a 200 ms ease-out entrance and 160 ms ease-out exit. Dismissal still closes picker state and invalidates PhotoKit work immediately; there is no delayed `onDismiss` task. The shared Aiden Reduce Motion setting removes the transition. The shipping-source suite and unsigned generic iOS build pass, and three focused XCTest cases passed on a physical iPhone 13 Pro. Physical iPad visual acceptance remains open.

## Quick-photo strip & inline staging follow-up (2026-11-27)

Long-pressing `+` in iOS Workspace and Bot chats opens a zero-permission out-of-process `PHPickerViewController` in `.compact` mode (`.quickPhotos`, `selection = .continuous`, `selectionLimit = 1`, `edgesWithoutContentMargins = .all`, mounted only while open/collapsing via `renderedMode`) over a `UIVisualEffectView` backdrop blur anchored above the measured composer top (`AidenComposerTopYPreferenceKey`) and scaled from `attachmentButtonCenter`. Tap `+` retains the `.menu` / `.camera` / `.photos` flow and existing `AidenAttachmentPickerPresentationMotion` contract. `AidenPickedPhotoItemLoader` uses ImageIO `CGImageSourceCreateThumbnailAtIndex` synchronously inside `loadFileRepresentation` (preserving EXIF orientation and PNG alpha while bounding 48 MP HEIC / ProRAW memory and supporting `Progress` cancellation). Both `AidenChatViewModel` and `AidenBotSessionModel` now share `AidenStagingAttachment` cards (`72×72 pt` images / `114×72 pt` files) with inline circular progress rings (replacing `AidenUploadProgressRow`), per-item `×` cancellation across `.preparing` and `.uploading`, and synchronous in-memory `pendingPreviewImages` handoff so staging → pending never flashes a placeholder.
