## 2026-10-29: PiP from the screencast (audit-fix speech/media/VMs)

PiP no longer runs a 250 ms `capturePage` + PNG data-URL loop on the main thread. `PipFeed` (`main/services/browser/pip-feed.ts`, Electron-free, unit-tested with an injected clock) paints the newest `Page.screencastFrame` at most every 250 ms and holds acks while painting, waiting, or while the PiP window is hidden/minimized (Chromium keeps ~3 frames in flight, so held acks stall the encoder). `BrowserService.screencastFrame` acks immediately when a recording is active (recording owns pacing) and `startRecording` releases held acks. PiP holds `tab.pipLease` and `tab.pipUnhost = hostWhileActive(tab)` for its lifetime; probe showed a detached view's screencast stops when the host is minimized, an attached-invisible one with throttling off keeps going. Crash closes an open PiP and releases its lease (review follow-up, below). Debugger `detach` (DevTools) falls back to `pipCaptureLoop`. Linux keeps the capture loop (screencast behind the invisible native host unverified). `stopRecording` keeps the screencast running when PiP is open. `incrementCapturerCount` does not exist in Electron 43. Native fixture asserts paints 2-8/1.5 s minimized host, 0 while PiP minimized, paints during/after recording, captures===1. Early Playwright runs died after "starting recording" while other Electron probes ran concurrently; three consecutive clean runs passed afterwards.

## 2026-10-29: crash closes PiP (review follow-up)

Review flagged that keeping the PiP lease through a renderer crash left a dead screencast. Restarting `Page.startScreencast` on the recovered page's `did-navigate` (with or without a `stopScreencast` first, toggling `setBackgroundThrottling`, or re-adding the child view) sent no frames: the replacement renderer reports `document.visibilityState === "hidden"` behind a minimized host and rAF runs about 5 times a second. Reopening PiP on that recovered page also painted nothing. So the crash handler now ends PiP (`endPictureInPicture`, destroy the window, `state.pictureInPicture = false`). The native fixture reopens PiP, crashes and asserts the preview closed and throttling restored; that assertion fails on the old code. Open question for the owner: a renderer recreated behind a minimized host does not render for a reopened preview.
