- Plan: `docs/plans/proactive-aiden-plan.md` Phase 2. A1 (core, prompts, verdicts), A2 (reviewer), A3 (main loop, rounds, IPC) and A4 (desktop goal bar, `/goal`) are built; `goalLoopEnabled()` in `renderer/shared/goal.ts` returns true (the one switch to turn it off). - Files in `main/services/goal/`: `goal-core.ts` (pure state machine, CAS on `{id, revision}`), `goal-prompts.ts` (objective in `<untrusted_objective>`), `goal-verdict.ts`, `goal-reviewer.ts` (side-call continuation, isolated fallback, usage source `goal-review`), `goal-loop.ts` (the `GoalLoop` class; every effect is a dependency so it runs with fakes), `goal-main.ts` (Electron wiring and the `goalLoop` singleton), `goal-round-start.ts`, `goal-turn-hooks.ts`.
- `goal-turn-hooks.ts` is a registry so `llm-client.ts` and `follow-through-main.ts` never import `goal-main.ts` (import cycle). `startGoalLoop()` installs the hooks after `startFollowThrough()`; until then they are no-ops.
- Hooks in `llm-client.ts`: the kickoff note is the first turn note of the person's next non-notice turn after `set` (given once per goal); the post-compaction reminder is a request transform (`chatStateRequestMessages(head, current, reminder)`), inserted right after the last compaction summary and never journaled; `runSettled` fires from `settleRun` for every run that owes its chat turns, with `stopped` and `failed`.
- A round is an attended windowless turn like an owed turn: owner `llmClient.attendedTurnOwner(chatId, "goal:<streamId>")` (id 0, prompts through `owedTurnPrompts`), options `goalRound: true` (C2's `TURN_ARGS_REFUSAL_RULES` refuse `check_back` set), the last run's context (`owedTurnContextOf`), no permission field so the chat's approval mode applies, and a `source: "goal"` notice "Keep going · round N of 50".
- Loop after a settle: wait 1.5 s, skip if the chat is busy (the person's send wins), pre-checks (other boot, Stop, failed run, round cap, running helper → skip with a 30-minute watchdog), review with one retry for an unusable answer, spending refusal → paused `spending`, CAS write, then settle / wait / next round (not started if the chat became busy during the review). An unavailable round start pauses with cause `failed`. `shutdown()` sets a stopped flag so the quit's own aborts don't pause goals; they come back paused `restart` on the next launch.
- State: optional `goals` in follow-through `state.json` (`savedFollowThroughGoals` / `saveFollowThroughGoals`, parsed by `parseGoalRecords`). Deleting a chat drops its goal; a folder-access change pauses it; `beginFollowThroughMove` throws while the goal is active.
- IPC `main/handlers/goals.ts`: `chats:goal:get|set|pause|resume|clear` (changes need the active document; desktop sources `slash|menu|proposal`), broadcast `chats:goal-changed {chatId, goal: GoalView | null}`.
- Reviewer output cap: 400 tokens, plus the chat request's thinking budget (capped at 16,384, and at the model's max) when the parent request reasons, so thinking params stay byte-identical for the cache (`goalReviewMaxTokens`).
- Analytics: `goal_started {source}`, `goal_settled {outcome, rounds}` with the goal-only buckets `GOAL_ROUND_BUCKETS` (1, 2-5, 6-10, 11-20, 21-49, 50); rows in `docs/analytics.md`.
- Tests: lane `test:goal` (core, verdict, prompts, reviewer, loop, round start, `main/handlers/goals.test.ts`, `renderer/shared/goal.test.ts`); reminder in `chat-frozen-state.test.ts`; a prefix case in `prompt-prefix-stability.test.ts`; analytics in `analytics-feature-reports.test.ts`.

- A5 approvals: `createOwedTurnPrompts().publish(..., lifetime)` takes a per-turn `{ms, expired}`; goal rounds pass `ATTENDED_TURN_PROMPT_LIFETIME_MS` (30 min) through `llmClient.attendedTurnOwner(chatId, doc, lifetime)`, and an unanswered card calls `goalLoop.promptExpired` → Needs you, cause `unanswered`. A question closing at the agent's own earlier deadline does not count.
- A5 policy (`chat-turn-tool-policy.ts`): windowless goal rounds refuse `classify`/`generate_image` (only the owning window can allow them); a `TURN_ARGS_REFUSAL_RULES` row refuses `subagent` runs that may write (`subagentCallMayWrite`: any non scout/planner/reviewer role, or workspaceWrite/shell/delegate/mcpMutations at batch or task level). - A5 notices: `NoticeDelivery` dep `startGoalRound` (wired to the `noticeRound` goal hook → `GoalLoop.noticeRound` → `startAttendedRound` in goal-main) answers a waking notice with a goal round while the goal is active; it spends no wake budget and doesn't bump `rounds`.
- A5 Inbox: `chats:pendingAttention` kind `goal` (after interrupted, before working, only with no live run) from `goalNeedsYou()` in goal-main; Inbox signal `attention: "goal"` → Needs you row labelled "Needs you" with "Keep-going goal: <reason>"; counts in the Dock badge. goal-main's `onChange` calls `chatActivityRegistry.touch()` so both recount.
- A5 `/until`: the goal is the only state. `chats:goal:set {source: "until", check}` → `loop.set` with `untilGoalObjective(command)` and `check` (maxRounds 5, "check N of 5"). No kickoff; set while idle runs the check at once (`GoalLoop.look`), otherwise after the answer settles. `runCheck` → `follow-through-main.runGoalCheck` → `goalChecks: GoalCheckRunner` (`done-when.ts`; keeps admission, worktree identity, mutation gate and the process-group ledger of the old DoneWhenChecks). Failed → `applyGoalCheck` next round with the fenced output in `goalContinuationNote`; stopped → paused `failed` with the summary. Old `state.checks` records migrate once in `startFollowThrough` (`migrateDoneWhenRecords`: waiting/running → paused `restart` goals; passed/gave-up dropped; chats with a goal skipped); `checks` is always saved as `[]`. Removed: `chats:followThroughSetCheck|ClearCheck`, the composer check chip, `ChatFollowThroughV1.check`. Keep-awake reads `goalChecks.list()`.

- A9 rounds in a window: `goal-window-rounds.ts` (`GoalWindowRounds`, pure). Each chat pane reports `chats:goal:view {chatId|null, focused}` (focus/blur, unmount → null); main keeps views per renderer document (`rendererDocumentOwner`, `onInvalidated` = gone). `goal-main.startRound` first `offer`s the round to the most recent focused view of the chat (not when `powerMonitor.getSystemIdleState(1) === "locked"`): sends `chats:goal-window-round {chatId, token}` to that document; the pane (idle, `visualPromptBusyRef` false) runs `runGeneration` with `startGeneration(..., goalRoundStart(token))` → `chats:goal:startWindowRound {token, streamId}` → `startGoalWindowRound(windowOwner, token, streamId)` → `startAttendedRound(..., {owner, streamId})` (same `goalRound` options, the window owner, so not windowless). Declines or 5 s without a claim (`GOAL_WINDOW_ROUND_CLAIM_MS`) → windowless round. The window going away or showing another chat mid-round → `goalLoop.windowClosed` (paused `chat-closed`) then `llmClient.cancel(stream, "user_stop", doc)`. `runSettled` hook calls `goalWindowRounds.settled(streamId)` first.
