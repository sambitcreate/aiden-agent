# Keep-going goals (`/goal`) — 2026-11-22

- Plan: `docs/plans/proactive-aiden-plan.md` Phase 2. A1 (core, prompts, verdicts), A2 (reviewer), A3 (main loop, rounds, IPC) and A4 (desktop goal bar, `/goal`) are built; `goalLoopEnabled()` in `renderer/shared/goal.ts` returns true (the one switch to turn it off). A5 (30-minute approvals, jobs, `/until` as a goal), A9 (window-owned rounds) and A8 (`propose_goal`, onboarding tile) come later.
- Files in `main/services/goal/`: `goal-core.ts` (pure state machine, CAS on `{id, revision}`), `goal-prompts.ts` (objective in `<untrusted_objective>`), `goal-verdict.ts`, `goal-reviewer.ts` (side-call continuation, isolated fallback, usage source `goal-review`), `goal-loop.ts` (the `GoalLoop` class; every effect is a dependency so it runs with fakes), `goal-main.ts` (Electron wiring and the `goalLoop` singleton), `goal-round-start.ts`, `goal-turn-hooks.ts`.
- `goal-turn-hooks.ts` is a registry so `llm-client.ts` and `follow-through-main.ts` never import `goal-main.ts` (import cycle). `startGoalLoop()` installs the hooks after `startFollowThrough()`; until then they are no-ops.
- Hooks in `llm-client.ts`: the kickoff note is the first turn note of the person's next non-notice turn after `set` (given once per goal); the post-compaction reminder is a request transform (`chatStateRequestMessages(head, current, reminder)`), inserted right after the last compaction summary and never journaled; `runSettled` fires from `settleRun` for every run that owes its chat turns, with `stopped` and `failed`.
- A round is an attended windowless turn like an owed turn: owner `llmClient.attendedTurnOwner(chatId, "goal:<streamId>")` (id 0, prompts through `owedTurnPrompts`), options `goalRound: true` (C2's `TURN_ARGS_REFUSAL_RULES` refuse `check_back` set), the last run's context (`owedTurnContextOf`), no permission field so the chat's approval mode applies, and a `source: "goal"` notice "Keep going · round N of 50".
- Loop after a settle: wait 1.5 s, skip if the chat is busy (the person's send wins), pre-checks (other boot, Stop, failed run, round cap, running helper → skip with a 30-minute watchdog), review with one retry for an unusable answer, spending refusal → paused `spending`, CAS write, then settle / wait / next round (not started if the chat became busy during the review). An unavailable round start pauses with cause `failed`. `shutdown()` sets a stopped flag so the quit's own aborts don't pause goals; they come back paused `restart` on the next launch.
- State: optional `goals` in follow-through `state.json` (`savedFollowThroughGoals` / `saveFollowThroughGoals`, parsed by `parseGoalRecords`). Deleting a chat drops its goal; a folder-access change pauses it; `beginFollowThroughMove` throws while the goal is active.
- IPC `main/handlers/goals.ts`: `chats:goal:get|set|pause|resume|clear` (changes need the active document; desktop sources `slash|menu|proposal`), broadcast `chats:goal-changed {chatId, goal: GoalView | null}`.
- Reviewer output cap: 400 tokens, plus the chat request's thinking budget (capped at 16,384, and at the model's max) when the parent request reasons, so thinking params stay byte-identical for the cache (`goalReviewMaxTokens`).
- Analytics: `goal_started {source}`, `goal_settled {outcome, rounds}` with the goal-only buckets `GOAL_ROUND_BUCKETS` (1, 2-5, 6-10, 11-20, 21-49, 50); rows in `docs/analytics.md`.
- Tests: lane `test:goal` (core, verdict, prompts, reviewer, loop, round start, `main/handlers/goals.test.ts`, `renderer/shared/goal.test.ts`); reminder in `chat-frozen-state.test.ts`; a prefix case in `prompt-prefix-stability.test.ts`; analytics in `analytics-feature-reports.test.ts`.
- A4 desktop: `renderer/components/goal-bar.tsx` (`goalBarView`, `optimisticGoal`, `ChatGoalBar` with instant taps that roll back on failure) above the composer in `chat-pane.tsx`, before the spending notice. Query `useChatGoal` (`queryKeys.chatGoal`); `root-view.tsx` writes `chats:goal-changed` payloads straight into the cache and shows the settle notification (`renderer/lib/goal-notification.ts`, web `Notification`, skipped when `document.hasFocus()` and the route is `/chat/<id>`; it needs the previous cached view, which every round's broadcast provides).
