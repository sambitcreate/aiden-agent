# Create Images (CI-1) memory

- Flag: `AIDEN_EXPERIMENTAL_CREATE_IMAGES=1 npm run dev`. Default off; no store, ledger, IPC or route body without it.
- Caps: 1 provider request per Generate node; at most 4 per run; concurrency default 2, max 4; at most 4 active runs across all workflows. Plans are refused before consent when references can't be sent (model takes none, worst-case count over the model's limit or 4, known refs over 8 MiB / 40 MP). The storage headroom check runs one GC before refusing. `port.preflight` runs before the ledger claim, so local refusals are never "may have been billed". Storage full/unavailable after a paid request is `storage-full` / `storage-failed`.
- Modules: `main/services/create-images/` (run-ledger on node:sqlite, scheduler-core, run-executor, run-coordinator, consent-core, runtime, image-port); IPC in `main/handlers/create-images/`; UI in `renderer/images/`.
- Ledger: `run-ledger.ts`, restart sweep marks queued/running work interrupted and never resubmits. Retention keeps 100 runs plus each node's latest output, only for nodes still in the document (`liveNodeIds` from the workflow store's in-memory map); a deleted workflow keeps nothing; an unreadable workflow file (kept for repair) keeps all its latest outputs. Latest-output ordering uses the attempt id, never the wall clock. A corrupt or unsupported ledger is moved to `runs-v1.sqlite.corrupt-<ts>` and recreated (history only); a link/hard-link/foreign-owner ledger is refused, never moved. `CreateImagesRuntime.ready()` retries a failed open (5 s cooldown). On open, `reconcileImageHolds` makes `images-run:*` / `images-workflow:*` holds match the ledger and documents (stray holders released, missing holds re-held for assets that exist; Design holders untouched). Finding every stray holder needs the store's `holderIds(kind)` (added in PR #685); until that lands, `currentHolderIds` can only find holders on assets the ledger or documents still name, so a hold left on an otherwise unreferenced asset by a failed release stays until then. Perf lane: `npm run test:create-images:perf` (not in CI, per P1).
- Consent: single-use, bound to the document, expires after 5 minutes, digest re-checked at start.
- Retry: "Retry from here" (from-node) and "Retry this node only" (node-only), each with a fresh consent and its own request count.
- Delete: confirmation says "N images": Generate outputs plus the workflow's current Image Input assets (what delete releases). Busy workflows are refused. Released images are collected by the store's GC (startup, every 20 minutes, or before a quota refusal) once the 1 h grace has passed.
- Workflow files: ids are lowercase-only (all `randomUUID`); unreadable files stay on disk, are counted in a warning and can't be deleted from the UI; staging `.tmp` files are swept on initialize; `imageWorkflows:list` answers image-input ids from memory.
- IPC: 14 invoke channels plus 1 notification (budget 15). `gallery` and `image-action` added 2026-10-31 (ADR §2.11).
- See / explore / save (2026-10-31, ADR §2.11): `attempts.prompt` stores the exact prompt sent (written with the request claim, returned as `AttemptSnapshot.prompt`, deleted with its run; never in usage, analytics, logs or file names). `exports` table maps asset → auto-saved path. Both are added on every open if missing; `user_version` stays 1. `image-export.ts` (`CreateImagesExports`, Electron-free, injected root/fs/clock) auto-saves every stored Generate output in the background to `<Pictures>/Aiden/Create Images/<YYYY-MM-DD>/<HHMMSS> <title> <sha8>.<ext>`, written to a hidden `.aiden-<uuid>.tmp` in the day folder then hard-linked to the name (exclusive, ` (n)` on EEXIST; direct `wx` write where links are unsupported), so no truncated file ever shows under the real name; the title is cut between graphemes to 80 UTF-16 units / 180 UTF-8 bytes (`truncateFileNameText`, shared with chat's `safeFileNameStem`) for Linux's 255-byte NAME_MAX. Failures go to `reportIssue` with the error code only (never the fs message: it holds the path and title), never the run. Quit (`coordinator.shutdown`) waits up to 3 s for pending auto-saves before closing the ledger; main's image-runs budget is 5 s. `coordinator.whenIdle()` also waits for pending auto-saves. `gallery-core.ts` assembles the gallery (newest first by finish time, each asset once, collected assets dropped, `saved` = export recorded and file exists). Image actions are authorized only for ledger-known Generate outputs or `images-workflow`-held Image Inputs (else `not-found`); one image uses `ledger.generatedAsset` (SQL `instr` prefilter, exact check on the parsed output), Save All uses `ledger.generatedAssets` (one pass). A Save All that wrote some files answers `failed` with "saved N of M" plus `savedId`, so the toast still offers Show in Finder. Gallery dedupe is by asset id (content hash): byte-identical images show only under the newest run (accepted, documented in `gallery-core.ts`). Electron pieces are injected via `CreateImagesHandlerDependencies.files`.
- Tab panels: the shared `Tabs` takes `idBase` and `tabIds(idBase, value)` gives `{ tab, panel }`; the editor side panel and the Images home panels use `id` + `aria-labelledby` (not `aria-label`).
- Library (2026-10-31, ADR §2.11 "Library"): the Images home has **Workflows** / **All Images** tabs; the view is `/images?view=images` (`parseImagesHomeSearch` in `renderer/main/images-home-search.ts`, set with `replace`), so Back from a workflow returns to it; search/filters are component state and reset on leaving. Workflow cards (`workflow-grid.tsx`) take the newest image and count from the all-workflows `useGallery()`; the card's title button is the only opener (its `::after` stretches over the card) and its accessible name is the title alone (E2E relies on `list "Image workflows"` → `button "<title>"`). All Images = `image-library.tsx` + `library-toolbar.tsx` + `library-grid.tsx`, logic in `library-core.ts` (term-AND search over prompt/model id+label/workflow/node titles; facet counts follow search and the other facet; deleted workflows share the `:deleted` facet; local-day sections; `gridMove` geometry for ↑/↓). One shared `ContextMenu` for the whole grid (tile found from the event target), roving tabindex, viewer close returns focus by asset id (`libraryTileFor`, `data-library-asset`), viewer over the filtered list with Open Workflow (`ViewerAction.disabled(item)` added). Rename/delete on the home re-read the gallery (titles live on items).
- Pictures safety: `CreateImagesRuntime` saves nothing unless given `saveRoot` (only `main.ts` passes `app.getPath("pictures")/Aiden/Create Images`; tests pass a temp dir). The E2E bootstrap sets Electron's `pictures` path inside the fixture home, and `assertRuntimeIsolation` checks it.
- E2E: `tests/e2e/create-images.spec.ts` uses `fakeOpenRouter: true`. That sets `OPENROUTER_API_KEY` by env (the only allowed credential for that spec) and `AIDEN_E2E_OPENROUTER_REDIRECT_ORIGIN`. The bootstrap redirects the whole `https://openrouter.ai` origin to the loopback fake, which serves image generation only (everything else 503).
- Fixed in CI-1.9: canvas nodes stayed `visibility: hidden` because React Flow's measured sizes were not handed back (`measured` now passed through the flow adapter). The refusal message for a busy delete was cleared by the reload that followed it.
- Audit fixes (#383): node deletion is one undo step (React Flow `onDelete` -> `deletionOp`; change streams no longer emit removes). Leaving the editor saves first; a failed save blocks the route (`leave-guard.tsx`, TanStack `useBlocker`) with a destructive Discard choice, and the close guard is released only after a successful save. A conflict offers Keep My Version (re-read revision, save over) or Discard and Reload (confirmed). Main runs `window.__aidenFlushPendingSaves` (registered via `registerLifecycleFlush` in `renderer/lib/lifecycle-guard.ts`, bounded 3 s) before reading the close guard, so a quit inside the 800 ms debounce saves instead of prompting. Record lookups keyed by document ids use `ownValue` (own keys only). The run headline is the only `role="status"` in the editor. The E2E fake records `abortedRequests`, returns a distinct PNG per request, and `otherRequests` must stay empty (afterEach).
- Save states: an invalid save shows the server's reason with Retry and Dismiss; `not-found` is a distinct Deleted state (Back to Images), not a conflict; the viewport is clamped to schema bounds. The close guard is per source (`renderer/lib/lifecycle-guard.ts`: `editor` default, `images` with the workflow title), so the quit prompt names "the image workflow “title”" and the Files editor clearing its state no longer releases the Images guard.
