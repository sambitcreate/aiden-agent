# Generation timeline step bound (2026-10-29)

Every timeline reader rejects more than 200 steps (`MAX_GENERATION_TIMELINE_STEPS` in `renderer/shared/generation-timeline.ts`; iOS `AidenGenerationTimeline`, Android `AidenChat.kt`, OpenAPI `maxItems: 200`). Before this change `GenerationTimelineProjector` had no cap, so a run past 200 steps (about 100 tool calls with a thinking model) was saved with no timeline at all (`chat-store-core` `appendMessage` parses it), and Remote `run-event-projection` ignored every timeline event after step 200, freezing phone progress.

- The projector keeps every step internally (its `stepIndex` map and reasoning reconciliation use internal indexes); only `snapshot()` is bounded, through `boundGenerationTimelineSteps`.
- Fold order (reworked after review): drop the oldest settled tool steps by rank (routine read-only calls; plain calls, now including `run_command`; calls with a recap or that anchor images/visuals; failed ones). When a drop leaves two finished thinking steps adjacent at the same `contentOffset`, they merge, so thoughts stay in chronological place and reasoning stays fully covered. `subagent` and recording steps never fold. A drop is skipped if it would join two reply text rows (no kept neighbour at the same offset) or change the first step of an activity row holding an anchor or subagent (row keys use the first step id, so a change would remount iframes). Four passes: careful with the newest 40 kept, careful over everything, then relaxed (ignores the text/anchor rules, merges adjacent finished thoughts at any offset, may fold subagent/recording steps) with and without the tail. The relaxed passes matter for narrated runs (a line of text before every call, no thinking): every call sits at its own offset, so careful passes can drop nothing. Only running steps never fold, so the cap holds unless more than 200 steps are running at once. A merged group whose last thought is reopened keeps an open span (start, no end).
- Folding is sticky: the projector keeps a `GenerationTimelineFolds` (`dropped` ids, `mergedInto` map) and passes it on every `snapshot()`, so a step that settles later cannot bring back an earlier-dropped one.
- Trade-off: the summary sentence ("Explored N files") counts only the steps kept; a "N earlier steps" marker was considered and not built.
- No protocol revision: phones already accepted up to 200.
- Tests: the five long-run cases at the end of `main/services/generation-timeline.test.ts`.
