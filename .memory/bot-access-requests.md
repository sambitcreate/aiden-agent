It supports read/write authority and owner revocation for later plan approval. run.access is resolved on every bound file-tool call; protected roots and identity checks remain in the normal router. Read grants reject writes/edits, including codemode; independent fixed write grants remain valid. Terminal run states/delete/shutdown clear grants. Always goes through grantBotFolder in bot-application-service.ts, with a private atomic 0600 bot-folder-grants.json journal capped at 4,096 operations. The root ID is preallocated from operationId before creation. A shared reentrant root-inventory lock covers creation, compensation, ordinary access saves and phone approvals. New roots have botsOnly and botGrantOperationId; compensation removes only owned approval records unreferenced by committed Bot bindings, never filesystem folders or reused/shared roots. Recovery completes or compensates pending records before another grant. botFolderGrantPolicyRevision returns the exact verified publication receipt; stale answers never adopt a later policy revision.

Bot-only roots remain in the Bot catalog, including as unselected options for other Custom Bots, but stay out of phone browsing and Settings shared-root counts/lists. An explicit ordinary phone-root approval of that exact path clears botsOnly. Whole Mac is always once-only and cannot be persisted by an issue action.

request_access is model-only, safe replay, interactive and sequential. Only Custom scoped Bots receive it. Unattended routine/tg/bot/botreply turns raise private access_needed issues and never get a card. A persistable-folder issue can call grantBotFolder with its issue ID as operation ID; it validates captured policy/path identity but never resumes the old run or issues ephemeral access. A transient failed grant leaves the issue open. A definite stale live authorization ends as access_changed without a decline; changed persistent issue authorization produces a fresh immutable issue ID. All access issues can be dismissed through dismiss_access, without granting authority. Authorization remains in the private issue store and is stripped from public lists/transcript entries.
