Shared contract renderer/shared/bot-access-requests.ts owns strict bounded public cards and choices. BotAccessAuthorization is main-only even though its type/parser is shared: policy revision, run request IDs, target/root, pinned device/inode, choices, optional root ID and root-inventory hash. Main prompts also carry a live owner signal/deadline/validator. Public pending/get omit authorization, grant, logical request ID and owner. Deliberate reapproval gets a fresh waitId; unchanged live retransmission reuses one. Durable tool memo stores only a logical request ID.

bot-access-target.ts resolves canonical directories, file parents and ~ paths, pins device/inode, rejects private storage and prevents Always broadening to a parent or overlapping root. bot-run-access.ts is memory-only with a one-hour maximum and earlier owner expiry, exact policy revision and intersecting run inputs. It supports read/write authority and owner revocation for later plan approval. run.access is resolved on every bound file-tool call; protected roots and identity checks remain in the normal router. Read grants reject writes/edits, including codemode; independent fixed write grants remain valid. Terminal run states/delete/shutdown clear grants. Real harness tests distinguish joined steers from queued follow-ups, new runs and restart.

Always goes through grantBotFolder in bot-application-service.ts, with a private atomic 0600 bot-folder-grants.json journal capped at 4,096 operations. The root ID is preallocated from operationId before creation. A shared reentrant root-inventory lock covers creation, compensation, ordinary access saves and phone approvals. New roots have botsOnly and botGrantOperationId; compensation removes only owned approval records unreferenced by committed Bot bindings, never filesystem folders or reused/shared roots. Recovery completes or compensates pending records before another grant. botFolderGrantPolicyRevision returns the exact verified publication receipt; stale answers never adopt a later policy revision.

Bot-only roots remain in the Bot catalog, including as unselected options for other Custom Bots, but stay out of phone browsing and Settings shared-root counts/lists. An explicit ordinary phone-root approval of that exact path clears botsOnly. Whole Mac is always once-only and cannot be persisted by an issue action.

request_access is model-only, safe replay, interactive and sequential. Only Custom scoped Bots receive it. Unattended routine/tg/bot/botreply turns raise private access_needed issues and never get a card. A persistable-folder issue can call grantBotFolder with its issue ID as operation ID; it validates captured policy/path identity but never resumes the old run or issues ephemeral access. A failed grant leaves the issue open. Authorization remains in the private issue store and is stripped from public lists/transcript entries.
