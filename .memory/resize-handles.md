# Shared resize handle (UI SDK lessons unit 6, 2026-11-19)

- `renderer/lib/use-resize-handle.ts`: `useResizeHandle({ orientation, panel, value, min, max, disabled, onResize, onCommit, onResizingChange, onToggleCollapse })` returns the separator props (role, aria-orientation, rounded aria-valuenow/min/max, tabIndex 0 or -1 when disabled, onPointerDown, onKeyDown, onMouseDown). Steps are fixed at 16 / 40 (Shift). Options live in a ref, so the handlers are stable and inline callbacks are fine.
- `orientation` is the separator's own (vertical = between columns = width). `panel: "start" | "end"` is which side of the divider the sized panel is on; RTL (computed `direction` of the divider, read at press/keydown) flips only the horizontal axis. Aiden sets no `dir` anywhere and positions these panels with physical left/right, so the RTL branch is covered by the hook test only.
- Pointer: ignored when disabled, non-primary button, `!isPrimary`, or any of Shift/Alt/Ctrl/Meta. Captures the pointer (try/catch for synthetic events), listens on window filtered by pointerId, 3px threshold (`RESIZE_DRAG_THRESHOLD`, measured along the resize axis only) before `onResizingChange(true)` and the first `onResize`; body cursor (col/row-resize) and user-select none only while started. Release commits the clamped pointer position, pointercancel commits the last live size, a mouse move with `buttons === 0` ends it, unmount ends it and reports resizing false. A sub-threshold click calls nothing.
- Keys: Alt/Ctrl/Meta are left alone. Arrows on the separator's axis step (Shift = large), Home/End = min/max; each commits. Enter calls `onToggleCollapse` (not on `repeat`) only when given, else is not prevented.
- Users: SplitView sidebar in `ui.tsx` (start; Enter collapses and focuses the `[data-sidebar-toggle]` button via `returnFocus` in a rAF, since the divider goes tabIndex -1), `WorkbenchPanel` (end; Enter = `onClose`, whose Environment and Bot implementations already return focus), `DesignChatDivider` (start; no collapse), terminal drawer (horizontal, end; Enter = terminal `toggle`, which returns focus to `[data-terminal-toggle]`). Focus line switched from `bg-accent` to `bg-focus-ring` on all four.
- Behavior changes: resizing state starts at the threshold, not on press; the terminal drawer now saves its height after keyboard resizes too (it only saved after drags); the sidebar drag now captures the pointer and handles pointercancel.
- Not folded in: browser viewport and floating-browser handles (2-D edges/corners), device mini player edges, Quick View grips (reordering, not resizing).
- Tests: `renderer/lib/use-resize-handle.test.tsx` (threshold, guard, drag clamp, cancel, keys, panel end, horizontal, RTL, Enter, unmount, plus SplitView drag-save and Enter-collapse focus). In `test:command-system` and the registry lane beside `use-sidebar-view.test.tsx`. `design-layout.test.tsx` drag now passes `isPrimary` and matching `pointerId`s. Gotcha: `assert.equal(elementA, elementB)` failing on happy-dom elements builds a diff of the whole DOM and ran the process to 6 GB; compare attributes instead.
- Review nit (2026-11-19): `onMouseDown` preventDefault keeps a mouse press from focusing the divider, because otherwise focus stayed on it after a drag and the next Enter (meant to send) closed the panel. Chosen over a `:focus-visible` check on Enter, since the app hides rings after pointer input and happy-dom cannot test `:focus-visible`; Tab focus is unaffected. Divider keys are listed in `docs/keyboard.md`. The terminal drawer has no rendered test (its suite only greps source and rendering it needs the PTY and Ghostty stack), so its Enter and ArrowUp saving are covered only through the hook.
