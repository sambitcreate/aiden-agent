# Inline generative UI (Phase 1, desktop)

Spec: `docs/superpowers/specs/2026-10-08-inline-generative-ui-design.md`. Plan: `docs/superpowers/plans/2026-10-08-inline-generative-ui-phase-1.md`. Branch `feature/inline-generative-ui`.

## Decisions that are easy to undo by accident

- **Placement lives beside, not inside, the artifact.** `ChatMessage.htmlArtifactPlacements: [{mediaId, toolCallId}]`. `parseChatHtmlArtifacts` is all-or-nothing with exact keys, so adding a key to `ChatHtmlArtifactV1` makes older builds drop every artifact on the message. The placement parser is deliberately lenient and ignores unknown keys. Placements also carry `layout: "wide"` (only wide is stored; absent means the reading column). The model picks it via `render_artifact`'s `layout` argument; the ledger keeps the first call's position but the latest call's layout. Wide CSS measures the pane with `100cqi` against `[data-scroll-content]:has(> .chat-content-column)` (a size container), uses a 1.5rem gutter rather than the 4.5rem dock gutter, caps at 80rem, and stays in the column beside a docked Quick View card.
- **Focus ring is Tab-only.** The host draws the guest focus ring only when a Tab keydown in the host preceded focus entering the iframe (500ms). A click into a visual draws none: it used to look like a dark border around the visual, and the user asked for it gone.
- **Public call ids.** Timeline steps publish `call-N` ids (`GenerationTimelineProjector.toolStarted`), not Pi's raw provider ids. Anything that matches a visual or draft to a row must translate through `timeline.publicToolCallId`. `generative-ui-placements.ts` and the draft session already do. Unit tests with identical ids on both sides will not catch a regression here.
- **HTML never reaches the renderer as a string.** Previews and drafts are `aiden-genui://preview/<token>` URLs from `generative-ui-preview-store.ts` (Electron-free and testable; the protocol delegates to it). Drafts are single-use streaming responses whose CSP is nonce-only (`generativeUiDraftCsp`), so model scripts never run before the final artifact.
- **Bridge contract.** The schema is closed (`renderer/shared/generative-ui-bridge.ts`): escape, ready, resize, prompt. The host accepts a message only when `event.source === iframe.contentWindow`, and rejects it when `contentWindow` is null. `window.aiden` is frozen and non-configurable, and configurable, so a guest's own top-level `aiden` shadows it.
- **sendPrompt is confirm-only (owner decision 2026-10-09).** A visual's `sendPrompt` can never send as the user. `admitGuestPrompt` bounds the size and rate-limits it, and `HtmlArtifactFrame` then shows an Aiden-drawn chip (Send / Add to draft / Dismiss). Only a click on that app UI calls `GuestPromptHandler(text, mediaId)`, which goes through `handleSend` or `stageComposerText` when busy. Gesture attribution was tried and removed: guests can `focus()` themselves, `navigator.userActivation` is page-wide, and out-of-process frames never deliver `pointerenter` to the page (Electron), so three review rounds broke it and real clicks only staged. Do not reintroduce auto-send on browser signals. `window.aiden` is configurable on purpose, so guests that declare their own `aiden` still run.
- **Height** is `document.body.scrollHeight` of an inline body that is a positioned flow root without min-height. The root's `scrollHeight` never drops below the viewport; a rect misses absolute and overflowing children. A ResizeObserver plus a MutationObserver re-measure; the MutationObserver callback must never mutate the DOM (a dataset write there once looped forever). `font-size` is set on `body` only, so `rem` stays 16px (Design Studio and exports depend on it).
- **Theme.** Guests receive only allowlisted variables (`GENERATIVE_UI_THEME_VARIABLES`), validated by `sanitizeGenerativeUiThemeVars`. Radius tokens are Tailwind `@theme inline` constants (not present at runtime), so the kit uses fallbacks. Without a renderer theme (export), `GENERATIVE_UI_DEFAULT_THEME_VARS` is emitted. The light `--chart-*` values are deepened bot-avatar hues; dark mode uses the hues as-is. Legacy four-color callers (`DesignPreviewTheme`, no `vars`) derive `--text-primary`/`--focus-ring`, the secondary text tokens and `--accent` from their hex colors before explicit `vars`, which still win; otherwise dark Design previews got light-theme text. On a theme message the bridge remaps Chart.js dataset colors that equal an old `--chart-N` value to the new one (custom colors untouched), because `aiden.series()` hands out copied strings.
- **Handoff.** Visuals render inside `AssistantResponse` rows, so the iframe remounts once at stream→settled handoff. A module-level preview/height cache avoids a refetch and a height jump, but guest state set during a running turn resets. This is an accepted trade-off, open for a later restructure.
- **Availability.** Visuals are available in every attended desktop chat. `path` needs a workspace with file access. `AppearanceConfig.inlineVisuals` is sent per turn as `GenerationParams.inlineVisuals`.
- **Remote/mobile.** Phase 1 left the contract at revision 26 and forced phone-sent turns off. Phase 3 changed both (below).
- **Phase 2: native visuals (`render_ui`).** Branch `feature/inline-generative-ui-catalog` is stacked on PR #429. The full design is in `docs/pi-gui-artifacts.md` (Native visuals).
  - **Tool registration.** `render_ui` lives in the same generative-ui extension as `render_artifact` (one gate, setting and registration). It is offered only when the host passes `onUiVisual`, which desktop does and Design runs do not.
  - **Compiler and catalog.** The compiler and catalog are shared pure TypeScript in `renderer/shared/aiden-ui/`.
    - Parser rules: `Code`, `Math`, `Markdown` and `Data` bodies are raw text, so braces in LaTeX and code never parse as expressions. `Text` accepts inline `Kbd`, `Badge`, `Icon` and `Math`.
    - The expression AST keys (`op`, `v`, `name`, `of`, `key`, `o`, `l`, `r`, `e`, `test`, `then`, `else`, `fn`, `a`; actions `act`, `text`, `key`, `value`, `url`) and every catalog prop are wire-safe (`isWireSafeKey` mirrors the phones' private-key validators). Keep it that way, or Phase 4 cannot ship trees to phones.
  - **Storage.** `ChatMessage.uiVisuals` is parsed leniently. Local state is saved with `chats:updateUiVisualState` (no metadata bump), 800 ms after the last change. State changed while the visual is still streaming is not saved and resets at settle.
  - **Live events.** `ui` and `ui_draft`, retracted with `draft_end`. llm-client fans one `visualDrafts` object out to the HTML and UI draft sessions.
  - **Renderer.**
    - `AidenUiBlock` and the catalog component map live in `renderer/components/aiden-ui/`. Placement uses `renderer/lib/ui-visual-transcript.ts`.
    - Chart.js is imported lazily (`chart.js/auto`, its own chunk) behind the `setChartModuleLoader` test seam.
    - Radix roving focus moves asynchronously in happy-dom, so wait for it with `waitFor`. A modal Dialog hides the rest of the page from role queries until it closes.
  - **Shared primitives.** `renderer/components/ui-primitives.tsx` holds Segmented, Tabs, Checkbox, Slider, Progress, Tooltip, Disclosure, Kbd, Stat and DataTable.
    - Scheduled tasks' status filter is a Segmented radio group, so its e2e uses role `radio` and `aria-checked`.
    - The update and runtime-install progress bars use `Progress`.
    - The global `:focus-visible` rule already draws the neutral ring for buttons, radios, checkboxes and `[tabindex]`, so primitives add no focus classes.
  - **Onboarding.** Tile `inlineVisuals` with `features/inline-visuals.png`, an SVG composed in the clay style and rasterized with Playwright `omitBackground`. `npm run assets:onboarding` also rewrote `tool-scripts.png`; restore unrelated assets after running it.
- **Phase 3: snapshots and Remote (contract revision 28; renumbered from 27 at the main merge, where Bot memory took 27).** Same stacked branch. Design in `docs/pi-gui-artifacts.md` (Snapshots and paired devices) and `docs/aiden-remote-api-v1.md` (Inline visuals, revision 27).
  - **No tree on the wire.** `visuals` carries only id, kind, title, toolCallId, fallbackText, snapshotAttachmentId and layout. Markup, `dataJson` and saved state stay on the Mac; Phase 4 adds the tree behind its own opt-in.
  - **Reserved snapshot ids.** Snapshots are ordinary image attachments with id `visual-snapshot_<sha256(chat, message, visual)>`, linked by `visualSnapshots`. `withoutVisualSnapshots` keeps them out of image limits and every model input; the desktop strip hides one only beside the visual it pictures (`attachmentsShownWithVisuals`), so a paired Mac's chat shows it. Clients hide attachments named by any `snapshotAttachmentId`.
  - **Capture.** A hidden sandboxed `BrowserWindow` on the default session, one capture at a time with a 6 s timeout, light theme only, 720/1024 px at the display's scale. The window is marked auxiliary (`main/windows/auxiliary-windows.ts`), so Remote "focus app" and bot setup never pick it, and `shouldReleaseAuxiliaryWindows` releases it when it is the last window and closing should quit.
  - **Containment.** The guest is inlined as `srcdoc` (not its `aiden-genui:` preview URL: Chromium gives that site one shared renderer, so a runaway guest there would stall every later capture and the chat's own frames). A srcdoc document inherits its host's CSP, so the data: host page uses `GENERATIVE_UI_GUEST_CSP` with `frame-src about:srcdoc` (host libraries load, no network), and the window refuses every other frame navigation. An aborted capture destroys its own window, fenced by identity. Pinned by the e2e tests "snapshots run guest HTML offline…" (leak, margin and library probes) and "a runaway visual is abandoned…". HTML is wrapped `inline` (font size and margin measurement match the desktop) with `stillImage`, which turns Chart.js animation off. Pinned by the e2e "snapshots run guest HTML offline…".
  - **Revision.** Visuals feed `chatRevision`, so a late snapshot makes phones refetch. The protocol parser drops a malformed visual (or one with unknown keys, or a snapshot id that isn't an attachment on the message) and keeps the message.
  - **Phones.** iOS (`AidenChatVisual`, `AidenChatVisualPresentation` in `Models/AidenChat.swift`) and Android (`AidenChatVisual`, `AidenChatVisualListSerializer` in `models/AidenChat.kt`, row helpers in `AidenChatDetailScreen.kt`) decode visuals per entry and place each after the tool step that drew it, splitting a same-offset tool group at that step. A snapshot counts only when exactly one PNG/JPEG with that id is on the message. An html visual without one gets no row; its can't-view card stands for it. iOS keeps an unknown kind as `.other`; desktop and Android drop it. Live streaming rows never carry visuals.
  - **Remote turns.** `remoteGenerationSurface` follows the Mac's Appearance setting (injected `inlineVisuals()` reading `configStore` appearance) and sets `visualAudience: "remote"`, which adds a system-prompt note that readers see still images.

- **Phone viewer (contract revision 35, provisional; `chat-visual-viewer-v1`).** Owner chose tap to open (2026-10-16). Plan: `docs/plans/phone-visual-viewer-plan.md`.
  - `GET /chats/{chatId}/visuals/{visualId}/document?scheme&theme` returns one self-contained HTML document (`main/services/visual-viewer-document.ts`, Electron-free). Visual entries gained no key: their parsers are closed on every client, so a new key would drop all visuals on older phones.
  - The viewer page is `renderer/visual-viewer/main.tsx`, built by `vite.visual-viewer.config.ts` (lib IIFE, assets inlined, KaTeX woff/ttf stripped) into `build/renderer/visual-viewer/` after the main renderer build. The feature is announced only when those files exist (`visual-viewer-main.ts`).
  - Theme: the page applies the phone's preset with `resolveThemeTokens` (no storage; opaque origins throw on localStorage). HTML guests start with light defaults, so the iframe stays hidden until the guest's `ready` gets a theme message.
  - HTML guests inline only the host libraries their source names (`Chart`, `Plotly`, `katex`). `inlineGenerativeUiHostLibraries` is shared with export (and the CLI) and uses a function replacement so `$&` in library source stays literal.
  - Native channel: iOS `aidenVisual` handler, Android `AidenVisualBridge`; messages `ready`, `prompt`, `openUrl`. `AidenUiBlock` takes `onFollowUp` so the viewer hands prompts to the phone instead of drawing its own Send chip; the phone confirms and only fills the composer. Links use `ExternalLinkOpenerProvider`.

Every ambiguous place (a `/` after `}`, a non-head `)`, `++`/`--`, `yield`/`await`/`of`; `<!--`; line-start `-->`) records a fork; `findJsSink` reads each fork the other way (`readOtherWay`) until it meets the first reading (same offset, pointer-equal stacks, same line-break flag, same last three tokens; round 6 removed the old 2048-char cutoff, see below), copies the call frames at the fork and at the meeting point during the main scan, scans lead (8) + other tokens + 8 trail tokens (extended to finish a `+` chain of literals) from the fork's frames, and if the frames then differ from the main scan's at the meeting point keeps scanning the first reading with this reading's frames until the differing frames close. All of it is charged to one budget (8 units per character + 65,536; a char read, token scanned or frame copied is one unit; scan-fp corpus passes at 1/char); over budget is `limit` "a script reads two ways in too many places" (refused as too complex). Perf at ~300 KB under load ~200: adversarial shapes 100-600 ms (old lexer ~100 ms), realistic ~200 ms. Tests: 15 REFUSED_MARKUP entries (script + onclick) failing on the old lexer, 2 ADMITTED (regex after a block, division after a template).

- Review round 6, item 1 (2026-11-19): `readOtherWay` gave up after 2048 characters, so a sink more than 2 KB after an ambiguous `/` was admitted (`var x = {} /`/;` + 2 KB of comments + `${SINK}`). Now the second reading goes on until the readings meet or the code ends, with every character charged to the one budget. Over budget means `limit` (refused as too complex). Reading to the end alone refused realistic 60 KB code, because a reading that starts after `i++ / 2;`, with a template later on the line, never rejoins: the backtick parity flips.
