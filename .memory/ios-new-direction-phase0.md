# iOS new direction, Phase 0 (quick wins)

Branch `claude/ios-direction-phase0` (2026-11-24). Plan: `docs/plans/ios-new-direction-upgrade-plan.md` on the `ios-new-direction` worktree.

- **Workspace Settings sheet.** `AidenWorkspaceDetailView` presents settings with `.sheet(item:)` over an Identifiable `AidenWorkspaceSettingsPresentation` that carries the request context. The old `isPresented` sheet could render before the context arrived and showed a blank page. `AidenShellUITests.testWorkspaceSettingsOpensWithItsFormEveryTime` opens it repeatedly. Checked on the iPhone Duo inner display at regular width; the fold itself can't be driven from simctl (CoreSimulator has no fold API and Xcode 27.1 ships no Simulator.app).
- **Workspace Git summary.** Git is off the request path. `AidenRemoteWorkspaceGitCache` (`aiden-remote-workspace-git-cache.ts`) is a stale-while-revalidate cache keyed by repository root (a folder whose root isn't known yet is keyed by its own path): `peek` answers synchronously and queues a background refresh when the entry is missing or older than 30 s. Refreshes run 3 at a time, one per key, each under a 15 s deadline; a failed or timed-out read clears that folder's summary and backs it off (30 s x 2^failures, capped at 30 min); a slot stays held until the read itself settles. Reads go through `GitService.workspaceSummary`, which reports `isRepo: false` only for exit 128 "not a git repository" with no `.git` entry at or above the folder, and throws for a missing folder, broken repository or anything else. List, get and update peek; create's durable action projects without `git`; MCP's `offeredWorkspaces` (workspace list and chat start) calls `list({ git: false })`. The projection omits `branch` on a detached HEAD and cuts it at 255 code points. Revision never depends on `git`, so iOS's `.id(workspace.revision)` doesn't rebuild on a refresh. Desktop and `aiden serve` both wire `new AidenRemoteWorkspaceGitCache({ read: gitWorkspaceSummary })`; the host feed stays Git-free.
- **Copy and icons.** The tidied-memory receipt uses `AidenBotMemorySymbol.name` (SD card), never `memorychip`. Usage cards lost their 0.5 pt decorative stroke. "Erase memory" is "Forget all" on desktop, iOS and Android; the unreadable callout reads "Its files may be damaged. Choose Forget all to start {name}’s memory fresh." on all three. Bot first-run copy is sentence case everywhere. The Bot composer reads "Message {name}" when nothing holds it on desktop (`bot-chat-pane.tsx`, `remote-bot-chat-view.tsx`), iOS (`AidenBotSessionCopy.composerPlaceholder`) and Android (`aidenBotChatPlaceholder`, "Message your Bot" with no name).
- **Android.** Every user-facing "your Mac" that means the paired computer now says "your computer", matching iOS. The memory load failure reads "Memory couldn’t be loaded. Make sure your computer is on and nearby." Kept on purpose: the Simulator strings (iOS Simulator is Mac-only), `bot_activity_computer` "Using your Mac" (the phase table shared with desktop `bot-activity.ts` and iOS), and `AidenApprovalCard.ALLOW_ON_MAC` (a mirror of the desktop's own `allowOnMac` line). Text the server sends ("Run on your Mac?", refusals) is the server's.
- **Demo memory and responder.** The demo Bot's memory is a small store per machine (`AidenDemoBotMemory`, a `Mutex` around the view): an edit is decoded from the request body and applied with `AidenBotMemory.applying`, so a delete or rewrite changes only its entry, a stale one answers 404 `memory_entry_not_found`, and Forget all empties both groups; each edit gets a new revision. `AidenDemoResponder` is checked `Sendable`: one `Mutex<State>` holds routes, holds, parked requests and logs (holds are ids, a parked request captures the responder weakly, so a hold nobody releases no longer leaks it), delays use `Task.sleep`, and `reply(...answering:)` gives a route the request body. `AidenDemoURLProtocol` keeps `@unchecked Sendable` only for Foundation's unannotated `URLProtocol` base; its own state is a `Mutex`. `AidenBotMemoryModel.lane` stores the newest edit's Task and an `isolated deinit` cancels it (a sending edit holds the model, so this never drops a started edit).
- **Known follow-ups.** (1) iPhone Duo fold: switching between the split and the stack rebuilds `AidenWorkspaceDetailView`, so an open Workspace Settings sheet and its unsaved name close. The fix is shell-owned presentation and draft (the `AidenOfflineNoticeDismissals` pattern), with the sheet hosted above the split/stack switch; recorded in `docs/plans/ios-iphone-duo-plan.md` Phase 4. simctl can't fold, so it needs a device or a fold API. (2) `AidenWorkspacesTabView` gives the detail `.id(workspace.revision)`, so a rename on the computer closes the open sheet too; the Git summary never changes the revision. Both predate Phase 0.
