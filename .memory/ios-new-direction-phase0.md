# iOS new direction, Phase 0 (quick wins)

Branch `claude/ios-direction-phase0` (2026-11-24). Plan: `docs/plans/ios-new-direction-upgrade-plan.md` on the `ios-new-direction` worktree.

- **Workspace Settings sheet.** The shell presents settings with `.sheet(item:)` over the Identifiable `AidenWorkspaceSettingsDraft`, which carries the request context (see the theme F bullet). The old `isPresented` sheet could render before the context arrived and showed a blank page. `AidenShellUITests.testWorkspaceSettingsOpensWithItsFormEveryTime` opens it repeatedly. Checked on the iPhone Duo inner display at regular width; the fold itself can't be driven from simctl (CoreSimulator has no fold API and Xcode 27.1 ships no Simulator.app).
- **Workspace Git summary.** Git is off the request path. `AidenRemoteWorkspaceGitCache` (`aiden-remote-workspace-git-cache.ts`) is a stale-while-revalidate cache keyed by repository root (a folder whose root isn't known yet is keyed by its own path): `peek` answers synchronously and queues a background refresh when the entry is missing or older than 30 s. Refreshes run 3 at a time, one per key, each under a 15 s deadline; a failed or timed-out read clears that folder's summary and backs it off (30 s x 2^failures, capped at 30 min). Failures live in their own map keyed by folder, so a failure in a repo's root folder only marks the shared root entry stale and other folders keep their summary with no back-off. A read past its deadline gives up its slot (at most 8 at once, `maxAbandoned`; past that it keeps the slot) but keeps its key until it settles, so one dead mount holds at most one read. Reads go through `createGitWorkspaceSummaryReader()` (`gitWorkspaceSummary`), a separate `GitService` whose per-command timeout is the cache's 15 s deadline instead of the 4 s default other callers keep, then `GitService.workspaceSummary`, which reports `isRepo: false` only for exit 128 "not a git repository" with no `.git` entry at or above the folder, and throws for a missing folder, broken repository or anything else. List, get and update peek; create's durable action projects without `git`; MCP's `offeredWorkspaces` (workspace list and chat start) calls `list({ git: false })`. The projection omits `branch` on a detached HEAD and cuts it at 255 code points. Revision never depends on `git`, so iOS's `.id(workspace.revision)` doesn't rebuild on a refresh. Desktop and `aiden serve` both wire `new AidenRemoteWorkspaceGitCache({ read: gitWorkspaceSummary })`; the host feed stays Git-free. Follow-up, not built: nothing pushes a fresh summary to a phone; it shows on the next workspace read (listed in `docs/plans/aiden-on-the-go-plan.md`).
- **Copy and icons.** The tidied-memory receipt uses `AidenBotMemorySymbol.name` (SD card), never `memorychip`. Usage cards lost their 0.5 pt decorative stroke. "Erase memory" is "Forget all" on desktop, iOS and Android; the unreadable callout reads "Its files may be damaged. Choose Forget all to start {name}’s memory fresh." on all three. Bot first-run copy is sentence case everywhere. The Bot composer reads "Message {name}" when nothing holds it on desktop (`bot-chat-pane.tsx`, `remote-bot-chat-view.tsx`), iOS (`AidenBotSessionCopy.composerPlaceholder`) and Android (`aidenBotChatPlaceholder`, "Message your Bot" with no name).
- **Android.** Every user-facing "your Mac" that means the paired computer now says "your computer", matching iOS. The memory load failure reads "Memory couldn’t be loaded. Make sure your computer is on and nearby." Kept on purpose: the Simulator strings (iOS Simulator is Mac-only), `bot_activity_computer` "Using your Mac" (the phase table shared with desktop `bot-activity.ts` and iOS), and `AidenApprovalCard.ALLOW_ON_MAC` (a mirror of the desktop's own `allowOnMac` line). Text the server sends ("Run on your Mac?", refusals) is the server's.
- **Demo memory and responder.** The demo Bot's memory is a small store per machine (`AidenDemoBotMemory`, a `Mutex` around the view): an edit is decoded from the request body and applied with `AidenBotMemory.applying`, so a delete changes only its entry, a rewrite gives its entry a new id (a Mac's id hashes the text), an edit naming an id the view no longer holds answers 404 `memory_entry_not_found`, and Forget all empties both groups; each edit gets a new revision, and a repeated `Idempotency-Key` replays that key's first successful answer instead of applying the edit again. `AidenDemoResponder` is checked `Sendable`: one `Mutex<State>` holds routes, holds, parked requests and logs (holds are ids, a parked request captures the responder weakly, so a hold nobody releases no longer leaks it), delays use `Task.sleep`, `reply(...answering:)` gives a route the request body, and `reply(...answeringKeyed:)` also its `Idempotency-Key`. `AidenDemoURLProtocol` keeps `@unchecked Sendable` only for Foundation's unannotated `URLProtocol` base; its own state is a `Mutex`. `AidenBotMemoryModel.lane` stores the newest edit's Task so the next edit waits for it; nothing cancels it, so leaving the page never drops an edit the person already made (the earlier `isolated deinit` cancel could never fire, because each queued job holds the model, and was removed).
- **Workspace Settings across a fold (done, theme F).** The shell owns the sheet: `AidenWorkspaceSettingsSheet` (in `AidenAppShellParts.Built`, passed down as `\.aidenWorkspaceSettings`) holds an `AidenWorkspaceSettingsDraft` (workspace id, fixed owner context, name/permission/memory edits, the workspace as the computer last described it). `aidenWorkspaceSettingsPresentation` presents it after `.id(navigation.besideList)`, so a fold or the page's `.id(workspace.revision)` rebuild keeps it. It follows `AidenWorkspaceSettingsSource.current` (route lookup plus owner context): untouched fields follow the computer; an edited name, permission or memory switch stays, and `nameOnComputer` / `permissionOnComputer` / `memoryOnComputer` show the computer's own change in that section's footer ("Changed … on your computer"); Save sends only changed fields against the latest workspace. Save is optimistic (owner rule, /tmp/ios-direction/optimistic-rule.md; reworked in review round 3): the sheet calls `coordinator.enqueueWorkspaceSave` synchronously and dismisses. `AidenHostConnection` keeps `confirmedWorkspaces` (the baseline: what the machine answered) and `workspaceEdits` (a versioned optimistic overlay); `workspaces` is baseline plus overlay, snapshots only replace the baseline, and `supersededWorkspaceRevisions` keeps a list read before a save landed from restoring the old copy. Only the baseline is persisted. The coordinator runs one serial FIFO lane per (instance, hostGeneration, workspace) (`AidenWorkspaceSaveLane`): an unsent save made on the same base revision coalesces; each send uses the confirmed revision when it is the base or one of this phone's own answers (`ownRevisions`, including a reconciled ambiguous success), else the base so a computer-side change gets a 409. Lanes are cancelled on a pairing change or revocation. A failure settles its edits (falling back to the baseline under newer edits) and sets `workspaceSaveNotices[AidenHostObjectID]` plus an error haptic, never `presentedError`; the notice (`AidenWorkspaceSaveNoticeRow`) shows in the sheet and at the top of the workspace page until dismissed. Footer attribution (`nameOnComputer` etc.) compares confirmed copies, so a rollback isn't blamed on the computer. Owner Remove (review round 4) joins the lane: it awaits the tail, sets `lane.waiting = nil` so later saves queue behind it, and shows pending through `workspacesBeingRemoved` (Removing… in the sheet); a second Remove joins `lane.removal`. Its revision is the confirmed one when it is this phone's own answer, else the workspace's. On success it sets `lane.removed`, so later saves settle as `.stale` and `enqueueWorkspaceSave` returns nil, and without a canonical list it falls back to `confirmedWorkspaces` minus the workspace (never `workspaces`, which would persist another workspace's unconfirmed edit). `settleWorkspaceEdits` only writes an answer when the confirmed copy is present and not newer by `updatedAt` (revisions are hashes), so a late answer never overwrites a newer list or revives a removed workspace. `cancelWorkspaceSaves` also cancels the removal and drops notices and pending removals; it runs on re-pair, revoke (foreground and background) and purge. Saves and removals run under `beginBackgroundTask` (`AidenBackgroundTime`). The failure notice posts a VoiceOver announcement, Dismiss has a 44 pt target, and the workspace page shows it as an overlay so the list doesn't jump. The `.busy` branch remains for the non-owner path. Remove failures still use the alert. Review round 5 changed that: owner Remove is optimistic (`enqueueWorkspaceRemoval` returns a Task or nil; `AidenHostConnection.hideWorkspace`/`showWorkspace` keep a `hiddenWorkspaceIds` overlay, and `adopt` keeps a hidden workspace's confirmed copy until the removal settles), the button never turns into a spinner, and a refusal shows the workspace again with a `workspaceSaveNotices` note, never `presentedError`. A successful removal drops its lane, and `pruneWorkspaceSaveLanes` drops idle lanes for workspaces no longer confirmed, so a workspace the Mac recreates ("default") takes saves again. `enqueueWorkspaceSave` also returns nil when the workspace isn't confirmed; the sheet and Workspaces show a quiet refusal note on nil instead of a success haptic. Workspaces (`AidenWorkspaceDirectoryView`) rename/remove go through the same lane with the owner context. Background time starts at enqueue. `settleWorkspaceEdits` now decides a late answer by revisions (`answer(_:replaces:superseded:)`: drop an answer whose revision was superseded; take it when the current copy is the same revision or superseded; else only a strictly newer `updatedAt`), since the host's `updatedAt` is millisecond `Date.now()` and can tie (Pullfrog 4691464777). `nextWorkspaceEditVersion` is intentionally never reset (R5-7). Review round 6: a removal whose read-back fails drops only the confirmed copy at the revision the DELETE sent, so a same-id replacement a poll installed stays (Pullfrog 4691622784); `adopt(workspaces: [])` keeps no workspace waiting for removal (the hidden mark stays until the removal settles); Directory row swipe/menu Rename and Remove are disabled only when not connected, never by `isMutating`; a refused tap posts a VoiceOver announcement (`refuse(_:)` in both views); the refused-removal ordering test counts PATCHes inside the DELETE's answer instead of sleeping. Tests in `AidenOwnerRoutingTests` (queued order and revision chaining, stale list, rollback with notice under a newer edit, reconciled success chaining, Remove waiting, a save during Remove dropped after it or sent after a refused one, the removal fallback keeping another workspace's failed rename out of the cache, a late answer after a newer list or a removal, queued saves failing offline, forgetting a machine mid-save) and the Save-closes step of `testWorkspaceSettingsOpensWithItsFormEveryTime`. Server side, `AidenRemoteWorkspaceGitCache` skips a folder already being read (`inFlightFolders`). It closes on a removed or archived workspace, a nil owner context or one with a different lease (instanceId, deviceId, hostGeneration; the activation `generation` is ignored, so the machine becoming the default keeps it open), the default machine moving off its machine (`defaultMachineChanged(from:)`), or its route leaving every list tab (`AidenAppNavigation.holdsWorkspace`). The detail view only calls `present` (its unused `onRemoved` callback is gone). Tests: four state tests plus a hosted split/stack swap test in `AidenAppShellTests`, and the iPad UI test `testWorkspaceSettingsKeepTheirEditsWhenTheWindowChangesWidth` (on the local iPadOS 27.0 simulator windows don't resize, even with SpringBoard windowing defaults written, so it skips after the edit). A hosted test that moves the presentation inside the `.id`'d content fails, so the hosted test does guard the placement.
