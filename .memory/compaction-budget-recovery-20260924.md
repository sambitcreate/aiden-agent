# Oversized LLM compaction recovery — 2026-09-24

Production Aiden 0.43.0 had a chat created under Z.ai GLM-5.3 (1,000,000-token context) that later switched to Codex GPT-6 Astra (272,000-token context). After two `Connection error.` provider attempts, the next `Continue` failed during preflight compaction. The pre-checkpoint journal held about 258,579 estimated tokens; Pi's first summary request required 251,994 input + 13,107 output + 13,600 safety = 278,701 tokens. Aiden's guard correctly rejected it before provider I/O, but there was no recovery route. The installed diagnostic journal retained only `context_management` and attempts 0, obscuring the local budget cause.

The shared coordinator now catches only its typed summary-budget rejection. It compiles the same prepared branch with the bounded, isolated VCC worker without publishing a checkpoint, then sends the reduced text through Pi's ordinary bounded LLM summary. The original retained tail, file-operation evidence, leaf fence, rollback, cancellation and final checkpoint publication remain authoritative. If local reduction or the second bounded summary fails, the branch remains unmodified. Ordinary fitting summaries and provider failures do not enter this route.

Main diagnostics now record closed compaction budget/failure/recovery events with aggregate token counts, stage and fixed local-compiler cause, without prompt or provider text. The existing provider-failure event gains a fixed transport-cause category; `Connection error.` becomes `connection-error`. The renderer failure DTO and native `compact_context` activity contract are unchanged. iOS and Android consumers were inspected; no native implementation or suite is required for this host-only change. No onboarding or plan status changes.

The registered compaction (347 tests), diagnostic, and provider-failure suites pass locally, as do type-check, focused lint, renderer Vite build, Electron bundle build, and diff checks. The full `npm run build` stops while compiling an unrelated Bot inbox native helper because its fixed child environment selects a broken Command Line Tools SDK; a parent-scoped Xcode beta setting is dropped. Hosted PR CI and installed production acceptance remain separate gates.

Review follow-up (2026-09-25, Pullfrog on 4d9b99a3): recovery no longer collapses Pi's preparation into one synthetic message. Each prepared channel is reduced separately by VCC through a synthetic self-contained branch: `messagesToSummarize` always, and `turnPrefixMessages` when the turn is split. `previousSummary` and `isSplitTurn` pass through untouched, so Pi's update prompt still merges the prior checkpoint and a split turn still gets its dedicated turn-prefix summary. A channel VCC cannot shrink (`insufficient_reduction`) stays raw; its own bounded request still fails closed. With nothing to summarize (everything retained), recovery makes no local compile and reports the budget failure. `compactionFailureDiagnosticFields` classifies the caught error first (journal, summary-budget, summary-provider, local-compiler, host-*); `budget-recovery` is only the fallback when recovery was attempted and nothing more specific applies; `recoveryStage` and budget counts still record the attempt. `socket hang up` now maps to transport cause `socket-closed`.

Review follow-up 2 (2026-09-25, Pullfrog on f15fcf2a): each recovery channel is now budgeted against the complete request Pi will send for it. `summaryRequestSpareTokens` runs Pi's own `compact` against a probe `Models` whose `completeSimple` measures the request with the same estimator as the budget guard (`summaryRequestTokens`: prompt, preserved `previousSummary`, output allowance, 5% safety) and throws before any I/O. A channel whose raw request fits stays raw. Otherwise VCC gets the content budget (spare tokens with an empty conversation) as its input budget, the reduced request is re-measured, and up to three attempts tighten by the measured overshoot; if none fits, recovery fails closed as `local-compiler`/`insufficient_reduction` with no provider request and the journal unchanged.
