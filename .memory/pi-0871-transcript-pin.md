# Pi 0.87.1 transcript-owned prompt pin (2026-09-24)

This branch pins `@earendil-works/pi-agent-core` and `pi-ai` to 0.87.1. Pi's system prompt and tool declarations now live in leading transcript system messages. Aiden's host refresher appends section patches for AGENTS and browser discovery; the harness installs returned context messages and preserves the effective leading system message through compaction, emergency projection, and recovery. Context projection counts static prompt/tools once.

Pi 0.87.1 also replaced the 0.84.4 session repository interface and JSONL storage header. `pi-session-port.ts` retains Aiden's narrow journal contract over the new Session/Branch APIs. `pi-session-v4-upgrade.ts` converts old v4 journals on open with an exact private backup, including header-only and interrupted-operation journals, and maps legacy usage into native usage rows. Deleting a promoted chat removes its owned backup. The v3 migration now emits the new storage format and retains its rollback receipt contract. Child sessions use the new in-memory repository through the same port.

The PR #246 review follow-up makes every first-turn transcript start with a data-only system message and tool declarations. AGENTS patches are included in the first-turn context-capacity check; compaction replays all system patches into the effective head before history pruning and emergency fallback. The ownership-write failure path rolls back the created session and file so the chat id can be retried.

Second PR #246 follow-up (Pullfrog on b4d4fe5): Pi 0.87.1 restores operations only from configured-lane values (`pi.lane.state`/`pi.op.*`), which a converted branch-only journal never has, so the v4 converter reconciles each interrupted 0.84.4 operation during conversion. It retains the exact record and adds a synthesized `operation_finished` (`outcome: "aborted"`, key `pi087-upgrade-recovered-<runId>`, `recoveredBy: "aiden-pi-0.87.1-upgrade"`) under `aiden.pi-legacy-record`. The acknowledged branch tip is the recovered state. It mirrors the 0.84.4 loader (ids unique across entries and records; a finish only closes a same-lane start) and does not add new rejection paths. The rollback backup is created owner-only via an O_EXCL descriptor. A reused identical backup is chmodded to 0600 on its descriptor. `hasChatHistory` treats an owned header-only `.pi084-backup` as empty, and also a backup whose conversion exactly equals a completed empty-v3-migration promoted journal. Any other backup body stays protected. `create()` recovers from a failed ownership write whose rollback delete also failed, or from a crash before that write. On "Session already exists" it reclaims only a same-id, header-only, unowned Pi journal and then retries. A port-level pending-create set stops a concurrent create from reclaiming an in-flight claim.
