# Aiden Live in the send button

- 2026-11-19, owner asked for a Gemini-style composer: an empty draft's last button starts Aiden Live; typing turns it into Send. Owner's choices: ordinary chats only (1a); remove the idle corner pill, keep a corner notice for connecting, stopping, approvals and errors (2a); plain Send while Live runs (3a); reuse the existing setting, renamed "Show Live in the send button" (4a); Linux handled by the separate "Make Aiden Live work on Linux" work (PR #854).
- `renderer/lib/live-launcher.ts`: module store. `AssistantDock` (still window-level, still owns the session, ribbon, setup dialog and ⌘⌥A) publishes `{offered, sessionActive, needsSetup}` plus its own `openPanel` as the launch action. The composer subscribes; `liveLauncher.launch()` runs the same press the shortcut does. `prepareStart()` (async) runs before setup or start from any entry point, including setup's own Start Live (`startAfterHandoff` in the dock, passed to `AssistantLiveSetupDialog` as `onStart`); the composer registers `releaseMicrophone()` there, which cancels a dictation still opening the mic or stops a recording (words kept) and resolves once the tracks stop. The mic is disabled while a Live session is active.
- `offered` = Live capability + `aidenLiveEnabled` + `aidenLiveButtonVisible` + `hostSupported`. `hostSupported` is `useAppCapabilities().computerUse` in `AssistantDock`, the one Linux hide; #854 removes it once Live can start without Computer Use.
- Composer: `offerLive` prop, set by `chat-pane.tsx` from `liveChatReachable(chat.data)` (ordinary chats, drafts included; Bot, remote, design/feature chats get Send). `composerPrimaryAction` picks live only with no text (whitespace counts as empty), attachments, design comment tray, skill, dictation preview, no running/sending/first-send and no dictation. `useSettledPrimaryAction` (composer-live-button.tsx) waits 400 ms before Send turns into Live and ignores presses within 350 ms of the swap. Enter never starts Live.
- The button renders inside composer.tsx (not a separate component) so `composer-attachments-mounted.test.tsx`'s `./ui` stub still applies; that fixture bundles composer.tsx and only stubs its direct imports.
- Look: inverted solid fill (`bg-primary text-background`) with lucide `AudioLines`, names "Start Aiden Live" / "Set up Aiden Live" (aria-haspopup dialog), `data-live-guard="you"`.
- E2E: `composerPrimaryButton(page)` in tests/e2e/fixtures.ts matches Send/Queue/Live for specs that only need "nothing is running". To check Mac behaviour on Linux locally, build the renderer with `hostSupported` forced true (never commit that).
- Tests: `renderer/components/composer-live-button.test.tsx` (in test:gemini-live).
