# Component sink (UI SDK lessons unit 11)

Built 2026-11-19, modelled on the UI SDK playground's `<name>-kitchen-sink` fixtures (every variant on one page for manual testing), but as one page for all of Aiden's shared primitives.

- Files: `component-sink.html` (repo root, own CSP meta), `renderer/component-sink/index.tsx` (mount, `installInputModality`), `renderer/component-sink/component-sink.tsx` (the page, exports only `ComponentSink` so Fast Refresh works), `renderer/component-sink/component-sink.test.tsx`.
- Dev only by construction: `vite.config.ts` `rollupOptions.input` lists only main-window, pill and visual-snapshot, so `vite build` never emits the page, and nothing imports it. Vite's dev server serves any root `.html`, so it is at `/component-sink.html` under `npm run dev` (port 4143) or `npm run dev:sink` (port 4144, opens it). Verified 2026-11-19: a production `vite build` had zero hits for sink strings (`component-sink`, `data-sink`, `Right-click here`) while a control string from the app was present.
- Plain browser page, no preload: works only because ui.tsx's IPC access is lazy. A primitive that calls IPC at render would break it.
- Appearance: toolbar (DropdownMenu radio items for the 10 `THEME_PRESETS`, Segmented Light/Dark) calls `applyAppearanceConfig` with `mode` set to the scheme and that scheme's variant set to `getPresetVariant`. That call writes the appearance cache, so the sink restores the previous `aiden-agent.appearance-v1` value right after. It starts from the cached appearance (custom falls back to Aiden).
- Coverage test oracle: it enumerates the real exports of `ui.tsx`, `ui-primitives.tsx`, `ui-info-hint.tsx` and `settings/settings-page.tsx` (uppercase functions or `$$typeof` objects, aliases grouped by identity, e.g. `FieldLabel` = `Label`, `CustomDropdownMenu*`). Each must be named in some `data-sink` (space-separated on the case wrapper) or in `NOT_IN_SINK` with a reason (TooltipProvider, SplitView, Sidebar, SidebarFooter, ScrollArea, ScrollAreaFooterStack, ErrorBoundary, SettingsAnchorContext). Unknown `data-sink` names and stale exclusions also fail. Other tests open the Dialog, AlertDialog and menu, and drive the toolbar (dataset.theme, appearanceScheme, `--theme-canvas`, cache unchanged).
- Gotcha: an inline cmdk `Command` scrolls its first selected row into view on mount and drags the page scroller with it, so the Command case lives in a Popover.
- Button has no loading prop; the sink shows the app's idiom (disabled, `aria-busy`, `LoaderCircle` spinner with `motion-reduce:animate-none`, pending label).
- Registered in `test:settings-design` and the `renderer-other` lane of `scripts/ci-test-registry.json`.
