# Parent write_file symlink-swap fix — 2026-10-15

This branch stacks on the `edit_file` fix in PR #501. Before this change, parent `write_file` validated the target and ancestors, read the preimage, then used path-based `fs.writeFile`. A target or ancestor symlink swap after validation redirected that final overwrite outside the pinned workspace. A deterministic `buildPinnedCodingTools` test reproduced the successful outside overwrite before the fix.

`write_file` now pins the root for each call and selects a canonical in-root path without creating directories in TypeScript. The packaged cross-platform file-mutator helper gets the pinned root device/inode, root-relative path, expected absence or preimage device/inode/SHA-256, and updated UTF-8 bytes. Its `write-file` operation opens the root and each parent with no-follow descriptors, creates missing parents with `mkdirat`, opens a new file with `O_CREAT|O_EXCL|O_NOFOLLOW` or an existing file with `O_NOFOLLOW`, verifies the opened file and named leaf agree, and writes only through the open descriptor. Existing files retain their inode and normal in-place overwrite behavior. Stable in-root symlinks are canonicalized before the native traversal. Multiply linked existing files are rejected. A conflict rejects the operation without writing the swapped target. The shared helper's 256 MiB content/preimage cap now also applies to parent writes.

This prevents a symlink/path replacement from retargeting the final write to a different inode. It does not guarantee that the already-open original inode remains inside the workspace: a local actor can rename that inode or its parent outside the root after the final identity check, or create another hard link to it. If an in-place overwrite fails after `ftruncate`, the opened file may be empty or partially written; the tool reports that the write may be incomplete. A failed new-file write may likewise leave a partial newly created file. These are limits of the in-place semantics and concurrent namespace mutation, not reasons to claim an atomic transaction.

Behavioral tests cover target and ancestor swaps for overwrite, an ancestor swap during creation, stable in-root links, normal nested creation/overwrite and inode preservation, stale preimage rejection, cancellation, and outside-file preservation. The native helper binaries and source manifests were refreshed for macOS universal, Linux x64, and Linux arm64. No shared server protocol, native client, UI, onboarding, or plan status changed.
