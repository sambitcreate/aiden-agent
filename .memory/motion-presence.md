# Motion tokens, Reduce Motion and presence (UI SDK lessons unit 5)

Built 2026-11-19. Docs: `docs/design-guide.md` "Motion".

- Tokens: `--motion-duration`/`--motion-easing` (small), `--motion-large-duration`/`--motion-large-easing` (large), plus the new `--motion-decelerate-easing` (`cubic-bezier(0, 0, 0.2, 1)`, five uses: model-pad marker and tooltip lifts, slash palette entrance, dialog entrance, Quick View entrance). `(0.19, 1, 0.22, 1)` and `(0.16, 1, 0.3, 1)` became `--motion-easing`; quart/quint-out variants (`0.25,1,0.5,1`, `0.23,1,0.32,1`, `.22,1,.36,1`) became `--motion-large-easing`. 200ms and the near-same 180/220ms became `--motion-duration`; 150ms, 300ms (terminal drawer) and 10ms (dialog) stay literal on purpose.
- `literal-motion` ratchet: styles.css max 13 (activity-mark and Bot-face loops shared with iOS/Android, image scan, Live trigger lift, reasoning body rows), extend-art.css max 1 (9s knob loop). The three Web Animations curves (inbox FLIP, Bot send arc) use inline allowances: WAAPI `easing` cannot take `var()`.
- Reduce Motion follows the in-app setting. `prefersReducedMotion()` (appearance-runtime) now returns the applied `:root[data-reduce-motion]` and uses the OS query only before appearance is applied; it used to OR the OS in, so Off could not win. `reduceMotionApplied` in `use-reduce-motion.ts` was folded into it. The activity mark, ghostty cursor blink (now listens to `APPEARANCE_CHANGE_EVENT`) and the device 3D runtime stopped reading `matchMedia` directly. use-theme and pill-appearance still watch the media query, which is how System picks up OS changes. The visual viewer has no settings and keeps the OS query.
- CSS: every `@media (prefers-reduced-motion)` block in renderer CSS was converted to the attribute or deleted where an attribute rule already existed. `@custom-variant motion-reduce`/`motion-safe` at the top of `styles.css` remap ~150 Tailwind uses to the attribute (verified with `@tailwindcss/node` compile). Under Reduce Motion `--motion-duration` and `--motion-large-duration` are 0ms (the opp/ui idea of zeroing the duration token), which also reaches generated UI through `generative-ui-theme.ts`. The global 0.001ms rule stays so end events still fire.
- Presence: `renderer/lib/use-presence.ts` has `whenAnimationsSettle(el, done)` (`Promise.allSettled` over the element's own finite `getAnimations()`, root only so inner entrances don't hold an exit, immediate with none or Reduce Motion, timeout from the longest computed end + 50ms for paused animations, as in opp/ui `foundation/motion/presence.ts`) and `usePresence(present, ref)` -> `{ rendered, exiting }`. Converted: EventPresence (180ms timer), ActivityFeed (180ms), composer slash palette (110ms; `slashPalettePresenceState` and its test deleted, palette takes a `presenceRef`), Quick View card (120ms; now waits for its root's 300ms slide too, invisible by then), app update banner (120ms). The Quick View Subagents body's 300ms `useMountedWhileOpen` became `QuickViewSection` `bodyWhileOpen`, which drops children once `useCollapsibleBody` hides the body. That hook now waits with `whenAnimationsSettle` instead of `onTransitionEnd` (removed), so a cancelled or never-started transition still hides it; covered in `quick-view-cards.test.tsx`. The slash palette's `immediate` close is covered in `composer-slash-palette.test.tsx`.
- Not converted: `PAD_COMMIT_CLOSE_DELAY_MS` (a pause before closing, not an exit wait), chat title reveal timers (choreography), `USER_MESSAGE_FOLD_REVEAL_MS`.
- Tests: `renderer/lib/use-presence.test.tsx` (test:model-pad, next to `reduced-motion.test.ts`), `reduced-motion.test.ts` now asserts an explicit Off beats a reducing OS. Stale source-grep lines in `chat-sidebar.test.tsx`, `interface-polish.test.tsx`, `assistant-motion-contract.test.ts` and `dialog-motion-contract.test.ts` were dropped or loosened, not extended.
- e2e specs that use `page.emulateMedia({ reducedMotion })` rely on use-theme re-applying appearance on the media `change` event (setting System).
