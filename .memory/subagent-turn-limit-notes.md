# Subagent turn-limit partial notes — 2026-09-21 (reconciled 2026-09-26)

Production 0.42.0 recorded a scout stopping at the deliberate 24-turn ceiling after 45 tool calls; the result was failed with only the limit warning. The per-run store remains private and its identifiers/contents are not copied into this note.

PR #206 originally added a runner-side "last four completed notes" tail for turn-limit failures. PR #207 (issue 202, see `issue-202-subagent-turn-budget.md`) landed first with a stronger runner design: all settled, non-aborted assistant text within the output budget is credential-sanitized and returned for any turn-limit stop, regardless of capabilities, then head/tail-projected to 8,000 characters with `summaryTruncated`. On reconciliation, #206 dropped its runner change and eviction tests in favor of #207.

The remaining #206 change is display provenance: `SubagentEventProjector.finish` used to add the `report_truncated` notice only when `status === "completed"`, which predates failed results carrying summaries. A failed turn-limit partial that was shortened therefore lost its notice. The projector now honors `summaryTruncated` for any status. Tests: projector regression for a failed truncated result, a runner test that oversized turn-limit findings stay failed with `summaryTruncated`, and an assertion that output-limit failures expose no summary.

No wire schema, run authority, turn budget, or native projection change. iOS and Android remote clients exclude private subagent run details.

## Time limits and partial work — 2026-11-22 (helper chat plan, Phase 1)

The old 10-minute child and tree deadlines are gone. `subagent-child-policy.ts` now names two limits: chat helpers get a 24-hour safety net, Bot helpers get 60 minutes per reply. The supervisor's `SubagentReplyClock` starts at the first helper launch, not at construction; a Bot reply shares one clock across its tool calls. The desktop rebuilds Bot tools on every durable task phase, so a per-tool clock restarted on each call; `bot-subagent-reply-clocks.ts` now holds one clock per execution claim, released through the execution port's `settled` hook (final generation outcome and no new generation carrying the claim's inputs, so a queued message starting in the same commit still releases it), `dismissed`, or `resumed` (the service calls it for each claim a person's Resume restarts, including a blocked reply that only waits on its signal; the quiet auto-retry passes `{ automatic: true }` to `service.resume` and skips it, so repeated provider failures cannot keep refreshing the 60 minutes), capped at 256 and cleared by `forgetBot`. The CLI keeps one per turn (`bot-durable.ts` builds it with each `currentTools` refresh; a follow-up input mid-reply rebuilds tools and so starts a new reply). Each child's own runner deadline counts from its dispatch, so queued chat helpers lose no time. The one-turn report reserve applies only to Bots. Once a Bot's clock expires, later `subagent` calls return `BOT_SUBAGENT_LIMIT_REACHED_RESULT` and start nothing.

Partial work now reaches the parent on stop, every failure limit and timeout, not only the turn limit: settled assistant text plus "Files it changed: …" (committed write_file/edit_file paths, up to 20 listed) and "It also ran commands, which may have changed other files.", with the warning marked incomplete and unverified. A parent abort with no partial work still rejects as before. The CLI's forked worker runner (`packages/cli/src/subagent-process.ts`) does not collect file notes; CLI Bot helpers are read-only (see the review fixes below for its streamed-text handover). The projector no longer copies the warning into Result when the summary is empty, and the detail view hides Latest activity once a helper stops and puts Stop inside the "No recent update" notice. Phones read only states, which are unchanged.

## Phase 1 review fixes — 2026-11-22

- "Files it changed:" is a list with one path per line (a name can contain ", " or " and "); when a gated write may still have been settling after the drain, the list adds a may-be-incomplete note. The note text lives once, as `SUBAGENT_PARTIAL_WORK_NOTE` in `subagent-child-policy.ts`.
- The supervisor keeps a child's own completed result only when it arrived before any timeout, budget or parent stop reached that child (a user-guidance stop does not count). Otherwise the result is labelled interrupted or timed out, with partial work.
- The settlement seal waits the cancellation grace plus a margin (a quarter of the grace, 50 ms to 1 s), so a child draining for the grace can still hand over partial work.
- A Bot helper that waited for a slot gets only what is left of the reply as its deadline, so its report reserve lands before the reply limit.
- CLI durable Bots: `bot-durable.ts` builds one `SubagentReplyClock` per turn refresh and passes it through the tool context, because `bindTool` rebuilds the subagent tool on every call. The legacy non-durable path builds tools once per generation, so it was already per turn.
- New input: a new message is a new reply with a fresh 60 minutes (desktop: new claim; CLI: tools rebuilt). Documented in the READMEs and the plan.
- Resume: an interrupted Bot task a person resumes counts as a new reply (quiet desktop auto-retries keep the clock) with a fresh 60 minutes (desktop and CLI). Keeping the original start would need it persisted with the task; documented in the READMEs.
- CLI forked worker (`subagent-process.ts`): a failed child returns an empty summary and only its warning. A stopped or timed-out one hands over its streamed text through `projectSubagentPartialFindings` (the desktop's cross-line credential filter plus the summary cap), marked incomplete and unverified.
- Panel filter: a colon-and-block name counts as a display label only when it is on a fixed allow-list and has no secret hint anywhere in it; the parent-facing filter hides every indented line under a secret-named block.
